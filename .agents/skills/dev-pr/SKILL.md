# 拉取请求交付

先固定仓库、实际基线、目标分支、当前头提交和已授权的终点。把创建、跟进、更新和合并视为不同操作。使用当前项目的 Git 与平台能力，取得真实 PR、远端状态和有效证据。

| 本次目标 | 完整方法 | 完成依据 |
| --- | --- | --- |
| 创建或更新 PR | [打开 PR](references/pull-request-procedure.md)、[PR 证据与说明](references/pull-request-evidence.md) | PR 地址、目标分支、当前头和验证证据 |
| 查看或持续跟进 CI、审查 | [跟进 PR](references/babysit.md)，需要本地观察器时读[本地工具](references/local-tools.md) | 当前头的检查与审查、已处理阻塞及实际待决事项 |
| 合并已验证改动 | [验证后落地](references/verified-landing.md) | 当前头检查、独立裁决与真正的远端合并，或明确阻塞 |
| 已选用队列交付 | [独立 PR 队列](references/autonomous-queue.md)或[待审的堆叠 PR 队列](references/autopilot-stack.md) | 按实际依赖逐项核对基线、负责者、裁决和授权终点 |

1. 读取实际差异、权威行为契约、审查结论和验证证据。代码、依赖、环境与覆盖范围仍匹配时复用结果；行为发生变化时只补相关检查。需要新增审查或运行证据时分别调用 `dev-review`、`dev-verify`，或按当前环境直接取得所需证据。
2. 按对应方法交付。只有当前授权包含相关操作时才提交、推送、修改 PR 或合并，已有授权继续沿用。需要创建、审计或清理工作树时调用 `dev-worktree`，已有 Git 冲突时按分支所有权和授权调用 `dev-merge-conflict`，随后核对最新头。只读查看 PR 状态无需启动构建与验证负载；需要启动时先复用有效主机预算，记录缺失或过期时核对实际环境，托管 CI 以其运行器为准。
3. 读取平台实际终态。创建以可审查 PR 收束，合并持续到实际落地或明确阻塞。CI 成功、`READY` 与本地提交各有自己的证据效力。沿用各票同名验收报告，CI 下载与运行原件放项目根 `temp/dev/`。负责整个 Change 时，只在获得整体验收证据并达到约定的 PR、合并或上线终点后写根 `evidence.md`。

只要求直接提交或推送时，沿用项目指定 Git 方式。另有发布到指定环境的目标时，携带已核对的远端提交与有效证据交给 `dev-deploy`，再核验制品和真实服务。
