# 把一批 Change 编入同一目标

从用户指定的成员或现有批次计划开始。交付一份能回答“现在能做什么、其余在等什么、怎样验证整批结果”的计划。编排与接续均按[跨 Change 推进方法](references/batch.md)判断真实依赖。

- **只问顺序**时，给出当前可做项、等待的产物和理由。用户要为 Goal 准备材料时，补上可直接使用的目标文本。
- **在 Goal 中给出 Change 清单**时，读取各项已有记录和实际进展，形成批次计划后直接继续已授权的实施与验证。
- **给出现有批次文档**时，先核对其中的成员、实际产物和终点，从仍未完成的工作继续。

需要保存时优先更新已有总计划。新建批次记录默认放在 `.agents/dev/changes/<日期-批次主题>/program.md`，可取用[批次模板](assets/program.md)。成员的规格、原型、实施计划与证据保留在原位置。只需临时解释顺序时直接答复。

若宿主只允许读取该目录，沿用用户已指定且可写的计划位置。仍无法保存时，在回复中给出可复制的成员清单、顺序、接续点与 Goal 文本，并说明保存缺口。其他具备条件的已授权工作继续推进。

可把下面一句填入 Goal，替换实际路径及终点。直接给成员清单时，用各 Change 的路径替换批次路径。

> 完成〈批次文档路径〉列出的全部 Change，交付到〈约定终点〉。沿各 Change 的现有规格推进，核实前置产物后继续后续工作，最后验证〈组合场景〉并给出证据。

需要区分契约可用、实现可用和整批通过时，参照[邀请流程示例](references/invitation-example.md)。
