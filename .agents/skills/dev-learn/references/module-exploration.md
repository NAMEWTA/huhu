# 如何运作

探索代码库，回答“X 如何工作”。按用户已有背景及接手子系统所需的层次解释架构，足够建立可用心智模型，又不至于像逐行注释源码。

探索与讲解使用当前环境实际提供的只读工具；任务可分解且有子 Agent 能力时，派发前按执行主机当前可用资源、已有预留和工具上限分配会话名额，并行或分批完成。没有并行能力时按同样角度顺序调查。不要猜测宿主工具名，或为读取代码扩大权限。

## 1. 判断复杂度

范围模糊时，说明你的理解并开始探索，用户可以调整方向。

- **能沿一项用户操作解释清楚**：由当前 Agent 或一位解释者从实际入口追到状态所有者和可见结果，一次完成探索和解释。按[讲解提示词](explanation-prompt.md)组织发现，列出相关代码位置与失败路径。即使调用链跨文件，也可以这样处理。转到第 4 步。
- **存在需要独立查证的视角**：例如多个入口、并行的运行路径或相互冲突的所有权线索。转到第 2 步。

拿不准时选简单路径。

## 2. 探索（仅复杂情况）

把问题分成 2 至 4 个角度，每个是子系统的独立切片。按已预留名额一起或分批派出所有探索者，每位拿到填好角度的 [探索提示词](exploration-prompt.md)。

## 3. 综合（仅复杂情况）

全部探索者返回后，派一位解释者，给出 [讲解提示词](explanation-prompt.md)，填入所有探索发现。

## 4. 展示

展示解释者输出。可以为清晰度或对话背景做轻微编辑，不要大幅重写。

## 输出格式

解释采用 [讲解提示词](explanation-prompt.md) 定义的章节，删除不适用部分：概览、关键概念、工作机制、代码位置、注意事项。
