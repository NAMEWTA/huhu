# 开发环境与资源配置

交付结论在前、依据在后的环境记录：先回答当前项目建议同时保持几个 Agent（含主会话）、其中几项能同时运行重任务、每项使用多少内部 worker，以及还可新增几个会话和指定状态的 worktree。每个数字绑定执行位置、时间、负载组合和证据；缺少样本时给出未知项与最小补测路径。

用户已经指定的主机、范围、上限和授权继续适用。报告提供操作建议，实际限制由已有宿主、调度器或 OS 执行；文档本身不提供后台调度或操作系统隔离。

## 核对环境与容量

执行环境接入或容量评估时，读取[主机资源与准入方法](references/host-resources.md)，按其中计数、观测、成本和增量预算形成同一份推荐组合。只读分支复用已有样本；需要补测且已有授权时再采用其中的有界校准分支。

1. **固定对象。** 记录项目、检出、时间与时区、实际执行位置及容器、VM、WSL、SSH 或云端边界。只能访问当前执行器时就以该执行器为对象；用户电脑与不可达远端保留未知。远端只检查用户指定且已有访问能力的主机。
2. **核对项目条件。** 从项目指令、依赖清单、锁文件、版本文件与真实检查入口取得要求，区分满足、缺失、不兼容和未核实；注明新 worktree 的初始化、jobs/workers、浏览器与服务需要。宿主工具适配按 `dev-help` 处理。
3. **读取有效余量。** 核对受 affinity、cpuset、当前及可见祖先配额约束的 CPU、内存与压力、真实卷空间，以及现有会话、worktree、完整进程树和未兑现预留。按共享关系去重，必要时补 PID、inode 或本地 GPU 限制。
4. **匹配负载证据。** 分开会话常驻/轻量工作与附加重任务，复用同主机、相近项目版本和相同 worker 设置的有效样本。缺少成本时先报告可确认部分和最小补测方法；仅有一个主会话样本不证明新增 worker 的成本，更不证明硬件最多支持一个 Agent。
5. **形成联合建议。** 依据完整方法分别写当前观测、已验证规模、资源估算、建议总数和可确认新增量，注明主会话口径、重任务及内部 worker、worktree 状态和瓶颈。三类共用预算；实际 CLI、API 与用户限制按各自作用域核对。未知不当作零成本或无限资源，新增名额允许为 `0`；当前数量超过新建议时保留两个事实，暂停扩张并按压力处理逐步收敛。
6. **交付与刷新。** 使用[环境记录模板](assets/environment.md)先给执行建议，再给依据和未知边界。首表保留“当前可确认新增”；本次选择或需要新增多少另行说明，不能以“任务不需要新增”代替容量结论。只有磁盘条件估算时同时注明尚未确认的创建/初始化条件。由同一负责人或已有调度器维护预留；各阶段直接复用有效记录，启动新会话、初始化 worktree 或运行重任务前复测。跨 Change、跨仓库和嵌套 Agent 共用预算，子级从已分配额度中安排。

默认只读调查宿主与业务环境，写入所请求的报告属于交付。不为生成报告自动安装依赖、构建、跑测试、创建会话/工作树或清理文件。不同扩展任务按以下条件执行：

| 已授权的需要 | 接续方法与完成依据 |
| --- | --- |
| 测量指定并发或当前开发任务需要负载样本 | 采用主机资源方法的有界校准，先记录试运行并发、总时长或轮次、停止条件与入口；优先观测本来就要执行的任务。缺少支持下一档的依据时停止递增，记录已验证组合和未测范围。 |
| 验证项目能运行或核对最小工作链路 | 在预算内调用 `dev-verify`，记录实际执行结果；需要形式化能力时读取[接入前提](references/formal-options.md)，专门方法仍由 `dev-formal-verify` 负责。 |
| 回收已完成工作以释放资源 | 调用 `dev-worktree` 的现有审计与清理方法，传入主机、归属、直接父分支合并证据和进程身份；仅归还已确认实际释放的资源。普通评估只报告候选。 |
| 离线持续运行 | 按 `dev-help` 核对真实唤醒机制及可观测的停止、恢复方式。 |

校准的推荐组合以稳定吞吐、交互余量与任务独立性为依据。没有可比负载和测量时只交付资源可行建议，不宣称已找到性能最优点；成功运行 5 个仅是已验证规模，不代表第 6 个必定失败。

## 按需保存团队配置

主会话就是使用 team 的当前会话，可亲自执行或协调分工；只有另外调用的协作者需要按任务记录参数。

只有用户要求创建、重新初始化、修改或整理团队配置时，读取[团队配置方法](references/configure-team.md)，使用[团队模板](assets/team.md)保存到 `.agents/dev/context/team/<team_name>.md`。未指定名称时从 topic 生成可辨识且不覆盖其他团队的名称。多个文件独立存在，由用户在任务中显式引用具体文件；普通环境初始化不创建默认团队，不扫描或合并团队规则，也不向根项目指令注入自动加载入口。

派遣规则写入团队文件的“协作约定”，按用户选择记录同一会话接续多个 task、主会话与 worker 自主压缩及必要独立性的适用条件。执行任务直接沿用本次已选约定，不要求逐 task 重新运行本技能。

仅编辑团队文档时不启动环境探测或任务。只保存文件不宣称改变了宿主参数。

## 报告来源与监控

用户要求接入聊天、工单、邮件、监控告警，或按来源自动发现需求时，可选用 `dev-issue-setup` 完成来源、追踪器、仓库路由和触发器初始化。调用时传入真实连接器、已有授权、触发与失败恢复要求，交付可用配置，不假定后台服务存在。

来源平台不决定代码仓库或问题追踪器。手工单次任务不要求启用监控；定时、事件或 webhook 方式必须对应宿主中实际创建并验证的触发机制。新增来源与触发配置存入 `.agents/dev/project/issue-automation/`，秘密只保留安全引用。

## 输出与持久化

按当前任务读取 `.agents/dev/AGENTS.md` 和相关子目录说明，不假定宿主会递归自动加载。默认持久化骨架由安装器在选中 dev 技能时补齐，不属于本技能的执行步骤；本技能不维护骨架模板或初始化脚本。业务记录仍按真实内容创建。

环境与资源事实使用[环境记录模板](assets/environment.md)，默认保存于 `.agents/dev/context/environment.md`；已有等价记录原地维护。独立 worktree 和子任务引用负责人给出的同一实际位置，不各写一份全机额度。存在原生调度器时记录其权威预算入口，不复制易漂移的并发台账。只保存必要摘要，秘密仅留安全引用，运行原件留项目根 `temp/dev/`。

聊天交付与报告均先给各主机的建议组合、可新增量和一句依据，再解释瓶颈、已占用/未兑现预留、待补样本与刷新条件。按实际发生的工作附校准、验证或回收结果，不保留空表。区分建议上限、已验证规模与实际生效的运行时限制；未经验证的远端、配额或新会话能力保留未知，不承诺仅凭技能文档就绝不会 OOM。
