# 主机资源与任务准入

本方法负责环境核验、容量估算和准入记录，交付先给并发结论、再给测量与硬件依据的环境报告。使用现有宿主、系统观测命令和调度能力；工作树创建、父分支集成与清理由 `dev-worktree` 负责，派遣由实际主会话或已有调度器负责。

普通评估默认只读调查宿主和业务环境，再按请求更新报告。复用有效样本与轻量观测，不为填写报告而安装依赖、运行构建或全量测试、启动 Agent 或创建 worktree，也不执行删除。资料读取不扩大为远端部署、默认团队、模型选择或全局配置修改，不增加独立采集工具包、资源数据库或常驻调度服务。

## 执行范围与环境要求

1. 确认项目、仓库与目标检出、采样时间和时区、实际执行位置，以及物理机、虚拟机、容器、WSL、SSH 或云端执行器的边界。只能观测当前执行器时，就将评估对象写为“当前执行器”，不把它称为用户电脑。
2. 本机默认检查；远端只按用户给定的主机、连接或项目既有明确目标，通过现有 SSH、MCP 或管理接口做只读核验。不扫描网段、枚举未指定主机或读取凭据明文。不可达目标标为未核实且不可派发，不推断其空闲容量。
3. 从项目清单、锁文件、版本约定、容器定义、CI 与现有启动和验证说明提取运行要求。核对运行时、包管理器、编译器、构建和测试入口、jobs/workers、浏览器与必要服务。先读入口与已有记录；比较要求与实际版本，不以“命令存在”代替兼容性。
4. 在真正执行任务的主机和 worktree 只读核对依赖状态、工作目录、端口与可访问服务。主检出能运行不证明新 worktree 已初始化；记录两者的初始化差异。环境不匹配时记录受阻动作和可继续的只读工作，不自动启动安装或最小工作链路验证。
5. 为物理主机、可见父配额和共享存储标记资源池关系，各主机分别给结论。两台主机共享 NAS 时磁盘是同一池；同一主机上的多个容器同时受各自及公共上限约束。未知拓扑不得当作独立容量相加。

## 计数与证据口径

先定义对象，再统计数量与归属。每份报告注明会话口径是否包含主会话；同一资源池的总会话建议包含主会话。

| 对象 | 计数与资源归属 |
| --- | --- |
| task | 一份待完成的工作；同一会话可以依次处理多个 task，task 数不转换成会话数或进程数 |
| Agent 会话 | 正在运行的主会话、worker、subagent 或独立 CLI 会话；记录工作、等待模型、等待重任务等状态，保存的历史会话不计入运行中数量 |
| OS 进程与线程 | 按实际执行位置和共享关系计量；逻辑 Agent 数与进程数分列，一个进程可以承载多个 subagent |
| 重任务 | 一次依赖安装、编译、测试、浏览器验证、索引或必要服务启动；计算会话常驻成本之外的附加资源峰值 |
| 内部 worker | 构建 jobs、测试或浏览器 worker 等内部并行单位；受所属重任务额度约束，一个 worker 可能派生多个进程和线程 |
| worktree | 源码检出及其依赖、产物和缓存；保留时主要占磁盘，其中运行的任务另算执行资源 |
| Git 分支 | Git 引用；分支数不用于推导活跃 Agent、worktree 或构建数量 |

同一会话接续 task、上下文压缩与 handoff 沿用当前任务的既有规则，不因换 task 自动创建会话，也不把压缩上下文视为释放了常驻进程。创建纯源码 worktree 不增加 Agent 数；读取和审查类 Agent 可以使用已有检出，需要隔离写入时才交给工作树方法。

等待远端模型响应的本地 CLI 仍可能占用内存、连接、MCP 和 LSP，不能只统计采样时 CPU 忙碌的进程。共享宿主进程的 subagent 记录逻辑数量及实际增量，不按人数重复计算整份宿主 RSS。云端任务、SSH 远端执行和本地模型按真实资源池分别计量；远端推理不意味着本地加载模型权重，本地工具和代理转发的成本仍要计入。

对每项数字分别标注“实测”“带条件估算”或“未校准/未知”，说明样本来源与适用范围。同环境历史实测可以复用，但当前资源快照和历史任务峰值要保留各自时间。观察值、建议值与硬限制使用下列口径，不用一个笼统置信等级替代。

| 结果类型 | 可支持的结论 |
| --- | --- |
| 当前观测 | 采样时正在运行的数量和占用，不证明未来可增加多少 |
| 已验证运行规模 | 指定环境、负载、参数与窗口内成功运行过的组合，不证明更高并发必定失败 |
| 建议并发上限 | 结合成本、预留、实际限制和任务安排形成的当前操作建议，标明是估算还是经过可比校准 |
| 资源估算容量 | 在明确假设下计算的可行范围，未必运行过整个组合 |
| 运行时硬限制 | 当前版本、配置或套餐实际限制的范围，注明作用域及主会话口径 |
| 实际极限未知 | 尚未证明更高并发可行或不可行，不给伪精确的硬件极限 |

例如，5 个会话同时验证通过，只能记为“已验证运行规模为 5”，不能记为“已验证最大上限为 5”。只读评估和单次快照不提供永久稳定或绝对不会 OOM 的证明。

## 读取有效资源

优先复用已有监控和宿主只读接口。只记录任务需要的摘要与采集方法，不保存完整进程命令行、环境变量或秘密。下列为按系统选择的观测入口，不是要求每台机器执行全部命令。

| 位置 | 观测入口 | 判读与用于的决定 |
| --- | --- | --- |
| Linux | `uname -srm`、`nproc`、`free -b`、`vmstat 1 3`；按需用 `lscpu` 或读 `/proc/cpuinfo`、`/proc/meminfo`、`/proc/pressure/` | 按可见性记录 CPU 型号、架构、物理核和逻辑核，总内存用于设备说明。预算用有效 CPU、可用内存及压力，不用单独的 free 字段；swap 不作额外 RAM |
| Linux 容器/服务 | 结合 `/proc/self/cgroup`、`/proc/self/mountinfo` 定位实际 cgroup，读取当前层及可见父层的 `memory.current`、`memory.max`、`memory.high`、`cpu.max`、`cpuset.cpus.effective`、`pids.current`、`pids.max`；按需看压力与限制事件 | 计算适用层级剩余额度及 CPU 上限，识别回收、节流和 PID 限制。`max` 不作 0；`memory.high` 是操作压力边界，`memory.max` 是硬限制。cgroup v1 使用其实际对应接口 |
| macOS | `sysctl -n hw.logicalcpu hw.memsize`、`vm_stat`、`memory_pressure -Q`、`sysctl vm.swapusage`；型号、架构与物理核按可见接口补充 | 用页大小、压缩和压力解释当前内存余量；总内存或 free pages 不直接等同于可分配量 |
| Windows | `Get-CimInstance Win32_OperatingSystem`、`Get-CimInstance Win32_ComputerSystem`、`Get-Volume`、`Get-Process` 的必要字段；CPU 详情按需读 `Win32_Processor` | 取得设备、可用物理内存、卷与活动进程摘要；`FreePhysicalMemory` 以 KiB 计，磁盘和工作集常以字节计。容器、Job Object、WSL 限额另行核对 |
| 文件系统与 I/O | 对仓库、worktree、依赖缓存、构建输出和临时目录分别用 `df -Pk <实际路径>`；适用时用 `df -Pi <实际路径>`，结合现有 I/O 压力观测 | 未建立的路径查最近存在的父目录；按真实卷、适用 quota 和 inode 去重。空间用于保留及临时峰值预算，I/O 压力用于限制同时运行的重任务；标明 NAS、慢盘与 tmpfs |
| 活动进程 | Unix 可用 `ps -eo pid,ppid,lstart,rss,comm`，按需读取进程组 ID；Windows 按需读取进程 ID、启动时间、工作集及宿主实例 ID | 识别会话、安装/构建/测试、浏览器、LSP、MCP、服务、容器和其他背景工作。按完整任务进程树与共享归属确定当前占用，RSS 可能重复计共享页；无权限字段标未知 |
| 其他适用限制 | 读取实际进程或服务已有的线程、文件描述符、文件监视器限制和异常；有本地模型或 GPU 任务时再查显存 | 作为相关任务的额外准入约束，不因一般编码任务强制建立 GPU 画像 |
| Git 检出 | `git worktree list --porcelain -z`；需要详情时调用 `dev-worktree` 只读审计 | 纳入主检出、活动、闲置、集成树与原生宿主管理的实际路径，分别计算磁盘保留量和其中运行的任务 |

计算前统一单位：内存、磁盘和对应任务需求统一为字节；`df -Pk`、Unix `ps` 的 RSS 和 Windows `FreePhysicalMemory` 按 KiB 转换，页数乘实际页大小。CPU 用有效核数，inode 用数量；cgroup 的 `pids.current/max` 按包含线程的 TID 数量计数，不能用进程列表行数代替。保留原始单位与换算方法，表格可再展示为 GiB。

以实际执行任务的进程所在组为准定位约束；当前工具与目标不在同一 cgroup 时，核对目标 `/proc/<pid>/cgroup` 及其挂载映射，不能把工具自身的额度借给目标。读取当前层以及可见祖先，每层限额都与该层当前占用配对，祖先占用还包含同池其他任务，不能用叶子层占用代替。

CPU 容量使用亲和性、cpuset、适用配额共同限定的有效值；`cpu.max` 的 quota/period 可以是小数核，1.5 核不能向上当作 2 核保证。短时空闲和负载只用于校验压力，不把当前低利用率当作未来可预留核数。

内存新增余量不超过可用 RAM 与各适用 cgroup 硬限额剩余量的最小值，再结合 `memory.high` 与压力决定是否暂缓新增。例如物理机有 64 GiB，容器限制为 8 GiB，也只能按容器及可见祖先的实际剩余量计算；祖先更紧就继续收紧。`memory.high` 与硬限制分列，不混为一个“总内存”；接近或越过操作压力边界时按采用的策略预留、排队或降载，不能只因 `memory.max` 尚有余量就继续扩张。接口缺失、权限不足或父级不可见时保留未知边界，不能宣称已核实全机容量。

磁盘计入依赖安装、编译缓存、日志、截图和临时解包峰值。共享包缓存只计算一次固定占用，每个 worktree 仍保留实际增量；硬链接和写时复制不保证后续写入免费。`tmpfs` 同时受内存约束。

Node 的 `os.availableParallelism()` 只是程序可用并行度的建议，不能直接当作 Agent 数。`process.constrainedMemory()` 返回 `0` 时，不能据此认定 0 RAM 或已经确认无限容量；结合实际平台接口、配额和可见边界解释返回值。这些接口可补充观测，不能单独替代完整预算。

## 测量工作负载

先复用当前主机、工具版本、项目规模和 worker 设置仍适用的样本。按实际动作建立少量画像，至少区分会话常驻/轻量工作与附加重任务；项目实际使用浏览器或不同构建方式时再细分。同一进程或共享服务只归属一次，画像已含的成本不再次全额计入。

| 画像 | 记录的负载与成本 |
| --- | --- |
| 会话常驻与轻量工作 | 实际 CLI/宿主版本、常见上下文规模、读写搜索及必要 MCP/LSP；区分独立 CLI 与共享进程 subagent 的增量 |
| 依赖初始化 | 新 worktree 中安装、解包、依赖编译、冷缓存峰值及结束后的磁盘增量 |
| 构建或单元测试 | 实际命令、项目规模、jobs/workers、完整进程树峰值、CPU 需求、时长与缓存状态 |
| 浏览器或集成验证 | runner、浏览器及子进程、开发服务、数据库或容器、截图与追踪产物；包括每个 worker 派生的实际资源 |
| 合并后的最终验证 | 负载或环境不同才单列；相同则复用已有画像，另说明最终验证和必要集成树的预留，不重复计费 |

每份样本记录项目 revision、锁文件或等价版本依据、主机与资源池、命令和参数、内部 worker、冷/热状态、开始和结束时间、样本窗口、采样方法、观测峰值、退出结果、残留占用与适用边界。项目升级、测试规模、运行时或 worker 改变时检查样本是否仍适用。

测量方法按现有能力选择：

- 优先原生监控、任务/cgroup 聚合统计或已有测试性能工具，并核对统计覆盖的进程组和时间。聚合数据含其他任务或历史峰值时注明，不能把它冒充本次样本的独立成本。
- 使用进程树 RSS 求和时，记录同一时刻整棵树的观测峰值，说明共享页可能重复计算。单个父进程 RSS 或各子进程在不同时刻的最大值之和，都不能冒充整体同时峰值。
- 短任务可能逃过轮询。样本过早退出或窗口未覆盖安装、构建、测试、浏览器的关键阶段时，只记录已观察到的部分，保持完整峰值未校准。缺少样本不等于零成本，少量样本不标成有统计意义的 P95。
- 估算写明假设、适用规模与不确定性余量，实测标签仅用于实际观测内容。没有对应新增会话样本时，已有主会话的稳定运行不能直接证明新 worker 或独立 CLI 的增量。

只读调查到此已有可靠样本时，进入[容量计算](#计算可新增容量)；缺样本时仍给当前占用、可确认的新增量、未知项与最小补测路径。正常开发中观测本来就要执行的代表任务优先于另开测试，是否实际启动由下一分支决定。

## 按需有界校准

用户明确要求测量并发容量，或当前已授权任务需要验证某个组合时，才运行校准。沿用已有授权，无需为同一范围重复确认。普通报告只提出所缺样本及最小获取方法；没有任何安全试运行依据时继续只读，先补取既有同类记录或等待已授权正常任务的观测机会。

1. 读取最新余量、已有预留和运行时限制，选定与真实工作相符、可停止且有范围边界的样本。根据当前资源与已授权任务写明本轮最大试运行并发、总时长或轮次边界、停止条件和停止入口，不能无界递增。
2. 启动前记录负责人、host/pool、worktree 和已知宿主会话或服务 ID；启动时补齐实际 PID/进程组与启动时间。先观察一个会话或一项任务，固定内部 worker 和缓存条件，不同时放大多个未知类别。PID 会复用，执行停止和回收前重新核实身份。
3. 只有当前样本和余量支持下一档时，才逐步增加同类任务。覆盖实际进程树与磁盘峰值，比较相同工作量的完成时长或吞吐、失败情况、内存余量、I/O 与交互响应；记录每档组合及参数，不只比较 CPU 利用率。
4. 保护线触发、明显换页或回收、任务失败、收益不再改善时停止扩张，按[压力处理](#压力处理与恢复)回到已验证稳定组合。不能故意触发 OOM 寻找极限，也不能因等待超时继续增加负载。
5. 结束后记录成功运行的组合、实际覆盖窗口、失败和未测范围，更新原报告。仍存在的会话、服务、容器或 worktree 继续计入相应占用；未覆盖峰值的结果不能升级为完整成本样本。

这里的“最优”指在明确负载、任务独立性与响应要求下，兼顾稳定吞吐和交互余量的推荐组合。只读阶段通常给资源可行建议；有可比较的校准样本才能说明已比较档位中哪档更合适，没有可比工作量就报告资源估算。既不把“能创建的会话最多”当最优，也不以 RAM 或 CPU 达到 100% 为目标。

## 计算可新增容量

预算是当前执行组合的准入上限，不是机器的永久性能承诺。先明确要安排的会话、重任务、内部 worker 与 worktree 状态，再按每个主机和共享资源池分别计算，满足该组合涉及的全部约束。以下是工程估算方法，不能把厂商默认人数、安装要求或团队规模建议代入为通用硬件公式。

### 有效预算与保护余量

内存、磁盘、inode 和 PID 等按当前剩余量计算的资源维度 `r` 使用同一种口径：

```text
H_r = 当前有效剩余量
尚未体现在当前占用中的预留_r = 已准入但尚未启动的需求_r + 运行中任务尚未兑现的峰值增长_r
B_r = max(0, H_r - 额外保护余量_r - 尚未体现在当前占用中的预留_r)
```

`H_r` 使用本次实际剩余量，已运行进程和现存文件已经反映在其中，不能再次扣同一份占用。仍要扣除运行中任务从当前占用增长到已预留峰值的部分，以及已准入但尚未启动的预留。无法分辨已兑现部分时，保守保留整项预留并注明可能低估容量。

额外保护余量用于系统、桌面、常驻服务和未知背景增长所需的后续空间。优先沿用用户或平台已有策略，其次参考当前服务与背景波动；采用保守假设时写明数值、来源与理由。不能把统一百分比或“每个 Agent 固定几 GB”当官方标准，已经体现于当前占用的基线也不再全额扣一次。

CPU 单独按承诺量计算：`B_cpu = max(0, 有效核数 - 系统保留核数 - 运行中与待启动任务的全部已承诺核数)`。这里已经扣除待启动预留，不再套前式二次扣减；不以瞬时空闲率替代承诺量，也不在重算时丢掉运行中任务的 CPU 预留。

### 联合需求与建议组合

负载类别 `k` 的新增数量同时满足每个相关维度的 `n_k × demand[k,r] ≤ B_r`；混合负载沿用 `Σ(n_k × demand[k,r]) ≤ B_r`。把会话和附加任务展开后，每个资源维度都要满足：

```text
新增会话数 × 会话增量成本
+ 新增构建数 × 构建附加成本
+ 新增浏览器/测试数 × 对应附加成本
≤ 可新增预算
```

新增重任务可以来自现有或新增会话，其常驻成本只算一次；共享服务也只算一次。当前运行任务尚未兑现的增长已经在预留中，不再作为新增整项需求重复计入。

需求已知且大于零时，单一类别可取各相关维度 `floor(B_r / demand[k,r])` 的最小值。明确不消耗的维度可略去；未知需求不能当零或无限容量。多类任务共同消耗预算时先检查组合，不能把各类别单独算出的最大数同时相加。

资源可行后，继续核对用户上限、任务可并行性及实际 CLI、账户和 API 约束：

- 记录运行时版本、生效配置、作用域和主会话口径。单会话、会话树、宿主进程、工作流运行池或账户上限要先对应到实际对象，再用于限制候选组合，不能直接将不同作用域的数字相加或取最小值。用户值可以收紧有依据的建议，不能将未知容量变成已验证容量。
- API RPM/TPM 与会话数单位不同，只有具备调用速率、延迟和请求成本依据时才转换为并发建议。配额未知就单独注明，保留有依据的硬件估算，同时说明端到端可用容量尚未确认。
- 选择的内部 worker 必须与成本样本一致。多个 worktree 各自使用“全部 CPU”会放大嵌套并发；会话名额不附带无限重任务额度。需要不同 worker 档位时分别使用对应样本或标为未校准。

只读阶段给带条件的资源可行组合；可比校准支持哪个组合的稳定吞吐和响应更好时，将其作为当前推荐。即便校准成功，也记录适用负载与未测范围，不把推荐值称为实际极限。

分别报告下列数值及其假设，不把三个上限当作能同时独立用满的额度：

| 维度 | 必须说明 |
| --- | --- |
| Agent 会话 | 当前运行数、包含主会话的建议总并发、当前可确认新增数；子代理、独立 CLI 与共享服务的计数方式，仍缺证据时分别标未知 |
| 重任务 | 相关类别、每项 jobs/workers、当前运行数、建议同时运行数与该组合下的可新增数；其余会话继续轻量工作，到达重任务阶段时排队 |
| 保留 worktree | 当前数量和空间、指定初始化/保留状态下的建议总量及可新增数；其中允许同时运行重任务的数量另外受执行预算约束 |

示例仅解释计算：某资源池采样剩余内存 10 GiB，额外保护 2 GiB，已准入任务尚未体现的峰值增长/待启动需求共 2 GiB，则新任务预算为 6 GiB。若实测一个新会话的常驻需求为 1 GiB，它附加的构建需求为 3 GiB，两个新会话与一个构建共用 5 GiB；两个新会话与两个构建需要 8 GiB，不可准入。CPU、磁盘和其他限制还须分别满足。这些数值仅用于合成算例，不是默认配置或当前主机测量。

### worktree 的保留与运行成本

按需要分别记录纯源码检出的磁盘增量、完成依赖初始化并保留产物后的磁盘增量，以及在该树运行构建/测试时的附加执行成本和临时磁盘峰值。保留建议注明指定状态，混合状态列出组成；当前 20 个闲置树与 2 个运行会话是两个事实，新增纯源码树不会自动增加会话或重任务。

按实际卷和适用配额计算保留量，同卷余量只用一次。共享 Git 历史与包缓存已有占用已经体现在剩余量中，只对后续增长预留；每个树的独立依赖和产物仍计实际增量。硬链接/CoW 的未来写入与 tmpfs 的内存约束继续适用。先保留必要集成树、最终验证及临时峰值空间，再分配新树，不能等所有未合并子树占满磁盘才申请集成空间。

### 未知与当前超出建议

无法确认一次新启动可容纳时，当前可确认新增量可记为 `0`，说明是环境缺失、成本未校准、关键观测未知、等待回收还是已确认容量不足。未知的总容量保留未知；不能从“当前只有 1 个主会话、新增暂记 0”推导“硬件最多只能运行 1 个 Agent”，也不能用 `max(1, capacity)` 强行放行。

有依据的建议总量低于当前数量时，同时保留两者并报告新增 `0`。例如当前 5 个会话、重算建议 3 个，不为抹平差异把建议抬到 5，也不因生成报告自动结束已有会话；执行阶段按排队与压力规则逐步收敛。

为缺失的类别给最小补测方法，保留已有证据支持的结论和可做的轻量工作。远端余量只接收能够在那里实际执行且已获准的任务，本地编译不能借用远端空闲 RAM。

## 预留、派发与复测

执行阶段直接复用仍有效的环境记录；缺失或过期时按实际主机补查，不将运行本技能设为每个开发阶段的前置步骤。

1. 复用现有调度器的原子预留或单一负责人串行准入。项目记录默认在 `.agents/dev/context/environment.md`；多个检出传递同一权威路径。多个仓库/会话共享池时沿用已有公共协调入口；无法协调时不让每个主会话各自占满同一快照，应保守串行并注明未管理的背景负载。
2. 在派发新会话、创建或初始化 worktree、开始重任务前重新读取相关实时量，与当前预留合并检查。先记录任务/所有者、host/pool、工作量、预留和释放条件，再启动。子协调者与嵌套 Agent 从父级分配的同一预算中安排，不获得一份新的整机额度。
3. 明确区分“依赖已经满足”和“资源允许启动”。资源不足只是排队，不改变任务 DAG，不减少必须完成的候选总数或验收范围。失败重试与替换执行者也要经过准入；原进程未确认结束时保留其占用。
4. 优先复用当前会话接续 task；会话名额允许继续工作，但不自动授权再启动一项重任务。例如 10 个 Agent 都到达构建阶段，而当前预算只允许 2 项时，其余构建排队，各已准入构建仍遵守自身 worker 额度。
5. 将实际可用的宿主并发开关、构建 `jobs`、测试或浏览器 worker 限制映射到分配额度。先核对已安装版本、字段和作用域，再验证参数实际生效；例如项目使用 Playwright 时核对其 `--workers`，同时计入每个 worker 的浏览器进程。建议值与已生效限制分开记录，不能从文档示例猜参数。单会话子代理上限、API 额度、Node 堆限制、容器隔离都不能代替整机预算；需要硬限制时复用已授权的容器/服务管理能力，不擅自改全局参数。
6. 新一轮派发、任务或会话退出、恢复旧会话、换主机、CLI/依赖/worker 变化、首次重任务、清理后或出现限制与压力事件时刷新。记录有效条件而非把旧快照永久有效。长任务使用已有监控/事件或合理间隔采样，不忙轮询，不声称创建了不存在的守护进程。

### 压力处理与恢复

资源低于保护线、持续内存或 I/O 压力、明显换页/回收、OOM 或其他限制事件发生时，先停止新增和重试风暴，再让重任务排队、降低可控 worker。运行中参数不能热调时，限制后续启动，不声称已改变正在运行的 worker 数。必要时有序停止本任务可恢复的进程；保留用户和其他任务的服务，没有安全停止入口就记录占用和阻塞，不按进程名称批量杀进程。压力持续时，等待超时也不能获得启动许可。

采用的停止阈值、观测窗口和恢复条件写明来源，优先沿用平台或项目既有策略，没有全平台通用的 PSI 安全常数。恢复需要重新采样，并在一个明确窗口内持续回到正常范围；恢复条件应比停止条件留有余量，或使用连续健康窗口形成滞回，避免在同一阈值附近反复扩张和收缩。确认预留仍可满足后逐步放行，每档观察稳定后再增量，不能一恢复就释放全部队列。

## 按需回收

普通报告只列回收候选，不执行清理。用户要求回收或当前任务已经授权收尾时，将已完成且已合并到直接父分支的 worktree 候选交给 `dev-worktree`：传入真实主机/路径、完成与合并证据、用户保留要求、会话和进程身份。继续保护活动、锁定、归属不明和有未保存成果的对象，不另建删除方法。

先核实本任务实例退出，再按已有方法处理工作树与登记。文件、进程、容器或共享缓存的回收范围各自核实，不因一个任务结束就全局删除缓存。

回收失败或仍有后台进程时保留相应预留。成功后重读目录登记、进程状态和实际卷空间，只释放确认结束的部分；`git worktree prune` 不会停止进程，也不能代替现存工作树删除。把未释放项和理由交回原任务，恢复会话时重新核验，不照抄旧空闲量。

## 结论与交付

按[环境记录模板](../assets/environment.md)更新 `.agents/dev/context/environment.md` 或已有等价权威记录。首屏与聊天交付先给评估对象和时间、一句执行建议、会话/重任务/worktree 容量表、当前瓶颈与待补测项。表中分别给当前数量、建议总并发或保留量、可确认新增量、证据与条件，重任务明确每项内部 worker；硬件和工具链细节放在后面。

“当前可确认新增”是所声明推荐组合下有证据支持的资源额度；“本次选择/需要新增”是任务安排，两者分开表达。即使计划复用现有 worktree、不新建任何树，也要在首表说明可确认容量或为何尚不能确认，不能把需求为 0 填成容量为 0。只有磁盘条件估算时，在首表同时列带条件的保留数/上界与未确认的创建或初始化条件，后文再展开计算；这些估算不自动成为准入名额。未知时可以保守记准入 0，但要写出证据缺口。

随后仅展开实际需要的有效资源、样本、计算、运行时限制、预留、未覆盖范围和失效条件。没有校准、远端操作或回收就不建空表；模板占位符不能表示已完成。只保存必要摘要与安全引用，运行原件留项目根 `temp/dev/`；独立检出和子任务引用同一预算位置。

有样本时可按以下方式表达。数字只是格式示意，不是当前主机实测结果或默认值；真实报告必须提供相应样本与预算：

> 当前项目建议同时保持 5 个 Agent 会话，包含 1 个主会话和 4 个 worker。其中最多 2 个会话同时执行已测量的重任务，每项使用已验证的 2 个内部 worker；其他会话继续轻量工作，进入重任务阶段时排队。当前已有 3 个会话，可再增加 2 个。磁盘还可容纳 3 个已初始化 worktree，但这不增加重任务名额。本组合由所列样本推算，实际硬件极限未知。

只有 1 个主会话且缺少新增样本时，按事实说明：

> 当前确认 1 个主会话正在运行，新增会话的成本尚未校准，实际并发上限未知，目前暂无可确认的新增名额。这不表示本机最多只能运行 1 个 Agent。下一步先复用同环境样本；仍缺少成本依据时，在余量允许且任务已授权的范围内观察一个代表会话。若还需估算重任务并发，再观察缺少样本的一项项目构建或测试，更新对应组合。

建议来自观测和可审查假设，真正的硬保障取决于实际 CLI、调度器和操作系统限制。单主会话约定只覆盖受其管理的任务，报告不能宣称已经强制限制所有外部进程或阻止一切资源耗尽。
