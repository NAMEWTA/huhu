# 编写或修改项目技能

先读取目标、仓库约定、实际工具及已有技能。使用[完整技能编写方法](references/authoring-a-skill.md)和[本地结构规则](references/skill-authoring.md)，明确触发、输入、成果、责任边界和完成依据。已有技能能承担任务时原地完善，新的独立任务才建立新入口。同步维护入口、参考、模板、UI 元数据与受影响的使用路由。

沿用用户指定源仓库和路径。采用本套开发技能约定时，新建目录为 `skills/dev/dev-<name>/`，`name` 与目录名逐字一致，例如 `dev-api-permission-review`。其他领域使用相应前缀；已有命名约定优先核对。把真实项目事实写入项目资料。专用应用或形式验证包可分别调用 `dev-verify`、`dev-formal-verify` 的生成方法。普通文档用 `dev-writing`，仅改写单条提示用 `dev-sharpen`。需要从授权记录提炼稳定偏好时交给 `dev-personalize`，通用技能编写直接使用现有任务资料。

按任务风险核对引用、实际工具和自然请求。需要比较效果时，可调用 `dev-review` 独立评测，把原始请求与技能产物交给评估者。按当前授权保存或交付技能，并说明实际验证与未覆盖范围。
