### 工作树和模拟器清理

1. 快照与审计。记录实际工作树所在卷的可用空间，例如 Unix 的 `df -h <工作树路径>`，或 Windows 的 `Get-PSDrive -PSProvider FileSystem`。运行[本地只读审计](worktree-audit.md)中的 `worktree-audit.mjs`，交付回收时用 `--base` 指明实际父分支。一般回收以确认的默认分支或 PR 目标为基线。使用 `git worktree list` 的真实路径，因为宿主工作树可能在不同目录中。按大小、年龄、合并状态、未提交工作、PR 状态和明确选择的记录中最近触及它的会话分组。长任务可按实际可用能力后台执行，回读结果后再判断。
2. 分组是建议，不是许可。固定和活跃聊天才是真实产物，遵循 real-evidence。从用户或侧栏获取该集合，逐候选核对。`safe` 分组仍可能对应用户固定的工作树，因此固定集合优先。
3. 删除前验证使用情况。对每个 `verify-recent-chat` 行或任何疑点，扇出子智能体读记录，报告聊天是否固定或进行中、触及哪些工作树，遵循 工程原则（上下文管理），因为对话是大内容。固定聊天通过后台子智能体在兄弟工作树创建 方案比选 和复现树，即使名称没出现在侧栏，也正在使用。按本包执行支持与当前工具能力选择实际可用的模型、推理能力和速度。
4. 不可逆丢失时暂停。`wip:N` 是 N 项已跟踪未提交编辑，先展示差异取得决定，因为干净工作树可从分支恢复，未提交内容却会丢失。未跟踪文件不等于可丢弃内容。逐项核实归属、可再生性与授权，列出文件；不明内容保留。按自主性，干净、已合并、不使用的继续；`wip` 和使用中的暂停。
5. 清理已确认集合。回读准确的登记路径、分支和 HEAD，用 `git status --short --untracked-files=all --ignored=matching` 检查文件，并核对锁、使用状态及保存的证据。对授权范围内可恢复的检出按实际路径运行 `git worktree remove <path>`。命令拒绝时先查具体原因。若另有清除过期登记的任务，先用 `git worktree prune --dry-run --verbose` 核对影响范围。回读登记和所在卷空间。子分支提交由父分支的合并历史保留。
6. 用户要求释放其他磁盘空间时，再检查模拟器及缓存。先列出测试模拟器，核实无运行任务与需保留状态，只删除本次确认的设备；`xcrun simctl delete unavailable` 清不可用项，`xcrun simctl runtime list` 后 `runtime delete <id>` 清旧运行时。需要时再看 Xcode `DerivedData`、`iOS DeviceSupport`、当前开发工具的用户缓存目录 中 `state.vscdb.backup` 和 `snapshots/roots/<root>`，以曾作为工作区打开的文件夹命名的 root 会膨胀，以及 pnpm、uv、brew、yarn 包缓存。只清用户未要求保留的缓存。

这是唯一删除用户状态而没有代码审查兜底的手册，因此以上门禁就是审查。

**回复：** 清理前后的卷空间、已删除工作树，以及每个保留项的一行理由，例如仍有会话使用或存在未提交工作。
