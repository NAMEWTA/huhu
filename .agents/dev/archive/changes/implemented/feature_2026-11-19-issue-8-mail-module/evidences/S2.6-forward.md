# M-05 转发和新话题

[任务票据](../tasks/S2.6-forward.md)。下文记录当时的验证范围与结果。

从当前阅读邮件发起转发或新话题，浮层沿用 MailComposer 和现有草稿／发件箱。确认原型四个资源与 `7d17ffa6` 一致，确认指纹为 `9d0b1509bc58dd3146cce0dc9281ac443e6629c96cb9ec702e6490af5e201a65`。 [原型确认](../prototype-review.md) · [M-05 规格](../spec.md#workspace) · [S2.6](../tasks/S2.6-forward.md)

- 转发以空白收件人、转发主题和可编辑的原文摘录开始，保留原邮箱、目录、邮件身份和 RFC822 内容摘要。初次保存校验本地缓存的原信与附件列表。同 UID 的内容替换也会使旧转发预览失效。摘录沿用原有纯文本／净化 HTML 转文本和 24,000 字符、300 行上限。
- 能解码且适合转发的附件在首次保存时进入现有摘要对象及草稿修订，用户可先取消携带，也可保存后移除。空载荷、内联资源和 `message/external-body` 作为未携带的来源条目显示。缺少字节时须补选同名文件或明确不转发。同名存在歧义时要求明确选择不转发该条目。SMTP 从草稿中冻结实际已提交的受管附件。
- 新话题只预填同一封邮件的公开 From／To／Cc，排除本 Vault 地址并去重。可以切换发件账号。主题、正文、密送、附件和线程头由新草稿独立建立。转发与新话题的首次打开都按确认原型将焦点放在收件人。

## 运行证据

| 路径 | 观察 |
| --- | --- |
| Edge 转发 | 原收件人和密送未带入。编辑摘录后注入一次保存失败，当前正文保留，再保存并重开同一草稿。有效附件显示「已保存」，另一个条目显示「仅有名称 · 未携带字节」。取消本地补选时导入次数保持不变，明确跳过该条目后发送按钮才可用。 |
| Edge 新话题 | 收件人初始聚焦，只有公开参与者预填。主题和正文为空，第二个 SMTP 发件账号可选。主题按 Enter 仍留在当前编辑器。上述 UI 路径的 SMTP DATA 增量为 0，页面外部请求为 0。 |
| Engine 原信验证 | 两个回环 IMAP 邮箱的消息位于各自的账号和目录。换用同 UID 另一邮箱的身份被拒，更新同一 UID 原始内容后旧草稿预览也被拒。预览本身未写草稿或发起新 IMAP 请求。 |
| Engine 持久及 SMTP | 重启后转发草稿、原信身份、实际附件字节及仅名称条目均可读。跳过缺字节条目后只投递真实原附件；另一封仅名称的信在补选同名受管文件前拒绝投递，随后只投递补选字节。改用第二发件账号的新话题按独立信封投递，没有原线程头和附件。三次回环 DATA 均未携带历史 Bcc 或原始 Reply-To。 |
