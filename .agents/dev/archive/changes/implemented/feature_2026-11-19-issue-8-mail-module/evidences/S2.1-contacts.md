# S2.1 · 缓存邮件的联系人对话

[任务票据](../tasks/S2.1-contacts.md)。下文记录当时的验证范围与结果。

从单个邮箱或「全部账号」进入联系人列表，按公开参与者组合查看已缓存的往来。确认原型资源与 `7d17ffa6` 一致，确认指纹为 `9d0b1509bc58dd3146cce0dc9281ac443e6629c96cb9ec702e6490af5e201a65`。 [原型确认](../prototype-review.md) · [M-02 规格](../spec.md#workspace) · [S2.1](../tasks/S2.1-contacts.md)

## 接线

| 接线点 | 行为 |
| --- | --- |
| `plugins/mail/src/engine/public-mail.ts` 与 `message-cache.ts` | 复用 Huhu 的 RFC822 头字段读取、地址规范化和 Message-ID 校验。现有缓存仍按账号和目录存放。新记录在同一 UIDVALIDITY 下保留已取回的历史，旧格式单封缓存可直接读取。 |
| `plugins/mail/src/engine/conversations.ts` | `mail.conversations.list` 与 `mail.conversations.messages` 先筛出已选择的可见目录，再用同账号的可靠 Message-ID 归并副本。从可见副本的 From、To、Cc 合并公开参与者，排除 Vault 自己的所有邮箱地址，按组合聚合后分页。全部账号视图可在同一组显示不同账号的消息，保留各自独立来源。 |
| `MailModule.tsx`、`MailReader.tsx` | 邮件列表保留原账号、目录与本地消息 ID。正文、标读及派生写信复用阅读流程。公开本机已发从原发件事实读取纯文本。窄屏返回列表保留选中对话并恢复焦点。 |

本地 one-mail 固定提交为 `d1be24d5bb83c2da7123b167f119d5abd169b0af`，README 标注 AGPL-3.0-only。参考 `src-tauri/src/commands/data/conversations.rs` 中的查询与分页（L26）、往来（L211）、分组（L260）、本机已发接线（L332）、账号内去重（L350）与参与者提取（L363）。Huhu 使用自己的消息缓存、OutboxStorage、Engine capability 和 MailReader 实现对应行为。实现前核对 Modern Web Guidance 的 `stack-drill-down` 和 `accessibility`，在切换窄屏视图、返回和翻页时安置键盘焦点。

## 实测

Windows x64 使用固定 pnpm 12.10.1、Node 24.21.0、Vitest 3.2.7 和 Edge 157.0.4341.60。定向测试从 Windows 启动实际 Engine，创建临时 Vault 与两个合成本机 IMAP 账号。SMTP 夹具只计数，已发事实在临时 Vault 预置。

| 检查 | 观察 |
| --- | --- |
| 两个回环账号及可见副本 | A 的 INBOX、Archive 与 B 的 INBOX 使用 UID 42 和相同 Message-ID。A 两个可见副本归并，INBOX 为原来源，Archive 的公开抄送补齐组合。B 的旧格式缓存可读，保留独立消息和来源。 |
| 联系人分页与正文 | A 两组按最近邮件排序，逐组分页。多人组 5 封依次分页为 2、2、1，包含两封缺少可靠 ID 的邮件。全账号多人组合 6 封。两个账号的原正文分别可读，错用账号时返回需刷新。 |
| 隐私与投递 | 隐藏、垃圾箱、垃圾邮件、草稿、已标记删除的邮件和 Bcc 未进入公开组合。与 IMAP Sent 同 ID 的本机副本归并，独立的公开已发正文可读，仅 Bcc 的发送结果可从发件箱查到。读取公开组合及正文时 IMAP 命令计数不变。定向测试 SMTP 连接、认证和 DATA 均为 0。 |
| 重开与更换目录代 | 重开 Engine 后历史页仍可读。A 的 INBOX 更换 UIDVALIDITY 后，同 UID 的原历史正文失效，B 仍可读。 |
| 实际工作台 | Edge 在 390px 用键盘进入邮箱、联系人和邮件阅读。返回时恢复到原邮件条目。「全部账号」可读另一来源的正文，返回到「全部账号」按钮，期间 SMTP DATA 无增量。既有账号维护、回复、转发、新话题、草稿及投递场景仍通过。 窄屏联系人与往来（本机原件 `temp/dev/feature_2026-11-19-issue-8-mail-module/integration/legacy-7984bff4/S1-workbench/mail-contacts-390.png`） |

每次手动同步沿用现有最新一封抓取。每目录保存同一代已取回的最多 200 封，RFC822 base64 合计上限为 24 MiB，原单封大小上限仍为 2 MiB。远端历史批量扫描、旧消息的远端删除对账由后续同步任务处理。S2.2 的时间筛选、跨账号搜索与定位仍是独立切片。

## 复跑

在工作树根目录使用 Windows PowerShell。工作台探针以 Mail 证据文件为准，需要临时复制进测试收集目录。

```powershell
$repo = $PWD.Path
$pnpm = Get-ChildItem 'D:/.pnpm-store/v11/links/@pnpm/exe.win32-x64/12.10.1' -Recurse -Filter pnpm.exe |
  Select-Object -First 1 -ExpandProperty FullName
$probe = Join-Path $repo 'plugins/mail/test/workbench-renderer.test.ts'
$evidence = Join-Path $repo '.agents/dev/archive/changes/implemented/feature_2026-11-19-issue-8-mail-module/verification/S1-workbench/workbench-renderer.test.ts'
if (Test-Path -LiteralPath $probe) { throw 'Mail 探针路径已存在' }
Copy-Item -LiteralPath $evidence -Destination $probe
try {
  & $pnpm --dir $env:TEMP exec node "$repo/node_modules/vitest/vitest.mjs" run --root $repo --project '@huhu/plugin-mail' --maxWorkers=1 --minWorkers=1
  if ($LASTEXITCODE -ne 0) { throw "Mail 验证失败，退出码 $LASTEXITCODE" }
} finally {
  Remove-Item -LiteralPath $probe
}
```
