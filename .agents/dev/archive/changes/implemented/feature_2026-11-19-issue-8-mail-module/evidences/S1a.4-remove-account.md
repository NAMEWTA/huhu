## 提交与恢复边界

1. 桌面先按邮箱 ID 和配置修订预览删除影响。预览绑定草稿修订、投递记录版本和在途状态、实际缓存版本、凭据登记及共享附件引用。修改配置、草稿或共享引用后，旧预览不能确认。取消只关闭对话框。
2. 确认后先在现有 Mail 写入队列中发布该账号的清理记录。发布成功后使该账号的同步、标读、认证修复和投递失效，停止在途请求。活动的 SMTP 推进到本地结果边界后再清理，已经收到的服务端接受回执保留，可能已发送而缺回执时仍需核对。
3. 清理使用原草稿、缓存和 outbox 的写入边界，并维持草稿和投递去重的墓碑。已接受或可能已接受的记录只保留核对所需的 Message-ID、时间、收件人结果和去重身份。草稿正文、主题、服务器配置及附件引用从这些记录中移除，明确未投递记录只保留去重标记。只回收本次涉及且无其他本机引用的附件。最后使用凭据事务按原配置版本清除配置和本机认证。
4. 清理是可恢复的分步提交。首个状态写入失败时目标邮箱保持可用。其后步骤失败时显示可继续清理，原邮箱保持停用，重启后从同一清理记录续作。清理完成后保留账号 ID、确认修订及指纹供去重，完成记录不含配置、邮箱地址或文件信息。

## 运行证据

| 场景 | 观察 |
| --- | --- |
| 预览与取消 | Edge 390px 的真实 Mail 组件按键盘打开删除对话框，显示所选邮箱及影响，取消为初始焦点。取消后焦点回到触发按钮，原邮箱与打开的草稿仍在。 |
| 预览失效 | 更改邮箱名称推进配置修订，旧确认返回 `VERSION_CONFLICT`，需刷新预览。另外验证草稿修订变化和另一草稿增减共享附件会使旧预览失效，即使目标草稿数相同。把目标邮箱的预览指纹交给同地址的另一 ID 也被拒绝。 |
| 双账号隔离 | Windows Engine 保存两个同地址、独立 ID、IMAP 夹具及认证的账号。移除目标的缓存和三份草稿，另一账号的缓存、草稿修订、认证及共享附件保持可读。目标专用附件被移除。 |
| 在途与失败 | 一个 SMTP 已明确接受，一个在 DATA 前明确拒收，一个已收到 DATA 但仍扣留回执。确认时中止目标 IMAP 的活动 FETCH 与目标 SMTP。已接受与可能已接受的记录可查询，未投递记录的详情被清理，SMTP DATA 前后均为 2 次。迟到 IMAP／SMTP 响应和旧的认证修复或草稿保存无法恢复被清理状态。 |
| 断点后续作 | 首个清理记录写入失败时，未发布墓碑，目标仍在，投递状态仍为在途。另注入凭据定义写入错误，Engine 重启后可续作，Edge 中也能从「继续清理」入口恢复。最终配置与认证按 ID 清理，旧确认重放返回已完成。 |
| 合成远端 | 测试使用临时 Vault 与回环 SMTP／IMAP，删除和续作没有开启新投递，也没有发出远端删除指令。 |
