# S2.6 转发原信并区分附件元数据和实际字节

所属交付 S2。本项承接 [Issue M-05、§7.1](../source.md)，行为规则见[工作台操作](../spec.md#workspace)，设计见[调用与失败处理](../design.md#operations)。

## 交付与依赖

Mail 从单封信创建新的转发草稿，区分可携带附件与仅有名字的收件元数据。

**前置产物**　[S2.3](S2.3-read-message.md)、[S1b.1](S1b.1-compose-draft.md)、[S1b.2](S1b.2-managed-attachments.md)。

**代码入口**　[one-mail/src-tauri/src/commands/data/conversations.rs](https://github.com/zhihui-hu/one-mail/tree/d1be24d5bb83c2da7123b167f119d5abd169b0af/src-tauri/src/commands/data/conversations.rs)、[one-mail/src/components/mail/mail-composer/index.tsx](https://github.com/zhihui-hu/one-mail/tree/d1be24d5bb83c2da7123b167f119d5abd169b0af/src/components/mail/mail-composer/index.tsx)、[Huhu Engine 注册与插件生命周期](../../../../../../../apps/engine/src/boot.ts)。拟在 `plugins/mail` 的联系人、阅读与写信流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「正文 → 转发 → 查看附件 → 保存/补选」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#composer)，核对从阅读区发起转发后检查写信附件。

## 验收

- [ ] 对一封有真实合成附件字节的信转发，输入新收件人并保存，重开见原内容及正确附件字节。
- [ ] 另一封只有附件名时显示缺失/待补选，取消补选不生成虚假文件，原信和已有草稿不变。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
