# S8.1 通过获开放的工具操作同一邮箱

[验收报告](../evidences/S8.1-public-capabilities.md)

所属交付 S8。本项承接 [Issue §8.2、§5.4](../source.md)，行为规则见[网络与数据契约](../spec.md#durability)，设计见[调用与失败处理](../design.md#operations)。

## 交付与依赖

Mail 负责 §8.2 的账号、OAuth、会话、消息、写信、发件箱、附件、同步、设置、备份恢复及 AI 的 schema/分类；#6 持有统一目录与权限。

**前置产物**　[#6](../../feature_2026-11-19-issue-6-unified-tools-web/plan.md) 的发现/调用合同；每组需对应业务 handler。

按组联验的依据在[规格覆盖表](../plan.md#coverage)。先用账号列表和草稿保存验证发现、开关及同一 handler，其余业务组完成时逐组接入；整组签收需要 §8.2 每一行都有实际调用结果。

**代码入口**　[packages/kernel/src/dispatcher.ts](../../../../../../../packages/kernel/src/dispatcher.ts)、[packages/kernel/src/mcp.ts](../../../../../../../packages/kernel/src/mcp.ts)、[apps/cli/src/commands/call.ts](../../../../../../../apps/cli/src/commands/call.ts)。拟在 `plugins/mail` 的能力适配流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「账号、发件箱、设置与权限反馈」。此处仅用于对照可见结果。服务行为由下列验证判定。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#main)，核对切换「模拟只读 Vault」，观察账号、草稿及发件箱；外部授权入口归 #6。

## 验收

- [ ] 按 §8.2 建操作矩阵，逐组在 UI、CLI、MCP、API 对同一模拟 Vault 写入/读回。变更能刷新列表，重复发送仍只有一个业务操作。
- [ ] 关闭外部工具、停用 Mail、只读分别执行，区分错误及可恢复范围。内用仍依自身权限；普通查询、回执和公开参与者无秘密/Bcc 泄露。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
