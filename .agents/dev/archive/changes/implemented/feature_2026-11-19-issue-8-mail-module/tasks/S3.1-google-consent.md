# S3.1 添加并重新授权 Google 邮箱

所属交付 S3。本项承接 [Issue §3.2、§5.3、§6.2](../source.md)，行为规则见[添加与维护账号](../spec.md#accounts)，设计见[数据与提交顺序](../design.md#storage)。

## 交付与依赖

Mail 维护绑定 Vault、账号和主机的授权会话及 token 轮换；桌面发起或工具跟进同一授权。

**前置产物**　[S1a.1](S1a.1-account-discovery.md)；真实联验需 Huhu 注册客户端。

**代码入口**　[apps/desktop/src/preload/index.ts](../../../../../../../apps/desktop/src/preload/index.ts)、[one-mail/src-tauri/src/oauth/mod.rs](https://github.com/zhihui-hu/one-mail/tree/d1be24d5bb83c2da7123b167f119d5abd169b0af/src-tauri/src/oauth/mod.rs)。拟在 `plugins/mail` 的Gmail 适配流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「Google 账号 → 授权进行中 → 取消/过期/重新授权」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#fault)，核对添加 Google 邮箱与「OAuth 授权拒绝」。

## 验收

- [ ] 使用模拟回调检查 state、PKCE、地址匹配、取消和完成只生效一次；模拟两次并发刷新，保存一个有效的新版本。
- [ ] 地址不符、用户拒绝、令牌失效或客户端未配置时回到原账号修复；切 Vault 后迟到回调无效。只使用合成凭据。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
