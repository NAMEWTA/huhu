# S2.5 从当前邮件回复的回环验证

用临时测试 Vault、两个合成邮箱和本机 IMAP／SMTP 验证。浏览器探针加载 Mail 实际组件，能力请求由真实 Engine 处理。确认的原型四个资源与 `7d17ffa6` 一致，确认指纹为 `9d0b1509bc58dd3146cce0dc9281ac443e6629c96cb9ec702e6490af5e201a65`。 [原型确认](../prototype-review.md) · [行为规格](../spec.md#workspace)

| 操作 | 实际结果 |
| --- | --- |
| 在正文按 Enter 激活「引用回复」，从正文右键选择「回复全部」 | 两次焦点都进入正文编辑器。回复用原信 `Reply-To` 作为目标，回复全部增加公开 `To`／`Cc`，排除两个自有邮箱地址、重复地址及原信 Bcc。正在读原信时显示内联编辑器，发件人沿用来源邮箱。仅打开回复不写草稿，也不发起 SMTP 或 IMAP 写入。 |
| 编辑回复及引用，故意让首次保存失败 | Edge 中止保存请求后保留当前编辑器和内容。重试保存后，在「草稿」中重新打开，正文和已修改的引用都在。Engine 另有测试注入 Vault 写入失败，重开后按原草稿 ID 读回，并验证原账号和邮件身份。上述路径的 SMTP DATA 增量为 0。 |
| 显式发送回复后，在部分接受时只重试拒收地址 | 回环夹具捕获的 SMTP 信封收件人与选择相符。首发与重试均有 `In-Reply-To` 和顺序正确的 `References`，线程链尾是原信 `Message-ID`，每封发出的邮件另有自身 `Message-ID`。原信 `Reply-To` 用于确定回复对象，原信 Bcc 不出现在信封或 DATA 中。 |
| 从同 UID 的另一账号回复收件专用邮箱中的邮件 | 不能跨账号借用原信身份。收件专用账号显示原因并可保存回复草稿，UI 和 Engine 均阻止发送，SMTP DATA 增量为 0。 |

引用保留为可编辑文本，长信截取前 24,000 字符及 300 行，界面提示截短。有效线程引用最多保留 32 项，截断时保留最早一项和最近的祖先。原信缺少有效 `Message-ID` 时依旧保存 Mail 内的来源身份。
