# S0.2 合成邮件传输取证

Windows x64 build 26300，Node 24.21.0。使用原工作区 `temp/issue-baseline/mail-protocol` 的独立锁与夹具，实际安装 ImapFlow 2.12.1、Nodemailer 10.6.0 和 MailParser 3.14.5。运行 `node probe.mjs`。Core `t39` 退出 0。IMAP、HTTP 和 SMTP 端点均绑定环回地址和临时端口，消息和账号均为合成夹具。

| 样例 | 实得结果 | 实施含义 |
| --- | --- | --- |
| IMAP 只读获取正文 | 选择只读 INBOX，读取 UIDVALIDITY 123。以 UID 42 发出 `UID FETCH` 和 `BODY.PEEK[]`，解析到 `IMAP body`。退出后连接数为 0。 | 本机消息记录需要账号、目录、UIDVALIDITY 与 UID。正文获取可独立于设置已读。 |
| API 原生字符串 ID | 回环 JSON fixture 以 `provider_id-01` 返回 MIME，解析到 `API body`。两条样例 RFC822 Message-ID 相同，正文各自保持正确。 | API 定位保留账号与原生 ID。该夹具验证定位与解析，不覆盖 Gmail 或 Graph 的实际协议与授权。 |
| SMTP 在正文发送后失去确认 | 服务端收到固定 Message-ID 的完整 DATA 一次并断开，客户端得到 `ECONNECTION`、`command=CONN`，无 SMTP 回包码。测试将 `probe-op-1` 原子写为 `unknown`。新的 Node 进程按记录读回同一 operationId、Message-ID 及状态，服务端仍只收到一份。 | 连接错误标签不足以判断邮件未送达。产品应冻结投递意图并保留结果未知，依据服务端证据对账后再决定后续动作。 |

本结果证明 TS/Node 库可承接三条代表性路径。生产权限、真实 IMAP/API 提供商、发送取消、发送前崩溃窗口和安装包依赖仍待验证。候选库目前只在隔离测试使用，产品锁文件没有新增依赖。[ImapFlow 获取正文](https://imapflow.com/docs/guides/fetching-messages/) · [Nodemailer 错误参考](https://nodemailer.com/errors)

## Windows 同一夹具的 Rust 对照

在 Windows x64 26300 复用同一个回环服务、正文、UID、字符串原生 ID 和最终 SMTP 确认中断点。Rust 探针使用 OneMail 锁中的 `async-imap 0.11.3`、`lettre 0.11.23`、`mailparse 0.16.1`、`reqwest 0.13.4` 和 `tokio 1.53.1` 的对应直接版本，经 `cargo build --locked -j 2` 构建。仅使用独立探针，Huhu 根锁和生产依赖未加入这些库。

| 场景 | TS Engine 候选 | 独立 Rust 探针 |
| --- | --- | --- |
| IMAP / API | UID 42、UIDVALIDITY 123 和原生 `provider_id-01` 返回各自正文。 | 同一 UID、UIDVALIDITY、原生字符串 ID、正文和 RFC 822 消息 ID 均通过。 |
| 取消 IMAP | 服务收到停滞的 UID 43 FETCH，连接从 1 降到 0，等待中的请求拒绝。 | 等待 FETCH 的 250 毫秒期限结束，释放相应 session，服务端连接清零。 |
| SMTP 确认中断 | 服务收到完整 DATA 一次，返回前切断，库以 `ECONNECTION` 结束且没有 SMTP 状态码。 | 同一点切断，服务收到完整 DATA 一次，错误 `incomplete response` 且没有 SMTP 状态码。 |
| 重启对账 | 第二个 Node 进程只读出同 operationId 和 `unknown`，发送计数保持一次。 | 第二个 Rust 进程只读出同 operationId 和 `unknown`，发送计数保持一次。 |

比较由 `t5s` 完成，退出码 0。实测依据选择 TS Engine 持有首条读、写、取消和本地回执的生命周期。两组均需要由 Huhu 保留本地派送记录和实际对账。Rust 夹具的独立进程在当前样本没有提供更多投递确认，因此当前选择也减少正式打包时新增一套进程与协议边界。未采用 OneMail 源码和界面素材。

脚本与独立锁位于原工作区 `temp/issue-baseline/mail-protocol/`，原始结果 `temp/issue-baseline/core-finished/t5s.log`。探针中的重启回读证明保留与回读结果未知的表示，正式发送前的持久 intent、TLS、OAuth、真实邮箱和包内 Mail 验收分别留给对应生产切片。
