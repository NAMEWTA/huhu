# Mail 插件行为规格 · #8

一个 Vault 中可以管理多个邮箱。用户从公开参与者找到往来，在原账号阅读或回复，离线时继续写草稿，发送结果可在重启后查询。工作台新增独立的「邮件」模块，现有 Inbox 继续承接快速捕获。

本规格承接 2026-11-17 [Issue 正文及评论快照](source.md)。快照无评论。§3 的逐提供商配置、§4 的 M-01 至 M-08、§8.2 的操作清单及 §10 的来源映射继续作为验收输入。本文补充跨入口、异常和恢复契约。当前检出与上游默认分支的差异见[设计](design.md)，实施与采证见[计划](plan.md)。

<a id="accounts"></a>

## 添加并使用账号

1. 在当前 Vault 的 Mail 中选择预设或自定义，填写地址、显示名、认证和收发服务器。18 个命名预设加自定义完整保留提示、链接、端口和安全模式。完美邮箱按域名切主机，网易 126/yeah 的图标分类仅辅助识别。保留用户覆盖的端口和 SMTP 开关。连接失败显示原因，TLS 降级和跳过证书校验均不能成为自动恢复手段。
2. 普通账号测试连接、发现文件夹、至少选中 INBOX 后保存。不可 SELECT 的节点禁选。用户修改主机、账号或认证后，让先前的发现结果和在途响应失效。OAuth 走上游实际支持的文件夹流程。接收专用账号可以阅读，写信时显示无法发送的原因。
3. Google、Microsoft 使用 Huhu 自己注册的客户端。会话绑定账号、Vault 和授权主机，支持系统浏览器、PKCE、state、超时、取消和重授权。CLI/MCP 可发起并查询会话，LAN 用户知道在哪台机器完成；回调经验证后只完成一次。分别呈现缺客户端配置、拒绝、地址不符、token 失效、协议被禁、超时、目录失效。账号读取返回认证方式、配置状态、实际同步路径和修复入口。替换失败保留旧配置，省略凭据保留，清空须显式。
4. 认证归 Mail，Safe 未设置、锁定、停用均与上述流程独立。Mail 密钥暂不可用时，已有可读缓存和本地草稿仍可用。删除账号先预览受影响的本地配置、草稿、附件、发件记录、历史和认证，再按当前版本删除。服务商邮箱和其他本地账号、个人 Safe 条目均独立。处理在途发送见[设计](design.md)。

## 从联系人找到具体邮件

| 来源 | 用户动作 | 可观察结果 |
| --- | --- | --- |
| M-01 | 打开、切账号、折叠提供商、键盘或右键操作 | 全部账号和分组保留，选中项自动展开，未读、刷新、同步、异常和修复各有状态。全部账号只呈现适用操作。账号栏参考宽 260px、最小 220px，窄窗逐层返回原选择及焦点。 |
| M-02 | 同一消息存在多个目录、本机 sent 或另一账号，同时有多人抄送 | 在同账号内按可靠 RFC822 Message-ID 归并副本，缺 ID 保留独立来源。排除隐藏/已删/草稿及 trash、junk、drafts。先聚合本地全部历史再分页，规范化 From/To/Cc 并排除所有自己地址，按公开参与者集合归组。Bcc 仅见于相应私有发件记录；仅密送的邮件从发件箱查看。 |
| M-03 | 在今天的单账号视图中搜索另一个账号的旧邮件 | 默认今天，可选全部、今天、昨天、近三天，沿用工作台时区。跨账号搜索已缓存主题、参与者、摘要、正文，说明缓存范围；250ms 防抖、分页、上下键、回车、Esc。结果带账号，选择后切账号与全部时间、清除阻挡筛选、居中高亮。通知使用同一定位；命令系统只打开一个搜索入口。 |
| M-04 | 卷动到未读邮件或重试失败正文 | 初入定位最新，可回到底部。按视口加载、按时间正序区分收发，支持长文/引用/签名折叠、原文和纯文本/HTML。读取、预取或搜索无标读副作用。正文就绪且实际可见才另调标读。默认零外部资源请求；单封显式放行不会影响下一封。安全外链交宿主处理。 |
| M-05 | 在多人邮件上引用回复、回复全部、新话题、转发 | 内联回复用来源账号，右键结束焦点进编辑器。Reply-To、In-Reply-To、References 保留，reply_all 去重并排除自己及 Bcc。新话题可换账号，清除旧引用链。可从正文进入转发，能区分附件名与已携带字节。 |
| M-06、M-07 | 写富文本、关闭再打开、发送或修复 | 右下非模态浮层可扩大还原，选择发件人、多地址 To/Cc/Bcc、主题、链接与附件。去重、移除并持久保存受管附件；有内容时关闭先存草稿，失败保留编辑器，主动丢弃才放弃。发件箱恢复选择，可续编、查每次投递和删除本地记录。服务器 Drafts/Sent 与本机记录分别展示。 |
| M-08 | 在设置中调整周期或进入 AI、数据管理 | 周期改变实际调度。AI 默认关闭，用户选择内容并看到目的服务后才发送，可总结、提取待办、起草或对话。输出仅供阅读或采纳为草稿。远端 HTTPS 和 Key，本机回环可 HTTP 且不携 Key。可验证连接、替换或清除 Mail 专用 Key；故障保留原内容。 |

工作台沿用 Huhu 的模块、设置、命令、四套主题及明暗样式、焦点、减少动效和窄屏规则。将上游托盘业务动作映射到现有命令。上游提供功能和信息结构参考，Mail 使用 Huhu 自有导航、组件、主题和文案。桌面及 Web 的可见交互按[原型](prototype/index.html)与[用户确认记录](prototype-review.md)对应场景核对。此次规划和原型限模拟账号、邮件、附件和投递结果。

## 网络事实、发送与持久数据

- **同步与正文。** 每条消息以本地 ID 打开，Engine 根据实际来源用 IMAP 的账号/目录/UIDVALIDITY/UID，或 Gmail、Graph 的原生字符串 ID 取正文。IMAP 最近 200 封是初扫/补偿窗口。增量按 UID、服务端标记及对账推进。Gmail history、Graph delta 分页成功才推进相应游标，失效后重扫受影响范围。UI 显示实际路径、回退原因及范围。Outlook 默认 IMAP/SMTP 授权可走 IMAP；Graph 另验 audience、scope，只有 Mail.ReadBasic 时不能宣称正文或附件可读。
- **标读。** IMAP 检查 UIDVALIDITY，STORE 后 FETCH FLAGS 确认才返回远端已同步。失败留可修复状态。Gmail/Graph 基线本地覆盖返回 `remoteSynced:false`，旧同步不能反写用户刚做的标记。缓存、标记、通知只在当前 Vault 和账号代生效。
- **发信。** 对同一草稿版本并发点击或跨工具提交，查询到同一业务操作。只有 SMTP 明确接受才能标为已接受，部分接受逐收件人记录。可证明未提交的收件人才能常规重试；可能已接受的显示「结果未知」及核对入口。关闭、超时、重启、恢复备份都不重新投递。修改正文或收件人产生新版本；稳定 Message-ID 用于关联，不能证明唯一投递。
- **只读与离线。** 可从原 Vault 读取已有资料，临时 stateDir 只承载可丢弃状态。只读入口统一拒绝持久写、发送、远端标记和导入提交，后台和外部入口也受约束。离线可读缓存、在可写 Vault 保存草稿，重连按账号对账；停用/切 Vault/关闭取消订阅、定时器和连接，迟到响应失效。
- **新格式备份与恢复。** 整 Vault 包恢复到新空目录；Mail 子集走带类型与版本的包格式，在目标 Vault 预检后提交。可恢复草稿、已发、操作状态、仅本地标记、受管附件及非秘密配置。缺字节的附件列为待重绑。可重建缓存、游标和连接分开处理。新机默认重新填写邮箱密码或重新授权 OAuth。清缓存、重建 FTS、Git 同步均不得删除唯一副本或触发发送。产品尚未发布，本轮以 Huhu 新格式取代 Issue §9.2 的旧格式迁入交付，S6b 承接 Huhu 新格式邮件子集恢复。旧版 one-mail 文件及真实旧数据不进入处理流程。
- **统一能力。** 账号/认证、授权会话、会话/消息、写信/发件箱、附件、同步、设置、备份/恢复、AI 均有同一 schema 与 handler。#6 负责目录、能力选择和传输。干净安装时 MCP/CLI 工具默认关闭，用户可逐项或明确批量开启。插件停用返回不可调用，外部工具关闭不影响工作台；外部工具可独立完成已开放操作。大附件用受限句柄和流，禁止从调用设备提交任意 Engine 主机路径。

<a id="limits"></a>

## 基线缺口与验收边界

收件附件基线只显示元数据。上游缺少收件删除/归档/移动/星标完整入口、远端 WebDAV/S3 备份、已证明的 SMTP 成功后远端 Sent APPEND；全局远程图片设置未接通阅读器。保留单封放行，有效设置才进入界面。转发入口、API 正文定位、SMTP 不确定性属于必须补齐的断点。POP3/EWS、日历和群发平台超出 Issue 范围。实现后按[切片和关闭条件](plan.md)分别交真实邮箱、受控故障、界面与来源证据。
