# S2.1 · 公开联系人阅读与撤出

本轮修复独立审查 t187/report05.md 记录的两项 Mail P2。

| 验收路径 | 核对项目 |
| --- | --- |
| IMAP Sent 原件带 Bcc | Edge 从「全部账号」进入包含两个账号的公开联系人组合。打开合成 Sent 正文时，可读公开正文，页面和公开响应都没有 Bcc，阅读器没有原文按钮。 |
| 单账号普通原文 | 选择账号和目录，使用「阅读目录最新邮件」打开普通视图。原文按钮仍能读取缓存 RFC822，探针核对合成 Bcc 头。 |
| 已打开正文的目录撤出 | 保留账号，使用项目凭据定义的条件保存入口移除 Sent。Engine 的公开读取返回需刷新。原正文和消息项退出，另一个账号在同一组合中的邮件仍可打开。 |
| 账号移除与迟到正文 | 第一个窗口已经显示正文。第二个窗口真正发起读取，由浏览器代理短暂扣住 Engine 已生成的结果。移除来源账号后两窗口关闭读区，公开重新读取返回需刷新。放回旧响应后已撤出的正文保持关闭，同组其他账号仍可浏览。 |

`mail.conversations.loadBody` 复用 MIME 正文投影，在解析前后分别检查账号、选中目录的公开可见性与缓存原来源。联系人阅读器只调用该能力。普通单账号阅读器仍可按账号及选中目录读原文。账号开始移除时发布现有工作台实体事件。阅读期间也会重取本机账号定义，确保同一组仍有其他账号时可以关闭已撤出的阅读状态。现有普通标读、回复、转发和新话题仍走原业务能力。

探针使用独立的 Windows 临时 Vault、真实 Engine、实际 Mail 组件及本机回环 IMAP 和 SMTP。目录撤出前后核对 IMAP 命令和 SMTP DATA 计数不变，晚到响应期间只需本地服务。目录撤出通过项目凭据定义保存路径注入，当前 Mail 界面可在添加账号时选择目录。复跑方式见 [S2.1 联系人对话](../evidences/S2.1-contacts.md)，定向测试名为 `workbench-renderer conversations-engine`。 公开 Sent 阅读截图（本机原件 `temp/dev/feature_2026-11-19-issue-8-mail-module/integration/legacy-7984bff4/S1-workbench/mail-public-sent-390.png`）
