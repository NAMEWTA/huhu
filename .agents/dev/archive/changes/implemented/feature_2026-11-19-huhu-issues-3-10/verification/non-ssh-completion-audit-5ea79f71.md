## #4 已确认的交付缺口

1. **W8.1 新格式包恢复已保存的分栏纯布局。** 用户定案纳入已保存的纯布局，恢复后能辨认待绑定目录和未绑定终端。当前布局读写走 Core 文档 `huhu-agent-workspace`，Core 持久目录在 Vault 的 `.huhu/runtime/<machineId>/herdr`。通用包排除运行区，当前代码没有单独导出或恢复纯布局的路径。真实 Engine 包测试先在源库保存到 version 1，经 `vault.exportPackage`、`vault.importPackage` 和目标库重开，明确断言恢复后的布局为 version 0、空布局；Space 记录、相对目录对应及外部目录待绑定均已实现。这一差异在同一台机器恢复到另一空目录即可成立。补齐行为应保留布局结构，同时保持现有运行态、启动回执与本机外部目录绑定的排除边界。 [用户决定](../decisions-2026-11-21.md#L10) · [W8.1](../../feature_2026-11-19-issue-4-agent-cli/tasks/W8.1-new-format.md) · [Core 目录](../../../../../../../plugins/agent-cli/src/engine/index.ts#L113) · [布局存储](../../../../../../../plugins/agent-cli/src/engine/workspace-layout.ts#L110) · [ZIP 策略](../../../../../../../packages/vault/src/package/package.ts#L27) · [恢复断言](../../../../../../../apps/engine/test/agent-workspace.test.ts#L40)
2. **W2.2 迟到会话的当前 Tab 收纳。** 失效目标产生的真实进程可以从原 Space 找回，已实现手动查看且不自动创建 Tab。用户定案及确认稿要求「放入此 Tab／当前标签」。当前预览的唯一放置动作是「放入新标签」，调用 `placeSession` 的 `{ kind: "tab" }` 分支并聚焦追加的标签。W8.2/W8.3 同包用例也点击这个按钮，证明原进程可找回及重新装入新标签。当前标签已存在时，确认过的放置目标仍无入口。 [用户决定](../decisions-2026-11-21.md#L9) · [确认稿](../../feature_2026-11-19-issue-4-agent-cli/prototype-review.md#L15) · [生产动作](../../../../../../../plugins/agent-cli/src/ui/AgentCliModule.tsx#L693) · [同包用例](../../../../../../../tests/e2e/workflows/task-journey.spec.ts#L605)

另有一项已公开的复刻范围差异。历史的精确恢复与分支有 Pi 路径，Claude/Codex 有扫描、预览及适用的原现场定位；两者从已结束记录新启恢复或 fork 会被 `historySourceBlocked` 拒绝。当前适配的 CLI 参数只接受 ID，生产实现要求能绑定已选择的文件。规格允许不具备资格的记录只读并说明原因，现有界面和测试按此支持边界运行。它不属于账号缺证，也没有证据表明当前只读路径本身退化。交付表述应保留这一差异。 [原 Issue §10](../../feature_2026-11-19-issue-4-agent-cli/source.md#L376) · [实现阻断](../../../../../../../plugins/agent-cli/src/engine/index.ts#L531) · [W5.2 证据](../../feature_2026-11-19-issue-4-agent-cli/verification/W5.2-W8-linux.md)
