# HUHU Workbench 需求简报

本 Change 是 HUHU Workbench 从 0 到 1 正式开发的唯一依据。行为契约见 [spec](spec.md)，阅读顺序见 [README](README.md)。

## 一句话问题

个人用户的知识、待办、长期档案、Agent CLI 与远程环境分散在多个工具里；数据被私有格式锁住，Agent 的执行与人的判断混在一起。HUHU 用一个本地 Vault 统一保存这些内容：离开 HUHU 也能用普通编辑器读懂，执行类工作（Agent CLI、SSH、定时动作）则在同一工作台中可见、可追溯、可恢复。

## 输入与优先级

| 优先级 | 来源 | 用法 |
| --- | --- | --- |
| 1 | 用户本次任务的强制约束（下节） | 不可改变 |
| 2 | 可运行原型 `temp/huhu-workbench-v8`（产品版本 v9，入口 `HUHU_Workbench_V9.html`） | 产品意图、功能范围、关键交互与视觉的基准 |
| 3 | `temp/sources` 中已读源码的成熟实现 | 技术实现与组件来源，见 [reuse](reuse.md) |
| 4 | 本 Change 早期版本中仍合理的设计 | 已并入当前文件；旧文件已删除 |

原型中的“演示口令”“故障演练开关”“演练记录”“样例检测结果”属于原型说明工具，不是产品功能；正式产品用真实行为替代它们（见 [decisions](decisions.md) D-24）。

## 强制约束

1. **Vault 是持久化根。** 笔记、任务、档案、捕获、规则、运行结果、评论都是 Vault 内可直接阅读的 Markdown（YAML frontmatter + 正文）。`.huhu/` 只放配置、运行可靠性材料和可删缓存。
2. **Task 只有两态。** `completed: false | true`。任何 Task 都可人工直接勾选或取消；Agent 结果不自动勾选；勾选不终止进程。执行方式只有 `manual` / `agent`；提醒独立。
3. **自动化独立。** 按时间激活动作；内置规则扫描未完成的 Agent 任务，不另造 Task。
4. **保险箱在 Vault 内。** 账密、密钥、令牌由用户自设的主密码加密，密文存于 `<Vault>/.huhu/safe/`；不使用操作系统钥匙串。
5. **首版平台仅三个：** `win32-x64`、`darwin-arm64`、`linux-x64`。不做 Windows ARM64/32 位、macOS Intel、Linux ARM64、移动端。
6. **不做签名与公证。** 首版安装包不签名；用户自行接受安全提示后安装。
7. **首版交付 = 规划的全部功能。** 开发按依赖分阶段推进，但不以阶段缩减首版范围。
8. **0→1 新项目。** 不兼容任何旧原型格式、旧接口或旧数据；不保留迁移层或双写。
9. **复用优先。** 能复制成熟实现就不自研；复制保留来源与版权头。
10. **Change 只含 Markdown。** 不在 Change 中存放截图、JSON 或原型副本。
