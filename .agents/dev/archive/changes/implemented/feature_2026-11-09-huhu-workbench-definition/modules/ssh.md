# 远程连接（SSH）

插件：`ssh`。原型依据：`execution.jsx`（`SSHView`）、`ssh-console.jsx`、`ssh-session-state.js`。复用：R-39–R-43。依赖：safe（凭据引用）。

## 2. 界面

- **模块侧栏**：标题“SSH 主机 n”+“+”；搜索；分组“连接配置”下列出主机（名称、`user@host`、右侧连接状态点）；底部“凭据以引用方式保存 · 连接、Shell 与 Exec 独立管理”与“全部连接审计”。
- **主机页**：页头主机名 + 编辑、删除、主按钮“连接主机”/“断开”；分段：连接概览 · 交互终端 · Exec · 文件 · 审计；右侧状态徽标（未连接/连接中/已连接/失败）。
  - 连接概览：三张信息卡（认证方式、连接路径 直连/经 n 个跳板、主机信任 已信任/首次连接待确认）；“连接路径”图：本机 → 跳板1 … → 目标，每个节点显示名称与 `user@host:port` 和该跳的信任状态（修正原型中只有图标无文字的问题）；“连接与安全”列表：凭据引用（显示保险箱条目名称，不显示值）、主机密钥指纹。
  - 交互终端：shell 标签（重命名、关闭视图、清空视图输出（不结束 shell，审计保留）、结束 shell）、“新建终端”、“并排查看”；TerminalView；未连接时显示“先连接主机，再打开终端”。
  - Exec：命令输入（单行）、超时（秒）、“运行”；输出区（stdout/stderr 区分颜色）、退出码、耗时；运行中“中断”。
  - 文件：路径面包屑 + 列表（名称、大小、修改时间、权限）；操作：上级目录、刷新、新建文件夹、上传、下载、重命名、删除（AlertDialog）；文本文件（< 2 MiB）可预览。
  - 审计：本主机审计 DataTable（时间、动作、结果、详情）。
- **主机密钥对话框**（`ssh.hostKeyPrompt` 事件）：首次：主机与跳序、密钥类型、SHA256 指纹、“信任并连接”/“取消”；变化：红色警告“主机密钥与已记录的不同，可能存在中间人攻击”，只提供“取消”和“查看已记录的指纹”，要信任新密钥必须先在主机设置中“移除已记录的密钥”（AlertDialog）。
- **主机编辑对话框**：显示名称、主机名/IP（不能含空格或路径）、端口（1–65535）、用户名、认证方式（私钥：保险箱条目选择，可选口令条目；密码：保险箱条目；系统 SSH Agent）、跳板机（从已有主机中按顺序选择，禁止循环）、标签、连接超时（默认 20 秒）。

## 3. 行为

### 连接（`ssh.connect({hostId})`）

1. 冻结路由：目标与跳板主机配置快照；生成 `attemptId`。
2. 逐跳：第一跳 `ssh2.Client.connect`；后续每一跳在前一跳上 `forwardOut('127.0.0.1', 0, host, port)` 得到流，作为下一跳 `connect({sock})`。
3. 每一跳的 `hostVerifier` 使用 R-40：在 `.huhu/ssh/known_hosts` 中查找。匹配 → 继续；不存在 → 发布 `ssh.hostKeyPrompt`（reason first），等待 `ssh.hostKey.decide({attemptId, hop, accept})`（超时 120 秒视为取消）；接受则写入 known_hosts；不匹配 → 立即失败 `SSH_HOST_KEY_MISMATCH`。迟到的决定（attemptId 已结束）被忽略。
4. 认证（R-41）：私钥/密码从保险箱解密（需要解锁，否则 `SAFE_LOCKED` 并提示解锁）；系统 Agent 使用 `SSH_AUTH_SOCK`（Windows 使用 OpenSSH agent 命名管道 `\\.\pipe\openssh-ssh-agent`）。
5. 成功 → 状态已连接，审计记录。失败 → 状态失败，显示原因（超时、认证失败、主机不可达、跳板 n 失败）与“重试”。

### Shell、Exec、SFTP

- Shell：`client.shell({term: 'xterm-256color', cols, rows})`，Engine 维护 shell 列表，字节流经 `/ws/terminal/ssh-<shellId>`；关闭视图不关闭 channel；“结束 shell”关闭 channel。连接断开后所有 shell 变为“已结束”，重新连接后需新建（不会把旧 shell 绑定到新连接）。
- Exec：`client.exec(command)`；`ssh.exec.cancel` 发送 `signal('INT')` 并关闭 channel；超时同样处理；记录退出码与输出末 2000 行。
- SFTP（R-42）：`client.sftp()`；上传写入远端临时文件 `<name>.huhu-upload-<rand>` 后 `rename`；覆盖已存在文件前要求确认；断网中断的传输删除临时文件并提示。
- 断开：关闭全部 channel 与连接（逆序关闭跳板）。插件停用或 Vault 关闭时同样断开。

## 4. 验收

| ID | Given | When | Then |
| --- | --- | --- | --- |
| ACC-SH-01 | 测试 SSH 服务器（testkit，基于 ssh2 Server）首次连接 | 连接 | 弹出指纹对话框；接受后连接成功，known_hosts 新增一行 |
| ACC-SH-02 | 已信任主机更换了主机密钥 | 连接 | 失败并显示 `SSH_HOST_KEY_MISMATCH` 警告；没有发送认证凭据 |
| ACC-SH-03 | 经一个跳板机的目标，两者均首次连接 | 连接 | 依次出现两个指纹对话框（标明第 1 跳、第 2 跳）；取消第二个则整个连接失败且跳板连接被关闭 |
| ACC-SH-04 | 主机配置 A 以 B 为跳板，B 以 A 为跳板 | 保存 | 字段错误“跳板链不能形成循环” |
| ACC-SH-05 | 已连接，打开 shell 运行 `sleep 100` | 关闭 shell 视图，再从 shell 列表打开 | 回到同一 shell，命令仍在运行 |
| ACC-SH-06 | Exec 运行 `sleep 30` | 点击中断 | 显示已中断与退出码（或“未知”）；连接仍可用 |
| ACC-SH-07 | 密码认证主机，保险箱已锁定 | 连接 | 提示解锁保险箱；解锁后重试成功；审计与日志中无密码 |
| ACC-SH-08 | 远端已存在 `a.txt` | 上传同名文件 | 要求确认覆盖；取消则远端文件不变 |
