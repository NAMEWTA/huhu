# P10.2 验证所有现行消费者已切到所属模块

所属交付 P10。本项承接 [Issue S4、D01–D05、C01–C06](../source.md)，行为规则见[模块认证责任](../spec.md#modules)，设计见[现有消费者](../design.md#current)。

## 交付与依赖

#9 整合者一次替换已存在消费者，清理旧能力、订阅、清单、权限、文案、测试与示例。#7/#8 扩展的运行证据由所属 change 提供。

**前置产物**　P3、P4、P5、P6、P8、P9、[P10.1](P10.1-external-safe.md) 的适用子项；P7 对齐 [#8](../../feature_2026-11-19-issue-8-mail-module/plan.md) 真实进度。

按[规格覆盖表](../plan.md#coverage)核对每个真实消费者的 owner、脱敏回执和实际证据。P7 在 Mail 尚未接入时只签收凭据合同，缺少的真实 Mail 联调保留在 #8 的记录中。

**代码入口**　[apps/engine/src/boot.ts](../../../../../../../apps/engine/src/boot.ts)、[packages/kernel/src/dispatcher.ts](../../../../../../../packages/kernel/src/dispatcher.ts)、[tests/e2e/packaged/packaged.spec.ts](../../../../../../../tests/e2e/packaged/packaged.spec.ts)。

## 原型与确认范围

[Safe 原型](../prototype/index.html)的待确认场景为「组合演示：Safe 锁定 → SSH/Git/脚本仍可用 → 返回解锁，账号与标签完好」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[保险箱演示区域](../prototype/index.html#main)，核对settingsPage 的模块设置入口与 safePage 的个人条目视图，跨模块运行另验。

## 验收

- [ ] 在干净组合版本从 Safe、SSH、Git 和自动化真实入口按 C01–C06 操作；核对 D01–D05 的源码扫描、帮助、Git 暂存及整包证据，记录平台和实际运行范围。
- [ ] 分别停用插件、取消执行或使认证不可用，核对所属模块错误与清理；生产引用仍有 secretUse、safe://、allowedModules、envRefs 或借 safe.unlocked 恢复的消费者时列出具体调用点，联合切换不能验收。

使用新建隔离 Vault 和无价值的合成字段，记录测试入口、平台、操作结果及脱敏标识。实际结果回填本任务。
