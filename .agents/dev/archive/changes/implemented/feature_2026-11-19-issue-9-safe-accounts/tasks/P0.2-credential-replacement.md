# P0.2 替换模块认证失败后仍可使用原配置

所属交付 P0。本项承接 [Issue S0、§5.2、D03](../source.md)，行为规则见[模块认证责任](../spec.md#modules)，设计见[调用与失败处理](../design.md#operations)。

## 交付与依赖

所有者在配置 revision 提交前暂存新的保护版本，提交成功后清无引用的本机版本。其他模块只复用保护原语。

**前置产物**　[P0.1](P0.1-local-protection.md)。

**代码入口**　[packages/vault/src/write.ts](../../../../../../../packages/vault/src/write.ts)、[plugins/safe/src/engine/crypto.ts](../../../../../../../plugins/safe/src/engine/crypto.ts)、[apps/desktop/src/main/engine-supervisor.ts](../../../../../../../apps/desktop/src/main/engine-supervisor.ts)。

## 原型与确认范围

[Safe 原型](../prototype/index.html)的待确认场景为「模块设置 → 保存失败/重新设置」。此处仅用于对照可见结果。服务行为由下列验证判定。 [版本与用户确认范围](../prototype-review.md)

定位到[保险箱演示区域](../prototype/index.html#modal)，核对openOwner，认证方式、替换与清除；盘上提交中断另在测试目录演练。

## 验收

- [ ] 合成两份相同名称的配置，对其中一个显式替换、保留、清空、删除，重启检查只有指定对象的认证状态改变。
- [ ] 在暂存、配置切换、清理时分别中断或并发提交旧版本。恢复后恰有一个完整可用版本，其他插件/Vault 的绑定和数据未被清理。

使用新建隔离 Vault 和无价值的合成字段，记录测试入口、平台、操作结果及脱敏标识。实际结果回填本任务。
