# P1.3 只更新选中账号或条目公共信息

[验收报告](../evidences/P1.3-edit-account.md)

所属交付 P1。本项承接 [Issue S1、A02–A03、A07、D03](../source.md)，行为规则见[个人多账号操作](../spec.md#personal)，设计见[调用与失败处理](../design.md#operations)。

## 交付与依赖

Safe 将 entryId、accountId、expectedRevision 与密码 keep/set/clear 配对。单条目原子更新，旧版本冲突可重读。

**前置产物**　[P1.2](P1.2-save-entry.md)。

**代码入口**　[plugins/safe/src/engine/safe.ts](../../../../../../../plugins/safe/src/engine/safe.ts)、[packages/vault/src/write.ts](../../../../../../../packages/vault/src/write.ts)、[packages/kernel/src/idempotency.ts](../../../../../../../packages/kernel/src/idempotency.ts)。

## 原型与确认范围

[Safe 原型](../prototype/index.html)的待确认场景为「多账号详情 → 编辑一个账号 → 保存冲突/重载」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[保险箱演示区域](../prototype/index.html#modal)，核对showEdit / saveEdit，选择「版本冲突」或「保存失败」再保存。

## 验收

- [ ] 先修改第三个账号的手机、备注、密码，再仅修改公共网址，重开后其余账号逐字一致；测试含前后空格的密码和显式清空。
- [ ] 两个 caller 读同一 revision 后各改一次，后一个报告冲突，无遮罩回写；写入中断后重开能确定是哪次完整提交。

使用新建隔离 Vault 和无价值的合成字段，记录测试入口、平台、操作结果及脱敏标识。实际结果回填本任务。
