# P10.1 保险箱工具与旧凭据路径切换

## 合同

当前个人条目、账号、标签和生命周期能力沿用桌面与已登录 Web 的业务 handler。工具初始关闭。外部工具先以自己的身份调用已开放的 `safe.status`，取 `instanceId`、`generation` 和 `callerProof` 作为下一次调用的 `session`。证明绑定认证入口、主体、当前进程实例和解锁代。每次读取、写入及响应前使用当前 Vault 的策略。写入沿用条目或清单版本，提交守卫位于暂存之后及原子发布之前。

`safe.accounts.reveal` 单独开放，只返回明确指定账号的密码。普通条目输出含 `hasPassword`，写回执只含 ID、版本与状态。回放使用实时结果与版本，通用持久意图不可用。个人写入使用 handler 模式跳过公共输入摘要和结果回执。生命周期仍经原有解锁与主密码校验。外部生命周期写入也携带当前会话代。

底层策略与 transport 各自审计脱敏动作和状态。旧 `safe.items.*` 入口、共享 `secretUse` service 和 `safe://` 解析器从 Safe 生产路径移除。旧 keyring、元数据及密文仍可作为原始恢复资料。测试专用夹具通过真实旧版 AAD 生成同一份磁盘数据。

## Windows 证据

| 验证 | 实际结果 |
| --- | --- |
| 工作台 HTTP、CLI 子进程、通用 HTTP API、MCP HTTP、MCP stdio | 同一条目用真实请求串行修改和查询，全部命中相同修订链。CLI 使用 `--input-file -` 写入更换密码的输入。普通详情不含密码，两种 MCP 均在显式授权后读回当前目标账号。 |
| 单项策略与身份 | 干净安装外部发现无 Safe。只开详情仍拒绝明文与写入。明文选择独立且为高风险。撤销后已连接 stdio 继续调用旧工具名也被拒绝。另一个已授权 HTTP 主体复用旧会话和键被拒绝。 |
| 锁定、重交及切 Vault | 同键读回修改后的当前密码。同键重交已成功的旧版本写入得到冲突。锁定、重开解锁及换入另一个 Vault 后，旧实例或旧代均失效。旧解锁输入也不能重放。 |
| 在途撤销 | 暂存密文期间撤销写工具，旧清单字节保持。暂停已解密的响应后撤销读取工具或锁定，响应不含该密码。同源 Web 邀请撤销会中止在途读取，继续使用旧 cookie 得到 401。 |
| 旧数据与副作用 | 旧接口报告未知能力。旧 keyring、元数据及密文在启动、解锁、锁定和失败的个人读取后逐字一致。审计、Vault 和共享结果文件未发现合成密码或证明。 |

测试使用独立临时 Vault、合成值与回环入口。主密码与账号密码不进入命令参数或验收资料。 [外部入口回归](../../../../../../plugins/safe/test/external.engine.test.ts) · [旧格式测试夹具](../../../../../../plugins/safe/test/legacy-fixture.ts)

Safe 全量四个文件、36 项通过。SSH 自有密码在 Safe 未初始化、锁定和停用状态下均通过回环连接。Git HTTPS 回环认证修复测试通过，Safe 解锁没有引发新的请求。

Electron 生产构建成功。标准 Workbench 启动在注册 `widget:automations:summary` 时缺少来源并白屏。临时生成的渲染器资源跳过该条缺失项后，桌面多账号显隐、窄窗版本冲突、标签管理及锁定均通过。既有标签交集测试的直接写入夹具补齐幂等键后复验通过。独立浏览器测试通过邀请登录 Web、初始化并重新解锁与桌面共享的保险箱。合计五项界面验证。临时改动仅用于复验，生成资源已回写原字节。
