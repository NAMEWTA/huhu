# T1.4 按原快照重试已证实失败的执行

[验收报告](../evidences/T1.4-retry-snapshot.md)

用户能区分查询旧尝试、以相同输入重做，以及用修改后的正文重新派遣。

归属 T1，对应 [Issue #5 验收矩阵](../source.md) C06、D02、D06、D07。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 的不可变快照、run/attempt 与占用。此片可用带确定终态的执行凭据验收。
- **职责与边界**　API 重传保持原 attempt；用户明确重做须证明旧副作用已停止，复用原 run/快照并追加一次 attempt；新正文产生新意图。
- **现有代码入口**　[tasks/engine/index.ts](../../../../../../../plugins/tasks/src/engine/index.ts) · [tasks/engine/service.ts](../../../../../../../plugins/tasks/src/engine/service.ts) · [kinds/task-run.ts](../../../../../../../packages/contracts/src/kinds/task-run.ts) · `automations/engine/claims.ts`（原规划路径，当前已迁移） · [tasks/ui/TaskDetail.tsx](../../../../../../../plugins/tasks/src/ui/TaskDetail.tsx)。
- **原型走查**　[运行详情 → 重试原输入、新输入、等待对账](../prototype/index.html#detail)。对照「明确未发送」与「发送确认丢失」两个模拟分支。确认操作和原因。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 令原轮明确失败，改写任务后点击同输入重做，比较两次 payload/hash 并核对原 run 多一个 attempt；另选新输入可查新事件。
2. unknown、损坏记录、跨机器未核实、任务已关闭或删除时拒绝旧重试；只读请求不重建任务或释放占用。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../../../plugins/tasks/test/service.test.ts) · [plugins/tasks/test/shared.test.ts](../../../../../../../plugins/tasks/test/shared.test.ts)
