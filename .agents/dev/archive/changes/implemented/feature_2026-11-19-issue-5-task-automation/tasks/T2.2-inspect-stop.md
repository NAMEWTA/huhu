## Windows Engine 阶段

桌面工作台的 `tasks.dispatch.stop` 按原 taskId、dispatchId、runId 和 stopId 保存停止意图。后续读取 `tasks.dispatch.stop.read`。发送前记录持久状态，丢确认后仅查询同一原绑定。已知自然终态时保留原结果。原生中断确认后显示运行已取消、关闭未完成的原生问题，任务的业务状态仍由用户控制。

真实 Windows Engine 的合成执行器夹具验证停止意图写入、其他运行与竞争 stopId 拒绝、停机重开后仅查询一次、同一执行器只收到一次原轮的停止请求。Agent 单独的固定 Core 夹具验证同 thread/turn 的中断终态和异代次不触碰新 shell。桌面按钮、人工接管及真实提供方的产品路径继续按对应范围验收。 [Tasks 停止回归](../../../../../../../plugins/tasks/test/persistence-http.test.ts) · [Agent 固定 Core 回归](../../../../../../../plugins/agent-cli/test/native-stop.live.test.ts)

组合回归通过真实桌面 Engine HTTP 调用到 Tasks，再由生产插件权限进入固定 Core 和合成 App Server。Engine 在回包后仅记录待核实，重开后按原轮终态确认已停止。原 thread／turn 收到一次中断，运行显示已取消，任务仍为进行中。

### 任务详情与运行抽屉

两处共用运行详情，桌面以确认对话框发起停止。列表和运行抽屉读回同一条停止记录，保留待核实、已停止、已结束及绑定失效等反馈。pnpm 12.10.1 在 Windows 上复跑 `pnpm exec vitest run --pool forks --maxWorkers 1 plugins/tasks/test/persistence-http.test.ts -t '原轮停止先保存意图'`，1 项通过。失联后，原停止 ID 的待核实与恢复终态分别从任务详情和全局运行查询读回，执行器收到一次停止，任务保持进行中。真实窗口的停止确认和重开仍待同包验证。
