# T3.2 从原问题提交一次回答

任务详情和运行抽屉共享回答入口；回答已保存、待发送、待核实、已处理可区分。

归属 T3，对应 [Issue #5 验收矩阵](../source.md) A05、A06、A07、C02、D01、D03、D09、D11、E02。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 验收与取证

1. 在两个入口同时回答最后一个有效问题，插入新问题改变顺序，再重传；以具体 ID 核一个有效接受和一次输入。停用 Automations 后仍可从详情作答。
2. 接受后评论/event 尚未物化即断电，重启补齐；相同键异文、不同键抢答、发送确认丢失或原生请求失效时拒绝或待核实，不重发或自动批准。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../../../plugins/tasks/test/service.test.ts) · [plugins/automations/test/service.test.ts](../../../../../../../plugins/automations/test/service.test.ts)

## Windows 原生回答阶段

Tasks 经内部工作台 HTTP 接口 `tasks.reply` 保存当前 task、run、session、request、version、replyId 和选项，再按稳定 ID 投影回答评论。回复查询返回 `pending`（已保存）、`sending`、`unknown`（待核实）、`accepted`（原生已确认）、`expired`、`not_sent` 或 `unsupported`。保存与回执接收使用同一 task 写锁。原生路由从已签收的当前问题解析，回复接口不接收该路由。

真实 Windows Engine 与合成回答执行器的测试停用 Automations，并提交两个明确绑定同一问题的回答。一个保存，另一个返回版本冲突。同 replyId 同载荷重交读回原记录，同 ID 异载荷返回幂等冲突。评论投影受阻时关闭 Vault，重开只补写一条评论。合成发送确认丢失后保留 `unknown`，再次启动仅向执行器查询原回复并读到 `accepted`，累计发送一次。答案绑定原问题，即使另一个问题随后出现。

固定 Windows Core 0.1.19、真实 Engine 与合成 Codex App Server 组合实测一次原生回复。Tasks 查询先显示待核实。原生确认在 Engine 关闭期间写入，重开后读到已处理。时间线只保留一条回答和一条结果，二者关联同一 run 和会话。再次重开仍是一份原始输入、一次原生回答和两份持久回执。

验证入口见 [persistence-http.test.ts](../../../../../../../plugins/tasks/test/persistence-http.test.ts) 和 [native-receipts.live.test.ts](../../../../../../../plugins/agent-cli/test/native-receipts.live.test.ts)。真实 Codex 的确认事件格式与任务详情、运行抽屉的共同入口仍待验收。

## Windows 普通回答与后续轮次

工作台后端验证原 Task、run、session、request 和版本后，将回答与完整的新轮派遣意图一次保存。随后投影一条回答评论。新轮保留 `parentRunId`，只带答复和用户通过消息 ID 明确选中的讨论内容。原轮仍活跃时保持待派，只有原会话绑定提供接收证据才显示已处理。

以真实 Engine HTTP 与合成派遣执行器验证了两个入口同时回答、只受理一个、未派发送前重开、原键重交、异文拒绝、同绑定的新轮与唯一评论。Task 持久化套件 26 项通过，日志位于 `temp/issue-baseline/normal-reply-persistence.log`。固定 Core 上同一个受控会话的组合验证与工具入口切换单独取证。 [Engine 回归](../../../../../../../plugins/tasks/test/persistence-http.test.ts)

固定 Windows Core 0.1.19、真实 Engine/Tasks 与合成 App Server 的同进程组合通过三轮。第一轮经原生回答继续。第二轮显式选择同一会话，同时向可信 Tasks 接收端补入合成普通问题。回答先等待第二轮完成，再在同一 Core 地址、进程代次和 native thread 上开始第三轮。第三轮只收到一次答复，结果写入原 Task 并关联父运行。累计四份 Agent 持久消费 ACK，原轮时间线读回一致。日志位于 `temp/issue-baseline/normal-existing-combined-live.log`。 [组合回归](../../../../../../../plugins/agent-cli/test/native-receipts.live.test.ts)
