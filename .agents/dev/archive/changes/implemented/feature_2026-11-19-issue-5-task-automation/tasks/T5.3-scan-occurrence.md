# T5.3 每个定时点只接受一次扫描

用户可保存和修改扫描补充指令，看到每次发生接受、跳过与等待的原任务以及原因。

归属 T5，对应 [Issue #5 验收矩阵](../source.md) B03、B05、B06、B07、B09、D10。[行为规格 · 何时自动派遣](../spec.md#何时自动派遣) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T4.2](T4.2-window-preview.md) 的分类和 [T1.2](T1.2-accept.md) 的幂等受理；复用现有可创建规则，无需默认规则先装好。
- **职责与边界**　Automations 先记 ruleId/scheduledForUTC、规则版本与入选名单，逐项用稳定身份提交。手动 invocation 独立，一次运行不改日程。
- **现有代码入口**　[automations/engine/scheduler.ts](../../../../../../../plugins/automations/src/engine/scheduler.ts) · [automations/engine/service.ts](../../../../../../../plugins/automations/src/engine/service.ts) · [automations/engine/scan.ts](../../../../../../../plugins/automations/src/engine/scan.ts) · [automations/ui/RuleEditor.tsx](../../../../../../../plugins/automations/src/ui/RuleEditor.tsx) · [agent-autoloop/kernel/decide.ts](../../../../../../../temp/sources/agent-autoloop/kernel/decide.ts)。
- **原型走查**　[独立后台场景 → 到期扫描、掉电、重开](../prototype/index.html#simulation)。用独立「触发到期规则」「模拟重启」操作，不把后台动作藏进业务按钮。确认运行详情显示接受/等待/跳过，界面查看不触发扫描。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 让两规则与一次人工派遣同到，修改规则后重放相同发生。核对原版本/补充指令、稳定 eventId、一次有效执行；关机错过多周期仅补一次当前扫描。
2. 在记录发生、逐项受理、推进游标之间分别断电，用原名单补齐；停用期不追补，日程恢复后新命中才用新版本，长任务不阻塞规则详情。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../../../plugins/automations/test/service.test.ts) · [plugins/automations/test/scheduler.test.ts](../../../../../../../plugins/automations/test/scheduler.test.ts)

## 内部落点

- `taskScanOccurrences` 是 Automations 的进程内服务。`scheduled(ruleId, scheduledFor)` 以规则 ID 和 UTC 时刻定位发生，`invoke(ruleId)` 每次分配独立身份。筛选采用规则时区和实际扫描时刻。先原子写入规则版本、筛选配置、补充指令和各项输入身份，再把入选项交给 Tasks 受理。Tasks 用相同的输入身份校验尚未受理的项，并保存执行快照。任务与资源的当前状态由 Tasks 记录。
- `recover()` 按持久记录补齐未收尾的项，`lastScheduledFor(ruleId)` 从已落盘发生推导调度游标。原发生在规则变更、停用或删除后仍可重投，新发生按当前启停和版本判断。恢复不会重新筛选。接受回执的 `eventId` 和 `runId` 用于查询同一 Tasks 派遣。
- Windows 自动化验证在发生落盘后、Tasks 受理前导出 ZIP。保留和重置 Vault ID 的两次分别恢复均能读原名单，同一时刻重交只返回历史，恢复受理和派遣数为零。只有原机器、原物理目录和原 Vault 的发生参与重放与游标计算。 [ZIP 回归](../../../../../../../plugins/automations/test/task-scan-occurrences.test.ts)
- 绑定目标的只读预览和新发生先刷新 CLI 信息，随后共用 Tasks 的任务预检。已有会话按原 session 送检，原生恢复按原会话 ID 送检。Engine 夹具验证预览产生零写入，两类入选项都保留原目标，实际领取由执行器核对资源。 [目标回归](../../../../../../../plugins/automations/test/task-scan-occurrences.test.ts)
- 生产调度、公开手动入口、预览和运行详情的统一接线见 [T7.1](T7.1-cutover.md)。本切片通过真实 Engine 装配验证内部服务，执行器采用合成替身。 [服务实现](../../../../../../../plugins/automations/src/engine/task-scan-occurrences.ts) · [Engine 回归](../../../../../../../plugins/automations/test/task-scan-occurrences.test.ts)
