# T3.4 向原任务发送补充并保留普通讨论

[验收报告](../evidences/T3.4-supplement.md)

没有待答问题时，也可选中补充内容发送给此任务。发表评论只新增讨论，Agent 上轮输出不会自动成为指令。

归属 T3，对应 [Issue #5 验收矩阵](../source.md) A06、A07、C02、D01、D03。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 的稳定接受记录、#4 [W6.1](../../feature_2026-11-19-issue-4-agent-cli/tasks/W6.1-bound-input.md) 的输入仲裁；可先用合同接收端验选入上下文与去重。
- **职责与边界**　补充意图保留所选消息身份、顺序、目标和快照，不能把补充当作原生请求的批准。普通评论沿用 Markdown 既有入口。
- **现有代码入口**　[ui/TaskDetail.tsx](../../../../../../../plugins/tasks/src/ui/TaskDetail.tsx) · [engine/service.ts](../../../../../../../plugins/tasks/src/engine/service.ts) · [engine/index.ts](../../../../../../../plugins/tasks/src/engine/index.ts) · [dto/task.ts](../../../../../../../packages/contracts/src/dto/task.ts)。
- **原型走查**　[任务详情 → 发表评论/发送补充信息](../prototype/index.html#detail)。确认两个入口、已保存与待核实反馈。对应体验待用户按[原型确认记录](../prototype-review.md)的指纹和范围确认。

## 验收与取证

1. 在任务中发普通评论和两条补充，只选择后一条发送，检查原会话一次输入仅含选中内容，另一任务的讨论、旧结果与未选消息未加入。
2. busy 后重启并重试同意图，仍只处理选入的一次；若已写但无确认，保留待核实，用户可回原时间线查看。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../../../plugins/tasks/test/service.test.ts) · [plugins/automations/test/service.test.ts](../../../../../../../plugins/automations/test/service.test.ts)

## Windows Engine 验收

独立的工作台补充入口保存原 Task、run、session、supplementId 及用户选择的消息顺序。一次保存冻结派遣文本和原会话绑定。原运行完成且输入可用后派遣独立后续轮。普通评论仍由原 Markdown 评论入口保存。

通过真实 Engine HTTP 和合成派遣执行器验证了跨任务消息拒绝、仅发送选中的消息、忙时停机重开及发送确认丢失。重交原键继续核对，异文被拒，原会话累计只收到一次补充，原 Task 时间线只新增一条补充事件。Task 持久化 27 项通过，日志位于 `temp/issue-baseline/task-supplement-persistence.log`。 [组合回归](../../../../../../../plugins/tasks/test/persistence-http.test.ts)
