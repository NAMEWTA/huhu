# T1.3 在发送前取消指定待派任务

[验收报告](../evidences/T1.3-cancel-pending.md)

即使原规则已经删除，用户仍可在任务中查到并单独取消这条已入队未发的意图。

归属 T1，对应 [Issue #5 验收矩阵](../source.md) C07、D08、D10。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 的接受身份、领取状态和持久记录。
- **职责与边界**　Tasks 拥有取消意图。取消指定项、人工关闭任务与停止正在运行的 CLI 分开；可能已发送时转到 T2.2 核验。
- **现有代码入口**　[tasks/engine/index.ts](../../../../../../../plugins/tasks/src/engine/index.ts) · [tasks/engine/service.ts](../../../../../../../plugins/tasks/src/engine/service.ts) · `automations/engine/claims.ts`（原规划路径，当前已迁移） · [automations/engine/holds.ts](../../../../../../../plugins/automations/src/engine/holds.ts) · [tasks/ui/TaskDetail.tsx](../../../../../../../plugins/tasks/src/ui/TaskDetail.tsx)。
- **原型走查**　[待派任务 → 单项取消、取消确认与竞争](../prototype/index.html#detail)。确认所选任务及保留项。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 造两个待发任务，按其中一个 event 取消并重启，只有另一个仍可领取；再在领取前关闭任务，验证其未发意图停止。
2. 在领取同时取消、丢取消回包再重试，核对一次终态；有发送可能时原绑定保留，未确认前不显示已停止。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../../../plugins/tasks/test/service.test.ts) · [plugins/tasks/test/shared.test.ts](../../../../../../../plugins/tasks/test/shared.test.ts)
