# T5.1 安装一次可由用户管理的默认规则

[验收报告](../evidences/T5.1-default-rule.md)

首次启用后可在列表看到普通的 15 分钟规则，编辑、关闭或删除后跨重启保留用户选择。

归属 T5，对应 [Issue #5 验收矩阵](../source.md) B01、B07、A08。[行为规格 · 何时自动派遣](../spec.md#何时自动派遣) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　已有规则存储及启停入口。用固定时钟重开测试 Vault 即可验证初始化、停用和删除标志。
- **职责与边界**　默认规则采用工作台 IANA 时区、任务自身目标、包含可执行的逾期及未排期项、一个活跃轮次。
- **现有代码入口**　[automations/ui/AutomationsModule.tsx](../../../../../../../plugins/automations/src/ui/AutomationsModule.tsx) · [automations/ui/RuleEditor.tsx](../../../../../../../plugins/automations/src/ui/RuleEditor.tsx) · [automations/ui/cron-presets.ts](../../../../../../../plugins/automations/src/ui/cron-presets.ts) · [automations/engine/scheduler.ts](../../../../../../../plugins/automations/src/engine/scheduler.ts) · [automations/engine/service.ts](../../../../../../../plugins/automations/src/engine/service.ts)。
- **原型走查**　[自动化 → 默认规则、频率、显式恢复](../prototype/index.html#main-content)。确认默认值与状态可见。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 用全新测试 Vault 首次启用两次并重启，对照只有一条规则及 */15 预设；依次编辑、停用、删除，再显式恢复。
2. 模拟规则/初始化标记只写其一和并发初始化，恢复后无重复；用户删后普通重启不复活，停用期不追补。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../../../plugins/automations/test/service.test.ts) · [plugins/automations/test/scheduler.test.ts](../../../../../../../plugins/automations/test/scheduler.test.ts)

## 数据验收

- Automations 的 `automations.defaultTaskScan` 服务提供 `initializeAfterEnable()` 和 `restore()`。规则使用稳定 ID `rule-defaulttaskscan`。初始化标记完成后，规则缺失即表示用户已删除。待完成的初始化在重开后继续，保留原规则文件和用户版本。 [实现](../../../../../../../plugins/automations/src/engine/default-task-scan.ts)
- Windows 使用固定 pnpm，经真实 Engine、隔离 Vault 和时钟夹具验证 5 项。覆盖并发初始化、工作台时区、普通编辑与停用、删除后重开、显式恢复、两类部分写入和保留损坏文件供修复。 [回归](../../../../../../../plugins/automations/test/default-task-scan.test.ts)
- 闭环首次启用与恢复按钮由 [T7.1](T7.1-cutover.md) 统一接到这两个进程内入口，15 分钟预设及状态呈现随已确认界面验收。
