# T6.1 改期或取消原任务的一次性跟进

[验收报告](../evidences/T6.1-follow-up.md)

用户能查看、调整或取消 followUpAt，到期后只唤醒原任务一次。

归属 T6，对应 [Issue #5 验收矩阵](../source.md) B08、D08、D10。[行为规格 · 并发与失败的外部语义](../spec.md#并发与失败的外部语义) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T5.3](T5.3-scan-occurrence.md) 的稳定发生身份和 [T1.2](T1.2-accept.md) 的受理；关闭任务使用 Tasks 的当前状态。
- **职责与边界**　Automations 维护到期时间和取消版本，Tasks 校验原任务与授权。
- **现有代码入口**　[automations/engine/scheduler.ts](../../../../../../../plugins/automations/src/engine/scheduler.ts) · [automations/engine/service.ts](../../../../../../../plugins/automations/src/engine/service.ts) · [tasks/engine/service.ts](../../../../../../../plugins/tasks/src/engine/service.ts) · [agent-autoloop/kernel/decide.ts](../../../../../../../temp/sources/agent-autoloop/kernel/decide.ts)。
- **原型走查**　[后台场景 → 跟进、改期、取消](../prototype/index.html#simulation)。用独立时钟推进到期；从任务的跟进入口设置、改期或取消。确认原任务、预定时间及到期结果。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 登记一次跟进，改期跨越原到期点，再推进新时钟到期和重启；只在新时刻向同 taskId 有一次输入，任务数不增。
2. 到期与取消/关闭同时发生，核对接受边界；取消后无未来动作，已关闭任务不重开，迟到旧 timer 不投递。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../../../plugins/automations/test/service.test.ts) · [plugins/tasks/test/service.test.ts](../../../../../../../plugins/tasks/test/service.test.ts)

### Windows Engine 验证

固定版 pnpm 运行 Tasks HTTP 持久化和 Automations 发生记录共 40 条用例，全部通过。测试实际启动同一 Vault 的 Engine，使用可控时钟和合成执行器。通过工作台能力改期或取消后，到原时间点的输入次数不变。复制库到另一目录后，已到期的记录显示「需重新确认」。原库重启后对同一任务只受理一次，已关闭任务保持关闭。进行中的任务等原运行的可信完成回执，随后在相同会话生成一轮。

命令为 `pnpm exec vitest run --pool threads --maxWorkers 1 plugins/tasks/test/persistence-http.test.ts plugins/automations/test/task-scan-occurrences.test.ts`。 [测试入口](../../../../../../../plugins/tasks/test/persistence-http.test.ts)

### Windows 桌面

使用确认稿、Electron 44.9.1／Chromium 152 和固定 pnpm 12.10.1。运行 `pnpm exec playwright test tests/e2e/workflows/acceptance.spec.ts --grep '任务详情的一次性跟进' --workers 1`，1 项通过。Esc 关闭后焦点回到原入口。选定的纽约夏令时缺口不写入记录，重复的 01:30 可显式选择较晚时点。保存读回原 taskId 与精确 UTC 时间。改期产生替代发生，任务重开仍显示保存时间，取消后保留取消记录且尚无派遣。到期触发由上面的可控时钟测试复验。用现有 date-fns 与 @date-fns/tz 得到每个候选 UTC 时点并按当地显示值复核。
