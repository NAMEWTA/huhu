# C06 与 H05 收尾

## 判红与修复

`session-slow-bridge.ts` 在 Electron 已挂载编辑器的真实 Y.Doc 上包住事务派发，仅在派发期间改变耗时采样和该事务安排的计时器。首笔真实结算让原桥进入慢速分支，后续计时器保留待办。每个损失回归在动作前检查 DOM 已是新文、Y.Text 仍为旧文。测试没有调用结算出口或伪造保存响应，生产端没有引入探针，也没有改变 vendor 的调度参数。

基线是 `290e8f7` 构建。修复前的比较包含以下观察。

| 路径 | 修复前 | 修复后的检查 |
| --- | --- | --- |
| 自动保存退出 | Electron 退出后，磁盘只有「初始正文首」，DOM 退出前已经有尾字。 | 完整原文件字节和新实例中正文一致。同一 Vault 由 preload 返回的路径确认。 |
| 手动退出与草稿 | 早期用例在重启后尝试定位尚未出现的文件树行，未以此认定草稿内容。 | 用新实例读取草稿原文，核对原文件未改，再经真实搜索入口打开及恢复草稿。 |
| 切 Vault | UI 漏报仍只存在于编辑器中的修改。 | 在 A 中保持会话显示已干净但编辑器有末字，实际切到 B，再切回 A 恢复草稿。 |
| 切笔记、无编辑重开 | 既有布局销毁路径的结果通过。 | 继续核对切换前末字落盘，之后只读重开既不改字节也不改 mtime。 |
| 普通发表、发表并关闭 | 两个入口在同一轮连续点击时向引擎发送了两个旧正文。 | 连续两次点击只发送一次最新正文，关闭任务用评论写入后的任务版本进行 CAS，重开后只有一条人类评论且正文完整。 |
| 撤销到空 | 实际发起评论请求。 | 同样的点击不发请求。 |

## 入口清单

- 笔记的编辑器端口随挂载、只读状态、路径和会话变化注册或解除 drainer。现有会话 flusher 统一等待端口，适用于关闭应用、关闭文档、切视图和保留草稿。Vault 确认框在筛选前排空端口，在确认时再次收集。自动保存、手动草稿以及版本串行写入继续走原会话入口。
- 任务评论的两个按钮共用结算、判空及防并发请求入口。清理请求期间仍保持忙状态。只读性能样本独立计量全部 30 个实例。
- 任务新建和编辑表单在保存生效前读取已结算正文，关闭确认也根据当前正文判断脏状态。
- 档案正文在停手与离开正文区域前结算并排队写入。编辑器卸载的 layout cleanup 先交付文本，页面清理保存同样已结算的正文。实际 Electron 用例覆盖失焦后磁盘和重开。
- 知识库正文选区评论和编辑评论通过 `ComposerMentionInput` 直接读取其当前编辑器内容。属性、整篇及回复使用原生输入。知识库评论桥在定位正文锚点前已经调用笔记宿主的 flush。
- 收件箱的快速捕获、编辑、转入表单使用原生 input 或 textarea 受控值，没有 Y.Text 或延迟桥。
- B07 继续由编辑器既有组合事件处理控制。自动交付在输入法组合期间推迟，显式 `port.flush()` 仍按既有规则同步结算。没有添加 Enter 提交快捷键。检查了 `ime-safe-enter-submit` 和 `forms`，保留原生任务表单提交及已有输入法检查。用 CDP B07 用例核验，另由全量套件覆盖组合中点击源码的路径。

## 验证记录

全量复跑 107 条一次通过，十万文件 Vault 用例按默认设置跳过，实际重试 0 条。全量结束且无其他 Playwright runner 时，1 MiB 打开耗时 413 ms，5000 行输入 p95 14.1 ms，样本 80。测量开始和结束的 1 分钟负载分别为 1.07 和 1.20。两项严格阈值再次通过。
