# W0.2 Windows Core 子进程基线

Windows x64，构建号 26300，Node 24.21.0，本地证据基线 `1b3b385797eee2dbd9d9af42c57be44dd8ad2562`。发行版 Core 0.1.19 的下载包经 [项目锁](../../../../../../../scripts/herdr.lock.json) 校验，SHA-256 为 `1cf7de14c862abc49b8eaeed32dc6a60d8146740edb2c244570d1a9f07cb813a`。取出的 `herdr-core.exe` SHA-256 为 `8c5c088eda5c441502fa58714277a250e38103c66180376ef00d63d6cab03f8d`。调度器为本机 Core 0.1.21。

测试为每轮配置独立命名管道、HC_SESSION、状态和配置目录。先确认管道不存在，启动后核对 Core ID 为 `68390c9c67cc3893acc2d2127ad1fd10`。测试与正常调度器及用户 Vault 隔离。父进程通过测试文件结束，子进程自身没有结束信号。

| 父进程结束方式 | 父进程结果 | 默认子进程 | 启动时显式保留的子进程 |
| --- | --- | --- | --- |
| 自然退出 | t1，exit 0 | t2，原 PID 10032，随父退出 | t3，仍 live，PID 32064 保持一致 |
| 显式结束 | t4，exit 1 | t5，原 PID 2268，随父退出 | t6，仍 live，PID 47888 保持一致 |

分别使用 `run --parent` 和 `run --parent --outlive-parent` 启动，通过 `get` 记录原 PID，`wait --timeout 12` 确认父和默认子结束，重新 `get` 确认可保留进程的身份。每组结束后停止存活的合成进程，最终核对同一 Core ID 后关闭隔离 Core。启动命令 pane `t3y` 退出 0，原始输出及夹具在原工作区 `temp/issue-baseline/core-finished/t3y.log` 和 `temp/issue-baseline/core-lifecycle/`。

这四组为 W1.1 的 Windows 启动路径提供运行证据。收纳后的默认子进程、只读观察者和实际可用的 provider 自动输入待查。包内 Core 的实机启动、shell 与输入回显已在 Windows 阶段包覆盖。见 [包内证据](../../feature_2026-11-19-huhu-issues-3-10/windows-stage-packaging.md)。

## 握手和文档条件写

`t5p` 用同版本和二进制 SHA，在新的独立 Core `3d5ed96db905131083a8bf5ac6cf0b16` 上执行本机命名管道 RPC。`hello` 回传 generation 1、Core 0.1.19，列出 `framed`、`attach`、`events`、`status`、`shell`、`resize_notifications`、`automatic_input`。发送不支持的 generation 得到 `unsupported_generation`。功能声明与实际能力分别记证。

`doc.get` 首读为 version 0，`doc.set` 以 version 0 写入后返回 version 1。另一个连接按 version 0 写入不同正文，得到 `conflict`，未改变值。关闭并从同一隔离状态目录重开 Core，读回 version 1 与原值。探针 `temp/issue-baseline/core-lifecycle/rpc.cjs`，原始输出 `temp/issue-baseline/core-finished/t5p.log`。
