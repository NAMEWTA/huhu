# W3.4 移动已有 pane 或调整 Tab 顺序

在不同叶子和 Tab 间移动同一个终端，用户的输入现场与已有进程跟随稳定 ID 保留。

归属 W3，对应 [Issue #4 验收矩阵](../source.md) B01、B03、E06。[行为规格 · 工作区中的操作](../spec.md#工作区中的操作) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[W3.1](W3.1-split-move.md) 提供可编辑的树和目标叶子；复用 [W2.1](W2.1-space-document.md) 的版本提交。
- **职责与边界**　原叶子脱离与落入目标属于同一结构修改。拖动期间保留 viewer 和 session，键盘重排按同一目标提交。
- **现有代码入口**　`ui/split-layout.ts`（原规划路径，当前已迁移） · `ui/SplitView.tsx`（原规划路径，当前已迁移） · [ui/AgentCliModule.tsx](../../../../../../../plugins/agent-cli/src/ui/AgentCliModule.tsx) · [terminal-topology/terminal-pane-tree.ts](https://github.com/stablyai/orca/tree/8bc232f5ed8b4b36fec0c5f0f85ab96b4c0ccdf3/src/shared/workspace-layout/terminal-topology/terminal-pane-tree.ts)。
- **原型走查**　[六叶布局 → 移动 pane、重排 Tab、取消](../prototype/index.html#pane-tree)。确认拖动目标与键盘焦点，模拟稿未展示的落点另核。对应体验待用户按[原型确认记录](../prototype-review.md)的指纹和范围确认。

## 验收与取证

1. 在六叶布局里移动一个已有终端，再左右移动当前 Tab；核对进程地址、其余叶序以及每个 viewer 的 attach 次数，重开验证新顺序。
2. 拖到自身、取消或落点已在另一窗口关闭时保留最近已确认的树与焦点；不重复运行原命令。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/agent-cli/test/split-layout.test.ts](../../../../../../../plugins/agent-cli/test/split-layout.test.ts) · [tests/e2e](../../../../../../../tests/e2e)
