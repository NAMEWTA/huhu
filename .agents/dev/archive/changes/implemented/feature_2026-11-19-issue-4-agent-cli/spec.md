# #4 工作区、终端与历史会话

用户在某个 pane 点“右分栏”，应能在它右侧打开选定的本机 CLI。离开工作区再回来，仍能找到刚才的进程。任务发起的 CLI 也应出现在所属工作区，可从原任务直接前往。

本规格承接 [Issue 全文及验收矩阵](source.md) §0–17。快照更新于 2026-11-17，无评论。用户已确定 herdr-app 的工作区与生命周期语义、ORCA 的新建与历史交互、沿用 Huhu 设计系统和无兼容切换。下表说明可观察结果。完整对照和取证分工见 [实施计划](plan.md)，当前实现、拟议接口和待决选择见 [设计](design.md)。

## 启动、断线与持久化

- 设置预览、手动新建、恢复和 #5 的派遣共用 resolver。显式 cwd 错误时返回目录错误；交互新建继承焦点 pane 实时 cwd，继承失败仅按上游规则退回机器 HOME，并显示最终目录。已冻结的任务目录不随焦点或 Space 编辑变化。
- 检测分别呈现停用、未找到、已发现但版本未验证、可尝试、启动中、运行及具体失败阶段。至少覆盖 shell、Claude Code、Codex、Pi。检查 GUI 与登录 shell 的 PATH、shim/解释器、Windows 脚本、空格/Unicode、参数边界。原生登录交给 CLI。交互退出留在 shell，需要结束的非交互轮次由 Agent CLI 提供同一执行底座。
- 回执区分建立本地记录、进程创建、attach 可见、Agent 受理和业务结果。run 响应丢失先按原身份对账，查不到权威状态时显示 pending/unknown。传输中断只使视图失联。Core keep 恢复为新 shell 时显示原 Agent 丢失，既不重放 argv，也不向替代 shell 发送旧任务。
- 每台机器在隔离 Core 内维护 Huhu 专用的单一结构文档。布局版本冲突时读取已接受版本。文档不可读、损坏、超限或只读时保留确证快照，结构写入失败对用户可见。切 Vault 或重连后的旧事件不得写入新视图。窗口退出时区分已保存、提交在途和失败。
- 受控环境由 Agent CLI 或规则所属模块管理，模块自己的秘密使用 #9 的本机加密边界，普通配置可读、秘密只能看到配置状态。原生登录及所属模块的设置独立于 Safe，删除 shell 的 envRefs/secretUse 供应链。只有受权执行路径可以注入秘密。布局、回执、诊断、导出、重启记录的清理以假秘密实测。统一工具入口和外露权限遵循 [#6 规格](../feature_2026-11-19-issue-6-unified-tools-web/spec.md)。干净安装的 MCP/CLI 工具默认全关；须逐项或明确批量开启。

## 历史、文件与完整界面

| 场景 | 验收结果 | Issue #4 |
| --- | --- | --- |
| 跨当前/其他工作区搜索，同名原生 ID 来自不同机器，快速切换范围 | 按机器、来源、provider、原生引用、规范化目录判归属，覆盖重叠根、子目录、大小写、符号链接、目录消失。范围、过滤、分组、排序、pin、虚拟分页、截断、扫描进度、错误和键盘选择明确。迟到查询不串页，总数与已加载量分开。 | §10，D01、D05–07 |
| 点击活跃、已结束、只能预览或记录损坏的历史行 | 活跃项定位原会话或按权限 peek/observe。恢复和 fork 分别检验 provider 能力、确切原生 ID 或 transcript 路径、cwd 与目标代次，以同一操作身份创建并登记绑定。Pi 单独查证。无资格时给原因；预览、取消固定和移除视图均无进程或原生文件副作用。若提供删除，明确文件范围及确认。 | §10，D02–08 |
| 在窄窗展开 Files/Changes、创建/打开 worktree、打开文件、发送评审 | 左侧 Spaces/Agents、顶栏 Tabs、pane header、中部终端、辅助面板和状态区按 app 布局关系工作。目录取当前工作区，经 Engine 授权进入现有文件/评审入口；短暂 Git 探测失败保留已知归属。评审对准原会话并参加输入仲裁。布局借鉴上游，字体、间距、颜色及控件遵从 Huhu。 | §3、11、13，E01–02、F01 |
| 外接显示器、四套主题明暗、compact、reduced-motion、100/125/150/200% 缩放，快速输出同时调整分栏 | 无双滚动、截断输入行或固定高度留白。稳定 viewer 在可见、字体/尺寸就绪后 fit。TUI、切屏、光标、宽字符、组合输入、复制粘贴、鼠标、查找、链接和快捷键可实际操作。重连只绘一次首屏；多次切换、退出后订阅和资源数量回落。 | §8、11，C06–09、E03–08 |

新格式备份恢复在全新测试 Vault 验证；布局是否随包由设计末节记录，真实旧数据保全。完整验收还覆盖真实包、来源许可、跨 Vault、SSH 共用 viewer 和无兼容清理（§12–17、F01–06）。应用级多窗口、任意 GPUI mod 运行时和 ORCA 原生聊天等独立产品维持来源约定的范围；远程 Agent 只按宿主的实际能力呈现。本 change 的交互稿供按场景走查，用户确认的版本与范围以[原型确认记录](prototype-review.md)为准。
