# B06 取证：rc.4 上的“鼠标选区 / 上下行光标”复现（2026-11-18）

**结论：未能复现。** 在 rc.4（`9132640`，CM6 实时预览编辑器）上，用真实 Electron（xvfb + Playwright）驱动鼠标与键盘，没有观察到“方向反了 / 原地不动 / 大幅跨行 / 锚点漂移”这类明显异常。用户描述的具体手势与文档未知，所以**这不能证明问题不存在**，B06 保持开放。

## 方法

`selection-probe.mjs`：同一份探针对 rc.4（`.cm-content`）与当前 HEAD 的新编辑器（`.ProseMirror`）运行。文档：标题 + 9 个会折行的中英混排段落（含加粗 / 行内代码 / 双链）+ 列表 + 代码块。预言机用浏览器自己的 `caretRangeFromPoint`，不读编辑器内部状态：

| 编号 | 场景 | 判据 |
| --- | --- | --- |
| S1 | 段内拖选 ×6 | 选区文本 == 预言机在 mousedown/mouseup 坐标算出的 Range 文本 |
| S2 | ArrowDown ×14 | 字符偏移单调不减、位移 ≤ 2.5 行高 + 40 px、非末行不原地不动 |
| S3 | ArrowUp ×14 | 同上，方向相反 |
| S4 | Shift+ArrowDown ×8 | 选区只增不减、锚点不动 |
| S5 | 跨段落拖选（第 3 段 → 第 5 段） | 选区文本 == 预言机文本 |

## 结果（原始数据：`rc4-result.json`、`new-result.json`）

| 场景 | rc.4（CM6） | 新编辑器（ProseMirror） |
| --- | --- | --- |
| S1 段内拖选 | 0 / 6 不一致 | 1 / 6 不一致（差 1 个字符，在汉字边界） |
| S2 ArrowDown | 0 异常 | 0 异常 |
| S3 ArrowUp | 1 异常（首次 ArrowUp 偏移 −59 字符但纵向 190 px，发生在代码块 / 列表区，疑为该区域行高不同，探针按统一行高判定） | 0 异常 |
| S4 Shift+↓ | 0 异常 | 0 异常 |
| S5 跨段落拖选 | 不一致（差 4 个字符） | 不一致（差 4 个字符） |

## 解读（推断，明确标注）

- 两个编辑器在 S5 上与预言机的差异相同（4 个字符），说明差异来自预言机与编辑器各自命中测试在行边界处的取整 / 隐藏标记（`**`、`[[ ]]`）处理，不是新编辑器引入的问题。S1 的 1 字符差异在汉字中点边界，量级相同。
- 合成鼠标事件不等于真实硬件鼠标：触控板惯性滚动、拖选时自动滚动、真实输入法候选窗口、HiDPI 缩放都没覆盖。
- 因此：**没有复现；也没有证据表明新编辑器更差**。B06 不关闭，真机手势验证登记为“未验证”。
