# #6 统一工具与 Web 工作台 · 行为规格

用户在一处选择哪些操作向外部开放，然后可以用 CLI、两种 MCP 传输或外部 API 完成获准的业务。桌面开启 Web 后，普通浏览器可直接进入当前 Vault。以下均为目标行为。原始需求、固定提交和空评论记录见[来源快照](source.md)，本次开发以当前 Huhu 检出与本地上游默认分支快照为准，固定引用仅供追溯。当前实现及拟议接口见[设计](design.md)，验收编号沿用来源 §12。

## 同一批选择怎样生效

**首次策略（Q6-1 已定）。** 干净安装时，当前目录中全部 MCP/CLI 工具均关闭，包括常规只读项。桌面仍可管理策略，管理目录显示全部描述；外部工具发现结果为空。只有用户逐项或对明确的 ID 集合批量开启才产生授权。后续新装能力显示未配置且同样关闭。

搜索 ID、标题或说明，可同时按插件、scope、risk、选择和可用性过滤。同一维度多选取并集，不同维度取交集。选中行、整组、全部匹配和全目录分别显示目标数量，组有部分选中态。筛选和跨页选择以匹配的 ID 集合为准。将虚拟列表滚出视窗不改变选择。MCP、CLI 和服务设置都能进入同一权限页。

“启用全部只读”添加所有 read，包含 high。“仅保留常规只读”将当前全目录替换为 read 且 normal 的集合。“开启插件全部”“开启／关闭筛选结果”“全部开启／关闭”均先显示涉及数量、插件、类型及风险，再提交明确 ID。提交期间目录变化须让用户看到新的目标差异。非法 ID、陈旧版本、重复且冲突的目标或落盘失败，整批维持原状态。两端同时编辑时后提交者可重新加载、核对再提交。服务重启仍能区分已关闭与新出现的未配置项。配置损坏时显示错误并阻止依赖该策略的外部调用。[B01–B05](source.md)

撤销选择后，缓存旧名字的调用也按新策略判定。已经接受的运行保留，继续读取、写入流时重新判定。诊断入口使用真实入口上下文，可单独解释插件停用、handler 缺失、入口关闭、未授权、业务条件未满足；点“检查”没有业务副作用。

验收以“用户动作→领域 handler 或流→真实入口→可观察结果”逐项盘点。对已有记录同时检查新入口编辑后桌面和 Web 自动刷新，以及版本冲突时原记录仍可读取。插件内部依赖不会要求用户开放一串底层工具。

## 桌面分享当前工作台

1. 初始 Web 关闭。首次开启默认选择局域网，也可只绑定本机。桌面从监听成功结果展示本机 URL、可用网卡的 LAN URL 和实际端口，IPv6 使用方括号。自动端口显示分配值，指定端口失败显示原因。多网卡标识接口，无可用 LAN 地址时只提供有效地址。每条地址可以打开、复制。
2. **局域网邀请（Q6-2 已定）。** 邀请绑定本次服务与 Vault，可重复打开。桌面显示每份邀请的状态，可重取有效链接或独立撤销。撤销后旧链接立即失效，通过它建立的所有浏览器会话及活动流立即断开。其他有效邀请的会话、桌面、CLI 和 MCP 继续可用。重新邀请得到新链接。关闭服务或更换 Vault 时，该服务代次的全部邀请和旧会话均失效。
3. 第二台设备打开链接后进入已认证工作台，共用当前 Engine、Vault、handler、事件及终端服务。控制 listener 与 MCP 保持回环。Web listener 提供打包静态资源、同源 API、事件/终端流与文件传输。刷新深链返回相应界面，缺资源有明确失败。
4. 在 LAN 浏览器创建任务、修改笔记、上传本机所选文件，再由桌面查看。浏览器从当前来源获取启动信息，在普通 HTTP 也有复制和操作 ID 的可用路径。下载发生在选择的设备。窗口管理和系统文件对话框由实际宿主呈现。
5. 浏览器刷新时重取会话快照。Web 停止后旧浏览器连接失效，原 Engine、CLI、MCP 和已接收的任务继续。换 Vault、重启或网卡变化后更新真实状态与链接，旧页面的变更被拒绝并引导重新连接。[E01–E07](source.md)
