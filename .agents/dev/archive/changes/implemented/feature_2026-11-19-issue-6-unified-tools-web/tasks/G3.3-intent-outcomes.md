## 验收

使用独立测试 Vault。记录所用入口、身份、操作前后版本或状态以及失败实得。

1. 对合成创建保持同 key 重发，查询到同一 operationId、一次写入；不同用户或 Vault 不共享重试结果。
2. 同 key 改输入须报冲突；完成后模拟响应丢失或输出不符合 schema，通过句柄对账，未证实时显示 unknown，无二次创建。

## 原型对照与确认范围

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「最近活动」对照「浏览器工作台／操作记录」。活动列表提供结果呈现参考，响应丢失与幂等按接口夹具另验。本片验证领域或接口结果，该场景用于对照结果在工作台的解释。可见效果的确认以[原型确认记录](../prototype-review.md)为准；后端合同可独立验证。

## Windows 首个接入能力

`tasks.create` 接受显式意图。CLI 用 `--intent-key`，HTTP 用请求体的 `intentKey`，MCP 两种传输用 `_meta["huhu.dev/intent-key"]`。调用者保存原键，已获得回执时可按操作 ID 查询。CLI 有 `operation` 命令，HTTP 有 `GET /api/v1/operations`，MCP 可读取 `huhu://operations/{operationId}`。重复提交前重新核对权限。

同一 Vault 的实际 CLI 与两个 MCP 入口复用原意图，重启后回到原结果。同键改输入冲突，其他调用者读不到原回执。测试预写受理记录后重启，结果保持待核实，执行器调用数为零。副作用后产生错误格式的合成输出时，只保留待核实回执，重交不执行第二次。相关类型检查和 37 项 CLI、Dispatcher 测试通过。现有模块专用派遣、答复或凭据操作沿用各自回执。 [CLI 实验](../../../../../../../apps/cli/test/cli.test.ts) · [Dispatcher 边界](../../../../../../../packages/kernel/test/dispatcher.test.ts)
