## 验收

使用独立测试 Vault。记录所用入口、身份、操作前后版本或状态以及失败实得。

1. 用含 high/read 与 normal/write 的夹具比较添加只读、仅保留常规只读、插件全部、启停匹配集及全目录；提交后逐项核对差集。
2. 预览后另一端改策略或目录删项，保留草稿、展示差异并可重算；取消预览不写入，不隐式启用插件。

## 原型对照与确认范围

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「工具目录」对照「批量策略／只读添加、常规只读替换、全部与冲突」。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。

## Windows 验证

Windows Electron 经固定版 pnpm 和 Playwright 运行打包应用入口。逐项预览按 Escape 后策略仍为版本 0，焦点回到原开关。两个工具在不同搜索结果中各自选中，随后在同一预览显示。模拟另一管理操作先保存后，旧预览被拒绝并保留两个明确目标。刷新预览并确认后，两项在版本 2 一并保存。风险、插件、访问范围及当前选择取自 Engine 的预览。其它筛选维度、设置间入口和批量预设的逐项走查见后续验收。 [桌面用例](../../../../../../../tests/e2e/workflows/acceptance.spec.ts)
