## 验收

使用独立测试 Vault。记录所用入口、身份、操作前后版本或状态以及失败实得。

1. 两个会话读同一 revision；A 改两项只增一版且只发一次更新，B 提交旧版收到当前版本。同 key 重试 A 可查同一结果。
2. 混入已删除 ID、相互冲突的重复项或模拟落盘失败，重读磁盘与内存均为旧快照；失败不会发成功事件。

## 原型对照与确认范围

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「工具目录」对照「批量策略／提交成功、冲突与重载」。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。

## Windows 验证

以固定版 pnpm 运行真实 Engine 的 HTTP 测试。两份预览读到版本 0。首个提交使两项选择一并生效，版本升为 1，只通知一次。同键重交读回相同结果；另一份预览提交时收到版本冲突。混入内部 Agent 执行项、冲突的重复选择、模拟落盘失败及目录新增工具，均保留原文件和版本。关闭两项后，外部令牌的目录恢复为空。 [测试](../../../../../../../apps/engine/test/tool-access.test.ts)
