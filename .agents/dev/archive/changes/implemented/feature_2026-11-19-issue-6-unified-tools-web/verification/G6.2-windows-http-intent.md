# G6.2 普通 HTTP 请求身份

`bd65012` 令统一的 Workbench `EngineClient` 在安全上下文沿用 `randomUUID`，在 `randomUUID` 不可用的普通 HTTP 使用 Web Crypto `getRandomValues` 生成请求 ID。独立 HTTP 请求仍有不同 requestId，同一业务写入重交可明确复用原 `idempotencyKey`。桌面工作台的启动查询、任务提醒和 Agent CLI 请求入口使用同一生成方式。 [Web Cryptography Level 2](https://www.w3.org/TR/webcrypto/#crypto-interface)

Windows Edge 157.0.4341.60 从映射到本机回环的普通 HTTP 夹具打开实际打包的 EngineClient 模块。`isSecureContext=false`，`crypto.randomUUID` 为 `undefined`。测试服务实际收到三次调用，两次重交的写入键相同、三个请求 ID 不同，普通读取没有写入幂等键。`t7n` 退出 0，录制脚本在原工作区 `temp/issue-baseline/web-intent-edge.cjs`。Workbench 命令 `node node_modules/vitest/vitest.mjs run packages/workbench/test/engine-client.test.ts --maxWorkers 1` 的 `t77` 为 10 项通过。

该证据覆盖请求与写入意图身份。打包后的完整浏览器工作台、深链、同源认证、普通 HTTP 复制和多设备需要相应入口与邀请流程。
