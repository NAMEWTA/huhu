# 模型与协作规则

## Herdr 团队分工

用户明确选用本组时，应用于当前任务及其接续。开始新任务时重新按用户选择启用。

用户启动并直接交互的会话是主会话，沿用启动时的模型与推理级别。主会话明确目标和验收条件，通过 Herdr 派遣任务，收集结果，并负责最终审核和交付。收到派遣的会话只负责本次分工，完成后向主会话回报。

| 角色   | 派遣时机与产出                                    | Codex 模型        | 推理级别    |
| ---- | ------------------------------------------ | --------------- | ------- |
| 疑难分析 | 根因难以确定、已有两次尝试反复失败，或架构与接口有重大取舍时，给出证据、判断和建议。 | `gpt-6.2-astra` | `high`  |
| 具体实现 | 目标和改动范围明确后，完成实现与相关验证，回报改动和验证结果。            | `gpt-6.2-sol`   | `high`  |
| 独立审查 | 实现完成并有可审查的版本后，核对改动、验收条件和验证证据，报告问题位置和影响。    | `gpt-6.2-sol`   | `xhigh` |

### 通过 Herdr 派遣与验收

1. 按用户明确选用的 Herdr 入口启动，以上角色、模型和推理级别适用于两个入口。
   - Herdr TUI 读取 [system-herdr](../../skills/system-herdr/SKILL.md)，确认 `HERDR_ENV=1`。将表中的模型和推理级别作为 Codex 参数，放在 `herdr agent start` 的 `--` 之后。
   - Herdr Core 读取 [system-herdr-core](../../skills/system-herdr-core/SKILL.md)，运行 `hc --skill` 并核对本机的 `hc run --help`。使用 `hc run --bg --json --name <唯一名称> --cwd <工作目录> -- codex --no-daemon -m <模型> -c model_reasoning_effort=<级别>`，用返回的完整 `address` 投递和收件。需要持久派发时按 Core 文件协议维护 task 和 report。主会话可从 Core 外部读报告。
2. 给每个会话提供目标、相关文件或证据、工作目录、可写范围和验收条件。疑难分析与独立审查只读业务文件。并行实现时分配互不重叠的写入范围。审查时确认审查会话能读到实际待交付的改动，包括任务新增的文件。
3. 主会话读取派遣结果，核对实际改动与验证证据。需要修复时交回实现会话，修复后复核受影响的内容。由主会话根据验收条件作最终判断。

Herdr 或指定模型不可用时，主会话说明受影响的分工和原因，并继续推进其余可做的工作。交付时如实说明实际派遣和审查情况。

2026-11-18 已对照本地 Codex 模型目录核对表中的模型与推理级别。各批次实际角色、终端与派遣结果由主会话在该批次的协作记录核验。
