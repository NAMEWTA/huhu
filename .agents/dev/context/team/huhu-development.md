# 模型角色分工

本表是项目默认路由，仅在任务需要相应角色时使用；本次明确指定的模型或推理级别优先。主会话沿用启动时的模型与推理级别。

| 角色 | 负责事项 | CLI | 模型 | 推理级别 |
| --- | --- | --- | --- | --- |
| 架构、疑难分析与顾问 | 设计架构与接口，比较关键方案，分析复杂根因，并给出证据和建议。此角色只分析，不实施。 | Codex | `gpt-6.2-astra` | `high` |
| 非前端实现与修复 | 编写和修改非前端代码，落实功能、重构和 Bug 修复，维护相关测试用例。 | Codex | `gpt-6.2-sol` | `xhigh` |
| 前端实现与修复 | 实现和修复 Electron 渲染进程、Web 端及两端共享的前端代码，维护相关测试用例。 | Claude Code | `claude-opus-5-5` | `medium` |
| 审查、测试与调查 | 检查改动、运行获准的测试并报告结果；搜索、梳理和探索代码库，调查现有行为并定位相关代码。 | Codex | `gpt-6.2-sol` | `medium` |

**同一个 Bug 经两次修复尝试，复现或回归检查仍确认问题存在时，暂停实现。第三次动手前必须请教顾问。** 提供复现步骤、两次尝试的假设与改动、验证结果。顾问指出最可能的根因、证据和下一步验证建议，不改代码、不改测试、不提交补丁。拿到建议后，由对应的实现角色继续修复；如果顾问不可用，记录阻塞，不做第三次猜测性修改。

跨前后端任务按改动所在层分别选实现角色。前端模型不可用时，报告受影响的范围，不静默替换模型。
