# 样式分层与大规模样式重构的陷阱

> 来源：`2026-11-14-design-system-completion`。每条都是被验证抓出来的真实错误。

1. **层序先于特异性。** `@layer` 里后面的层即使特异性更低也赢；不分层的普通声明又压过所有分层声明。把规则分进更高的层，会让原本靠特异性赢的规则输掉。**分层必须一步一步做，每步与冻结基线比对零差异**；一次按文件分三层会产生上千组翻转。
2. **运行时注入的第三方样式没有层。** CodeMirror（style-mod）、sonner（`__insertCSS`）在运行时注入无层样式，覆盖它们的规则放进层里会全部失效；编辑器内容里的装饰类（如 `.huhu-md-semibold`）也和 CodeMirror 的 `ͼN` 类竞争。这类规则放“不分层白名单”（只允许第三方选择器）。
3. **去掉 `!important` 不是无害的。** 它常常压的是内联样式（`.hu-primary-nav` 的 width 来自 AppShell 的 `style`）或更高特异性的 `button` 规则；去掉后要提高被覆盖规则的特异性或保留带说明的例外。
4. **改名会撞名。** `btn` → `hu-btn` 与 `base.css` 里已有的 `.hu-btn` 合并，按钮只在悬停 / 聚焦 / 按下状态变样。生成映射前要把**所有**样式文件（含 base / tokens）的类都算作已存在。
5. **脚本改字符串别 `trim()`。** 去掉无定义类名时顺手 trim，把 `" active"` 的前导空格吃掉，`agent-layout` 与 `agent-history-open` 粘成一个类。只在 class 上下文里按 token 改，并保留首尾空白。
6. **静态“无用”判定要用 AST。** 用正则从源码抽引号配对的字符串会错位漏掉 token，把仍在用的规则当死代码删（一次误删 1,529 条，AST 后只有 378 条）。
7. **局部回归会骗人。** 只跑部分屏幕会让标签栏等全局状态不同，产生海量假差异；验证必须全量。
8. **验证工具自己也要被验证。** 往页面注入已知差异（padding 1px、后代 hover、`:focus-within`、box-shadow），确认能被报出；这次就靠它发现伪元素属性互相覆盖会漏报。
9. **计算样式快照要避开类名与 testid 做键**（标签 + 结构序号 + role / aria），否则改名与新增 testid 都会让基线失配。
10. **合并重复选择器时简写与长写是同一个冲突。** `overflow`（简写）与 `overflow-y`（长写）按“属性名相同”判断会漏掉冲突，窄屏下滚动行为变了；要按“属性根”判断，合并后还要删掉同块里被覆盖的重复属性。
11. **拆文件也要证明顺序无关。** 凭直觉按组件拆 `core.css` 产生 354 处计算样式差异；改用“同层、同特异性、可能重叠、同属性族”建图，强连通分量不拆，才等价。拆分脚本会丢掉 `/* stylelint-disable … */` 注释，拆完要重跑 `pnpm lint`。
12. **覆盖率 API 只返回“用过”的规则。** `CSS.stopRuleUsageTracking` 的结果里 `used` 永远是 true；没出现的才是未用，要自己枚举样式表规则再相减，否则会得出“0 条未用”的假结论。覆盖率为 0 只是线索，固定 Vault 没走到的界面（启动页、SSH、自动化、评审树）必然为 0。
13. **页面里的构建哈希会让像素比对失败。** `settings-about` 显示构建提交哈希，每次提交后与旧基线都差几百像素，计算样式却为 0 差异；遇到这种先看 diff 图是不是内容文字，再决定是不是样式回归。
