## 数据与体验边界

- 同一计划从来源页和中心打开时有相同的身份与版本。过期修改须提示冲突。暂停或删除后，未受理或尚可取消的动作停止，发送状态未知的动作先按原发生核实。若核实为未发，旧计划不得重新认领。已发动作和已受理任务沿原身份收尾，答复、停止、签名 ACK 和资源释放仍可定位。全局暂停保留管理入口，停用 Automations 插件注销其能力。手动执行使用独立发生并保留原排期。
- 已确认写入与磁盘、回执对应；并发改写或进程中断后保留可恢复现场。账本转账、补期及恢复具有一致读边界。固定收支补齐启用区间的每个漏期，贷款补记先预览再确认。产品允许更换旧合同，已有笔记、批注、流水、配置与运行历史需按原单保全。
- Task 回答绑定实际用户、来源对象、问题和版本。执行终止、业务结果、人工关闭和外发分别可查。真实 GitHub 回传丢失响应时，查证原发送。工具目录与调用均核实当前授权。
- Huhu 向外提供稳定的 Streamable HTTP `/mcp`，普通 CLI 延续 Engine discovery。外部 stdio、HTTP 与 SSE 由 MCP 来源插件在 Engine 内连接。恢复会话的新外部 `tools/call` 在发送前拒绝，建立有效新会话并重新授权后才能调用。内置能力延续 Dispatcher 校验及回执，外部内容保留原生 MCP 结果。服务关闭后仍可配置和显式短时检查，停用管理插件则注销其能力。
- C3 先用现有规则和 FollowUps 贯通一次真实执行，C7 再替换投影和验证规模。中心的字段、状态与错误样例可先确认，真实接线分别等待所用计划及效果查询。界面、业务计划和常驻 Engine 各用自己的生命周期取证。
- #14 的 U0 按现场图建立复现基线。新布局或交互在本页/状态取得实际确认后落地；原型条件只约束依赖该决定的可见实现。SSH 已确认版本为 `0a890ec3a9f26bbedc304f7b61e9cb41975d8b48df4ca2a96a33ee05fb473d2b`。主机编辑/导入看 hostDialog、auxiliaryView，首次信任及变更看 verify，传输冲突看 conflictDialog。其余演示状态按原票核对。[SSH 确认与源码定位](../2026-11-19-issue-7-ssh-module/prototype-review.md)
- #15 §12 的迁移清单及各领域回退条件随同真实消费者验证。迁移中断后读者只看到完整状态或可处理的失败；已发送或身份未核实的效果保留原回执。跨平台、独立 Web、异机 CI 与真实 provider 分别记录实际覆盖。
