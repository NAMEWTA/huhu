## 分工与决定

1. **先固定持久化和主体语义。** #13 W1/W2 的版本、操作身份、取消、未知回执与授权是 Notes、Inbox、MCP 和任务来源共用的前置产物。#14 U0 现场复现、#17 终态归属、#7 快照核对与 #11 领域建模可以同时准备。共享文件由父单指定的一方集成。
2. **按可消费的接口解锁联调。** #13 提供唯一可写计划，#16 负责中心的计划编辑和运行追踪，各来源页按同一对象与修订提交。SSH 保留采样事实、账本保留期次和金额。暂停或删除计划后重启应停止后续动作，已受理工作仍能回答、停止和释放资源。
3. **分清协议方向。** #14 负责标准客户端到 Huhu 的稳定 HTTP；#12 负责 Huhu 到外部服务的三种上游协议。普通 CLI 保留。#17 的受控工具另验证任务级授权。交互 Agent、异机 CI 和受控 Task 各自留证。
4. **规格与确认。** 上述重叠均可由 #15 和子单的职责表裁决，未发现需要合并或另建的重复 Issue。UI 确认按具体版本和覆盖状态复用；#7 已有确认范围，新工作台、账本及自动化中心的新增交互仍需对应原型走查。#14 现场缺失的安装包 SHA、缩放、日志是调查资料；现有信息足以开始定位。
5. **验收终点。** 单项沿原 Issue 验收；整批在同一 SHA/制品跑 J01–J22，分别记录 Linux、Windows、macOS、独立 Web、真实 provider 和远端客户端的实际覆盖。本轮产物为读取、分诊与规格差异，GitHub 上的 Issue、PR 和产品代码均未由本任务修改。
