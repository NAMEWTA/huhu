# F31 · 将 Agent 状态观察迁入计划

[#13 原单](https://github.com/NAMEWTA/huhu/issues/13) · [本次完整快照](../../../../../temp/dev/2026-11-24-issue-inventory/integration/20261124T094741Z/13.md) · W5c / F31 / P2 · [批次规格](../spec.md)

## 交付

未来时间触发、重复提醒、用户状态查询/推送和等待后建人任务等策略统一归 Automations。Agent 提供已核验状态事实，Tasks 提供一次核对/派遣/回执领域动作；自动化负责何时观察、什么条件通知、是否重复、何时停止。复用事件、快照和共享活动投影，普通页面读取不再顺便启动另一轮后台业务查询。禁止 Tasks/Agent 各自再实现一套周期策略或通知去重账本。来自业务计划的提醒/观察效果由 Automations 记录；#17 的原请求结果回到来源及其交付回执由 Tasks/Agent 负责。这是两类目的不同的效果，共用持久操作及原身份核实语义，一次效果只有一个写入者。

现有入口为 [plugins/agent-cli/src/engine/sessions.ts](../../../../../plugins/agent-cli/src/engine/sessions.ts)。
