# F28 · 将任务提醒迁入同一计划

[#13 原单](https://github.com/NAMEWTA/huhu/issues/13) · [本次完整快照](../../../../../temp/dev/2026-11-24-issue-inventory/integration/20261124T094741Z/13.md) · W5b / F28 / P2 · [批次规格](../spec.md)

## 交付

一次性提醒与周期提醒共用 Automations 的计划、发生身份和可靠投递设施；任务详情只是同一计划的快捷入口。删除 Tasks 私有提醒轮询及第二份可写调度字段，不保留“自动化不可用时 Tasks 自行计时”的兜底。复用现有 [ReminderDeliveries](https://github.com/NAMEWTA/huhu/blob/eaf19473fdb8a5180cadde8b595904ed5a49cddc/plugins/automations/src/engine/reminder-deliveries.ts#L144-L215) 和固定通知 ID，补齐修订失效、取消和副作用提交边界；不能仅把原来的 30 秒循环搬进另一个文件。

现有入口为 [plugins/tasks/src/engine/index.ts](../../../../../plugins/tasks/src/engine/index.ts)。

## 前置产物

- [F29](062-f29.md) 统一 Cron 和 FollowUps 的计划目录。

## 验收

- [ ] 一次性、周期提醒在自动化中心和任务详情显示相同 plan ID/revision；在已选中但尚未提交时改期、暂停、删除，旧候选不能通知或污染新计划。每个持久化/通知边界中断后重启，按原发生身份核实：确知未送达且计划仍有效才可补送；已确认送达不重复；无法分辨则显示待核实，不静默标记成功或盲重发。任务删除、关闭、恢复、复制、只读 Vault 的关联计划策略明确，编辑其他任务字段不得恢复已删除提醒。
