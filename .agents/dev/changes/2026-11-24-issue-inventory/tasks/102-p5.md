# P5 · 连接恢复、停用回收与会话一致性

[#12 原单](https://github.com/NAMEWTA/huhu/issues/12) · [本次完整快照](../../../../../temp/dev/2026-11-24-issue-inventory/integration/20261124T094741Z/12.md) · §8 P5；§9 · [批次规格](../spec.md)

## 交付

完成共享连接的首次并发合并、有限退避、手动恢复、stderr 脱敏及连接/发现/调用各自预算。

关闭 MCP 服务只回收发布/长连接子作用域，配置控制面仍可工作，显式检查按独立短期作用域回收；真正停用管理插件、切 Vault 或退出时释放全部 handler 与资源。显式停用后的重新启用不自动发布，旧恢复/发现/登录回调不能复活来源。

与现有 `McpSessions`、撤销令牌、取消及恢复机制衔接，维护原内置持久意图回归；外部发送后未知结果不自动重放。

扩展共同审计与必要脱敏诊断，检查直接循环配置和故障来源隔离。

现有入口为 [packages/kernel/src/mcp.ts](../../../../../packages/kernel/src/mcp.ts)。

## 验收

- [ ] 演示： 并发客户端仅产生一个同配置 stdio 进程；杀死/卡住一来源时内置及其他来源可用；关闭后无遗留进程和定时重启。证据： A8/A9 的进程计数、取消/恢复/撤销与回归输出。
- [ ] A8 回收与故障隔离 · 至少 10 个并发同配置会话只创建一个长期 stdio 上游。杀死或卡住其中一个来源，其余和内置工具继续运行；恢复不重放已发调用。关闭服务时发布子作用域与已有检查回收，之后显式检查不改变开关且结束即退出；真正停用插件、删除、切 Vault、退出时回收对应全部资源，无孤儿进程/连接/恢复计时器，显式停用后的重新启用不自动发布。
- [ ] A9 主体与未知结果 · 撤销一个入站令牌、关闭会话或切 Vault 后，缓存路由不得继续到上游；另一有效身份仍按自身授权工作。取消在发送前不增加上游计数；发送后断连/超时显示未知结果并且重连不自动再发。恢复会话尝试新的外部 tools/call，即使夹具标注 readOnlyHint=true，也必须在到达上游前拒绝；建立不携恢复凭据的新有效会话并重新鉴权后才能调用。当前内置 mcp-recovery 和持久意图回执回归通过。
