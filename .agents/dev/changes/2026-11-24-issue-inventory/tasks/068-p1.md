# P1 · 添加一个 stdio 来源并从 Huhu 调用一项外部工具

[#12 原单](https://github.com/NAMEWTA/huhu/issues/12) · [本次完整快照](../../../../../temp/dev/2026-11-24-issue-inventory/integration/20261124T094741Z/12.md) · §8 P1；§9 · [批次规格](../spec.md)

## 交付

按当前 Huhu 插件规范新增来源管理插件，添加 manifest、静态能力描述符、`bindCapability` handler、Engine 注册与公开包入口。

完成最小服务管理、默认停用、显式检查、本机配置许可与单工具发布；来源定义通过 Vault 版本校验提交。

从唯一 HTTP `/mcp` 入口经同一 Engine 发现并调用一个上游工具；同一列表仍保留原内置工具。

核对真实调用方、总开关、只读与 Vault 隔离；外部调用采用原生结果类型，不能挤进内置 data 信封。

分离管理插件 Vault 作用域与发布/长连接子作用域。服务关闭仍可配置与显式短期检查；真正停用管理插件则全部 dispose，显式停用后的重新启用不自动开放服务。界面状态和动作按 §6.2 明确命名。

现有入口为 [packages/kernel/src/mcp.ts](../../../../../packages/kernel/src/mcp.ts)。
