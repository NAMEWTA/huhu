# G07 构建体积与启动

基线为 rc.4 `913264045cee1818497a37a57715c664aa85a1ae`。对照工作树保留在 `/home/wta/projects/huhu-wt-rc4`。在同一机器用 Node 26.11.1、pnpm 12.10.1、Electron 44.9.1 和 Chromium 152.0.7977.167 构建并运行。主机是 Linux 7.0.0-43-generic x64 / Intel Core i7-12700，任务可用 8 个逻辑 CPU，由 Xvfb 提供显示。

## 测量方法

`xvfb-run -a node scripts/measure-notes-startup.mjs /home/wta/projects/huhu-wt-rc4 20` 交替运行 20 对 rc.4 与候选，每次创建新 Electron profile 和同内容的独立 Vault（2,001 篇笔记）。工作台用现有冷启动用例相同的“工作台可见且引擎就绪”终点。收件箱从工作台开始切换，记录其根节点可见。首篇笔记记录文件树按下 Enter 到编辑区可编辑且能读到样本文字的时间，使用渲染器的 rAF 探针。p50 和 p95 使用 nearest rank。进程与应用 profile 冷启动，两轮均使用同机缓存条件，未刷新 OS 页缓存。

另外用 `1 --trace-modules` 独立诊断，通过 CDP 的 `Debugger.scriptParsed` 重放首屏已解析的脚本并观测后续脚本。工作台和收件箱中未出现命名的富文本编辑器、宿主路由和编辑面模块。首篇笔记打开后同一记录里出现 `rich-*`、`host-fetch-*`、`NoteEditorSurface-*` 及文件树模块。rc.4 的 CodeMirror 随首屏入口打包。诊断时序只用于判断模块加载，分位数使用未挂调试器的运行。

## task02 定因与拆分

从同一套 Electron 44.9.1 构建的主进程实际运行应用，在一次独立诊断中通过 CDP `Debugger.scriptParsed` 重放首屏脚本，并检查 `document.styleSheets` 的实际样式表。读取对应产物的字节长度。用复制到临时目录的应用，记录主进程的 `app.whenReady`、窗口创建、导航、`ready-to-show`、`did-finish-load`，并在实际 HTML 中观测首帧和工作台模块第一次出现。命令为 `xvfb-run -a node scripts/trace-notes-startup.mjs <desktop> [out] --profile-reload`。正式分位数另用原始构建测量。

| 版本 | 首屏已解析 JS | 实际载入 CSS | 主进程导航到 ready-to-show | 渲染导航到首帧 | 渲染导航到工作台出现 |
| --- | ---: | ---: | ---: | ---: | ---: |
| rc.4 9132640 | 5,108,660 B | 385,428 B | 455.4 ms | 872.0 ms | 902.5 ms |
| task01 8168981 | 3,899,089 B | 337,691 B | 407.4 ms | 672.0 ms | 697.8 ms |
| task02 整体路由试验 b12e156 | 2,833,867 B | 296,533 B | 572.9 ms | 932.0 ms | 949.3 ms |

主进程探针从脚本启动到 app ready，rc.4 为 241.6 ms，task01 为 138.0 ms，交付构建为 750.1 ms。app ready 到发起渲染导航依次为 69.6、51.1、159.2 ms。

上表各行只有一个诊断样本且宿主负载不同，分阶段耗时用于分界定位。实际加载的首屏 JS 相对 task01 减少 1,065,222 B（27.3%），CSS 减少 41,158 B（12.2%）。过去知识库贡献注册静态引用 NotesModule，又导入文件查看器和 `@huhu/editor` 的 CodeMirror 纯文本入口。task01 首屏实际解析 `w3c-keyname-*`（123,941 B）、`dist-DTrrCka6.js`（545,060 B）等依赖。首屏主入口从 1,231,560 B 降到 1,028,493 B。富文本、编辑区预载、Lingui 目录与 OK Tailwind 生成资产在 task01 就未进入工作台。当时共享样式表仍包含 OK 主题映射。整体路由试验只注册轻量知识库元数据，实际进入知识库时加载路由组件、查看器依赖及布局 CSS。OK 主题映射随富文本与文件树入口加载。试验构建在知识库挂载后仍预载编辑区。

共享 `src-CfcTBpij.js` 为 1,304,593 B，前后 hash 一致。构建源码边界显示最大组成是 xterm（约 412 kB）、workbench（约 271 kB）、TanStack Query（约 135 kB）和 Table（约 99 kB）。FileIcon 的实现和扩展名表在该共享块中，首屏没有加载 vendor 文件树模块。暖进程关闭导航缓存后重载的 CDP CPU 样本显示，整体路由试验主要脚本用时为入口 123.8 ms、共享 `src` 52.8 ms、`dist-1hTSuM8h.js` 78.6 ms、React/JSX 辅助 9.4 ms。rc.4 单入口为 307.6 ms。此 CPU 样本用于说明渲染解析/执行的构成，不能填补冷进程等待、UI 驱动或引擎等待的时长。

拆分试跑的第二轮出现了 4 次已打开知识库但文件树显示空列表。现场 UI 同时显示笔记计数 2001。文件列举回调与不断变化的菜单回调曾共用被动 effect，清理和重注册之间可能命中空列表兜底。试验构建拆开列举路由与菜单回调的生命周期。该轮 16 个有效候选样本保留作排障参考。

### 交付拆分

整体路由试验对附件展开和重开文档产生了验证失败，交付构建 `94e79ea` 将边界收窄到非 Markdown 查看器。打开纯文本、图片等附件时才加载查看器及编辑器依赖。知识库外壳、文件树注册顺序及进入知识库后的编辑面预载沿用原时序。OK 主题映射仍从两个 OK 子入口按需加载。两项相关端到端用例分别复跑三次，6/6 通过。

交付构建的首屏实际解析 JS 3,006,386 B，较 task01 减少 892,703 B（22.9%）。首屏 CSS 331,363 B，减少 6,328 B。首屏主入口 1,192,873 B，较 task01 少 38,687 B。CodeMirror 的命名块和 OK 的作用域 CSS 不在交付首屏资产中。最终阶段样本在宿主高负载下导航到 `ready-to-show` 为 1872.0 ms、导航到首帧 2344.0 ms、导航到工作台 DOM 2450.8 ms。暖进程重载探针中入口 231.8 ms、共享 `src` 168.1 ms、`dist-1hTSuM8h.js` 89.6 ms、React/JSX 辅助 31.6 ms。与前述单样本的测量条件不同，不能把绝对差值直接归给某个 JS 模块。

### 收件箱剩余差值

独立交错探针各测三次，使用 `scripts/trace-notes-startup.mjs <desktop> --profile-inbox`。Playwright 发起点击到浏览器收到 click，rc.4 与候选中位数分别为 52.2 / 39.5 ms。click 到收件箱 DOM 出现为 18.5 / 25.3 ms，增加 6.8 ms。DOM 出现到 Playwright 等待可见返回为 49.1 / 40.6 ms。候选的三个总时间为 93.8、98.1、187.3 ms。最慢一次的点击前 68.9 ms、click 到 DOM 34.7 ms、DOM 到可见返回 83.8 ms。各阶段中位数单独计算。
