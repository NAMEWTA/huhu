## task05 完整旅程切回后保存

从档案记录切回「日志」输入尾字后，原用例先等状态文字为「已保存」，随即只读一次文件。原版负载复跑在这一行读到标题 `旅程乙`、属性 `zip: 007` 和条目 `条目甲`，磁盘上还没有尾字，与 task02 和 layout task03 的失败相符。

受控慢桥使用回到「日志」后真实挂载的编辑器和保存流程。先输入并完成保存「切回后」，再输入「继续写」。探针同时观察 ProseMirror、`Y.Text('source')`、普通文件的 `notes.save` 请求和磁盘。旧断言放行时，ProseMirror 已含完整尾字，`Y.Text` 和磁盘只到「切回后」，此时尚无含完整尾字的保存请求。随后桥定时结算，DocumentSession 收到新全文并自动保存，磁盘与预期全文一致。本样本的两次保存请求相隔 3,356 ms，旧状态取样在第二次请求前 2,992 ms。延迟由探针引入，用来确认顺序。探针从输入到写完保持同一标签，全程使用真实保存请求与落盘路径。复测把前段改为通过已打开的标签切换。自然桥接的一次样本在首次读盘时也命中旧「已保存」，ProseMirror 有完整尾字，`Y.Text`、磁盘和请求都还没有。965 ms 后发出包含尾字的保存请求，第 1,933 ms 读到精确全文（以探针开始计时为基准）。另一次自然样本在首次读取前已保存，全文同样一致。
