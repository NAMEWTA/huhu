# H4.2 工作区启动 Windows 验收

使用 Windows Electron 44.9.1、临时 Vault 和仅监听 `127.0.0.1` 的 SSH 夹具。运行 `playwright test tests/e2e/workflows/ssh-workspaces.spec.ts --workers=1`。H4.1 一项和 H4.2 两项通过。SSH 的 Vitest 全组 56 项通过，插件 TypeScript 和改动源码 lint 通过。

| 场景 | 真实观察 |
| --- | --- |
| 临时启动三台主机 | 首次信任前夹具未收到密码。切离工作区再打开时取回同一主机密钥指纹。两台各自就绪，第三台拒绝密码后只有其 Pane 失败，另外两台保留独立会话和各一条连接。 |
| 真实终端与重新挂载 | 既有终端 WebSocket 收到回环 shell 的欢迎输出。可选登录命令在首个 shell 开启时发送一次，切换标签与重挂工作区保留原会话 ID。 |
| 固定模板和应用重启 | 临时运行可存为模板，启动模板获得新运行和新 shell。关闭 Electron 并从同一 Vault 重开后可回到原运行；显式重连显示代次 2，同一 Pane ID 获得新 shell。关闭运行后其绑定从列表移除。 |
| 绑定写入失败 | 临时 Vault 的 `.huhu/runtime/ssh` 被普通文件占用。Workbench 显示启动错误并保留草稿；清除夹具后回读为空运行列表、空连接审计，夹具监听器记录零连接。 |
| 失效目标 | 修改托管主机的回环端口、在夹具中移除旧目录记录，并使用已关闭的监听端口。三项分别显示身份变更、主机已移除、连接失败；原端口和新端口监听器均收到零连接。 |

参考本地 Motty `main@2daa9db582e16edf60a60b7ada26f47f808f973c` 的 `internal/workbench/workspace_launch.go`。完整运行绑定经过一次 Vault 文件原子写入后才启动独立连接。模板复用真实主机 ID，目标摘要覆盖主机、跳板顺序、账户和端口。同一会话的凭据通过原有 SSH 管理器的认证校验获取。运行绑定存放在 Vault 包排除的 runtime 目录，回读文件未见实际会话 ID、夹具密码或终端输出。

重启以显式重连取得新代次。关闭运行关闭所属 Shell，共享连接仍由原 SSH 连接管理器管理。H4.3 的换窗、运行中拖动和单分栏资源回收由下一切片验收。
