## 领域入口

| 静态能力 | scope / risk | 实际依据 |
| --- | --- | --- |
| `ssh.resources.host.get` | read / normal | 用已保存主机 ID 读取可移植主机与逐跳摘要。输出精确字段含目标 ID、地址和端口、认证类型、配置修订与路由修订。 |
| `ssh.resources.connection.start` | execute / high | 按目标 ID 和路由修订开始独立核验。沿用 SSH 逐跳、模块认证租约和原指纹校验。连接确认后回收，不注册为可用工作台 Shell、SFTP 或执行连接。 |
| `ssh.resources.connection.get` | read / normal | 读取本主体、指定目标和尝试 ID 绑定的现有核验与指纹待答。 |
| `ssh.resources.connection.list` | read / normal | 列出本主体的近期核验与待答，便于重取丢失的响应。 |
| `ssh.resources.trust.decide` | execute / high | 复核目标、路由修订、尝试、跳点、指纹与提示修订。接受仅用于本次核验，拒绝结束尝试。指纹变化继续由桌面专用流程核实。 |

五项均默认关闭，由当前 Gateway 工具选择独立开启。描述随现有 `sshCapabilityDescriptors` 在启用前登记，停用后保留管理目录说明。已授权读取从可移植定义和现有内存资源出发，甲和乙的 HTTP token 为不同主体。CLI 与 MCP 按当前认证主体工作。

## Windows 实得

- 主机与路线摘要通过桌面、Engine、实际 CLI、MCP stdio 及 MCP Streamable HTTP 的工具读取得到一致结果。工作台示例保持脱敏。读取时 `ModuleCredentials.list/use` 均未调用，两个回环服务均未接受拨号。
- Safe 停用的引擎案例使用模块自身合成密码成功核验。密码只在原连接的指纹获准后发送给服务器。核验后服务器观察到连接关闭，已知主机表为空。
- 同主体同路线的同时核验复用尝试。另一令牌和另一个入口不能访问原尝试或回执。已消费提示、错误目标与跳点、提示修订变化均拒绝。工具撤权返回 `CAPABILITY_NOT_EXPOSED`，HTTP token 撤销返回 401。
- 同一目标第二跳等待时变更跳板修订，旧答复返回 `VERSION_CONFLICT`，目标未收到密码。实际更换同一回环地址的指纹时，外部答复无法进入 changed-key 的专用核实路径，旧记录及线路认证保持预期。
- 工作台原有本机和回环 Web 指纹流程、专用已知主机管理，以及 SSH 停用后的目录行为由原用例复验。

首轮组合出现 Windows 凭据存储错误 8，旧用例和新用例均在创建测试主机时受影响。同一命名空间的合成写入复现该错误。按本终端两轮日志确认的 12 个已退出工作进程及试验文件指纹，回收其 23 条测试凭据。受控写入和读回恢复后，依次复跑 Workbench 和 SSH 模块。新增测试夹具在退出时通过领域接口释放其保护材料。 [初次 Workbench 失败](<C:/Users/cdewta/AppData/Local/Temp/huhu-t18v-task14/initial-workbench-windows-error8.log>) · [受控清理日志](<C:/Users/cdewta/AppData/Local/Temp/huhu-t18v-task14/owned-test-key-cleanup.log>)
