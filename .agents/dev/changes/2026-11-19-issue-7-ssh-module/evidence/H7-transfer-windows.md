# H7 文件传输 Windows 验收

从已集成 H4／H6 和 promptId 状态机的 SSH 工作分支构建 Windows Electron。全部 SSH 目标为本机临时回环服务器，所有 Windows 源和目标均在测试临时 Vault 内。两个 H7 场景通过实际 Workbench 操作和 SFTP 回读取证。

| 场景 | 观察 |
| --- | --- |
| Windows ↔ SSH 文件 | 传输中心生成稳定任务号。拒绝覆盖保留原件，确认覆盖后回读本机和远端字节。等待确认时远端改写后，旧任务失败，新内容保留。返回定位原会话和文件行，清历史只移除记录。 |
| SSH ↔ SSH 流中转 | 两个真实回环 SFTP 通道复制文件。暂停后保留已有目标，继续沿用原任务和部件。验证目标前缀后取源的剩余字节，新内容在暂存校验和提交后才出现。目标权限 0640 与时间戳正确。 |
| 冲突、取消、恢复 | 前缀失配和符号链接目标保留既有文件。暂存写入挂起时取消，原目标保留且暂存清除。注入发布重命名失败，恢复原目标，随后同任务重试通过。 |
| 有界队列与连接归属 | 接纳 32 个未终结任务，额外请求说明队列满。取消释放名额，切断源连接后原任务保留可查终态。每次最多两个任务同时占用工作槽，同一连接和本机目标路径互斥。 |

先独立交付基础路径，再完成暂停、前缀续传和双回环端点。旧 SSH 单文件支持和私有身份测试由 SSH Vitest 全组回归。复跑 `playwright test tests/e2e/workflows/ssh-workspaces.spec.ts --workers=1` 及 `vitest run --no-cache --pool forks --maxWorkers 1 plugins/ssh/test`。

本切片任务按单文件入队。目录拖放、批量递归选择和目录合并待继续。任务保留在当前 Engine 生命周期；原连接丢失且无法核对清理结果时，任务显示暂存名称或待检查的备份，后续连接仍需用户显式发起。
