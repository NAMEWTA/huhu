# H1.2 Windows 执行组件取证

Windows x64 26300 用 Go 1.26.11 从本地冻结的 Motty `2daa9db582e16edf60a60b7ada26f47f808f973c` 构建 Windows/amd64 参考程序。Viva 的同级替换路径为 `../viva`，检出 `a5da67aa63440ee836c37a5aa1c70e3eb317401c`。`go version -m` 确认替换，`go list -deps ./cmd/motty` 包含 `github.com/vivaui/viva/leaks`。两份上游检出在构建后仍干净。其许可证及来源见 [H1.1](H1.1-upstream-map.md)。

- `t3z` 执行 `go build -p 2 -trimpath -o <output> ./cmd/motty`，退出 0。`motty-win32-x64.exe` 为 61718016 字节，SHA-256 `9a4c3cf29c20005d09dce125615276233bf1444207e15e0d18c7abb97e120fca`。参考程序在原工作区 `temp/issue-baseline/ssh-executor/`。
- `t4h` 在全新 `MOTTY_DATA_DIR` 启动参考程序的 `mcp-serve`。无保存主机时程序退出 1，诊断指出缺少该目录的 `config.db`。现成运行入口依赖 Motty 自身的主机配置，因此在用作 Huhu 的 SSH 执行端前须验证适配如何保持 Huhu 为主机配置和运行状态的唯一所有者。
- `t4n` 在同一检出运行 `TestServeAgentMCPOffersReadingUntilTheUserAllowsCommands`、`TestServeAgentMCPServesNoHostThatWasNotOpened`、`TestServeAgentMCPRefusesWhatItCannotReadOrRecord` 三项，进程退出 0。回环、临时配置与合成身份，未使用实际 SSH 主机或用户凭据。

此轮没有引入 Go 源码、执行组件或生产依赖，不新增上游采用项。Huhu 启动实现、缺资产与错版本的分发故障、授权主机的连接与 PTY/SFTP/转发、退出释放资源须等执行端决定和可用测试主机。Linux 和 macOS 当前未测。
