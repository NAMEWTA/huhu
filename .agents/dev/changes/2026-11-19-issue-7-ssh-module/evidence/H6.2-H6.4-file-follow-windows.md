## H6.2 SFTP 读写

- Workbench 在 960×600 打开真实回环文件属性，读回 UID 和权限，保存权限后把原字节移到另一个目录，读取 SFTP 返回的符号链接目标。服务返回拒绝时，界面显示明确错误，原字节和权限保持。
- Engine 夹具在同一修订上并发改权限，只有一次写入成功。复核属主、目录权限、同名拒绝、跨目录移动、另一主机的字节和属主隔离、关闭会话及无 SFTP 状态。权限与属主分开提交，分别按版本复核，并使用原连接的 SFTP 句柄。
- SFTP v3 没有 inode 条件重命名和元数据事务。实测覆盖可观察的修订冲突。属性对话框显示服务端返回的目录条目大小；权限操作需要服务器接受只读 `OPEN`、`FSTAT` 和 `FSETSTAT`。 [ssh2 SFTP 接口](https://github.com/mscdex/ssh2/blob/master/SFTP.md) · [OpenSSH 句柄实现](https://github.com/openssh/openssh-portable/blob/master/sftp-server.c)

## H6.4 活动分栏和终端目录

- 启动 Windows Git Bash，Workbench 从隔离回环 SSH exec 的 PTY 请求取得真实 Bash 输出。服务端夹具通过管道转接 Bash 标准输入输出；全屏与口令读取由真实 Bash 命令产生序列及等待，原生 PTY 作业控制另验。
- 从 Shell 切换目录后，在文件面板读取从磁盘写入的标记字节。反向默认关。打开反向、关闭正向后，文件操作仅向原空闲 Bash 发送一次经字面量引用的目录动作。Bash 实际进入包含单引号和命令替换外形的目录，两个可能写入的位置都无额外文件。
- 对空闲快照等待 SFTP 时，终端输入使旧快照失效。切换 Pane 后才释放延迟响应，原分栏和新分栏均未收到目录输入。全屏及交互读取时跳过，回到空闲后也没有补发。关闭原 Shell 后回读临时目录、启动文件和源文件。
- 文件导航的准备和提交都约束到原连接、附属文件会话、Shell 和 prompt 修订。切换、关闭、输入或新导航使原范围失效。读取状态和提交能力仅供桌面调用。上游会话隔离和 prompt 集成做法来自 Motty 固定版本 `2daa9db582e16edf60a60b7ada26f47f808f973c`。 [源码入口](../../../../../plugins/ssh/src/engine/shell-directory.ts)
