# H6.3 SSH 远端文本版控 Windows 验收

在 Windows Electron 44.9.1 的独立双栏打开回环 SFTP 的 UTF-8 文件。通过 Workbench 查找替换、跳至第 2 行、缩进并保存。回读远端原始字节，确认 BOM、CRLF、更新的正文及 0640 权限。超过 1 MiB 和无效 UTF-8 夹具分别提示。

第二个绑定文件会话通过真实 Engine 和 SFTP 保存新版。原编辑器再次保存收到版本冲突，本地草稿与远端正文各自保留。读取新版本后在同一对话框查看两份内容。另在暂存写入时从夹具模拟外部修改，替换前再次校验发现变化，保留外部正文并清理暂存文件。

复跑 `playwright test tests/e2e/workflows/ssh-workspaces.spec.ts --workers=1`，H4 与 H6 的 Workbench 用例共 5 项通过。SSH 的 Vitest 全组 56 项通过，插件 TypeScript 和改动源码 lint 通过。

参考 Motty `main@2daa9db582e16edf60a60b7ada26f47f808f973c` 的 `internal/sftpclient/text.go`。Huhu 按规范化路径、字节和权限计算版本，同一 Engine 内串行化兼容的文档写入。服务器支持时使用 POSIX rename，其他服务器沿用备份及还原路径。SFTP 的版本检查与 rename 是分开的请求，对独立客户在最后一次检查和 rename 之间发起的写入没有服务端比较交换保证。系统外部应用桥只打开受管本机路径，当前平台缺少经过验证的远端编辑器目标适配器；远端编辑使用 Workbench 内置入口。
