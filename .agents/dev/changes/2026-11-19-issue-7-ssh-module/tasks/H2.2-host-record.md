## 实施验收

在新建测试 Vault 使用专用测试账户和凭据，经客户端保存、重新打开并从授权测试主机验证配置可用；证据只记版本、认证方式和结果。

1. 保存测试主机并重开，核对账户/端口、分组/标签及高级字段；依次省略、替换、清空测试口令，摘要反映状态；显式 0 与未配置可区分。
2. 两个编辑者持同版提交，迟到者收到冲突；模拟受保护存储写失败，旧版本与旧引用保持。Safe 未初始化、锁定、停用三个样例结果一致。

## 原型对照与确认范围

HTML 原型始终使用离线夹具，连接、终端、文件、转发和监控均为模拟。

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「主机」对照「主机／编辑器、认证摘要、保存失败」。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。

## Windows 桌面取证

- 真实工作台通过 `ssh.hosts.configure` 保存主机配置和 SSH 自有认证补丁。检查未初始化 Safe 时的密码、锁定时的粘贴私钥和口令、停用时的本机身份文件和 Agent。身份文件通过现有桌面选档接口取得，使用隔离 Vault 内合成文件。预览凭据字段留空，按后端摘要展示状态。 [编辑器](../../../../../plugins/ssh/src/ui/HostEditorDialog.tsx) · [定向端到端](../../../../../tests/e2e/ssh/host-records.spec.ts)
- 通过工作台验证冲突后草稿保留，重新打开后读取已提交版本。复制得到独立主机 ID，副本的密码待配置。验证凭据留空保留、显式替换、清空及撤销清空，以及改变目标后需重新配置。标签、连接超时、保活显式 `0` 和未设置次数可分别回读。编辑保留原目录分组。分组由主机目录能力维护。 [定向端到端](../../../../../tests/e2e/ssh/host-records.spec.ts)
- Windows Engine 回归使用回环 SSH，复核了受保护存储写入失败后旧版本和凭据保持，以及合成密码、加密密钥和本机身份文件的实际连接认证。UI 与 Engine 检查使用新建测试 Vault。 [Engine 回归](../../../../../plugins/ssh/test/host-auth.engine.test.ts)
- 复核原型六文件指纹 `0a890ec3a9f26bbedc304f7b61e9cb41975d8b48df4ca2a96a33ee05fb473d2b`。参照本机 Motty `2daa9db582e16edf60a60b7ada26f47f808f973c`（Apache-2.0）的 `internal/workbench/host_edit_save_failure_test.go` 对失败后保留编辑和已提交目录的验证方式，界面由 Huhu 的组件和认证合同实现。
