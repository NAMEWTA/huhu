## 实施验收

把应用的 OpenSSH 配置来源指向临时测试文件，分别从应用和该文件修改同一测试主机，比较两侧的实际内容与变更次数。

1. 修改测试文件中的 ProxyJump、IdentityFile 或 keepalive，预览并接受后修改对应主机；反向更新一次，下一轮无重复差异。
2. 两侧同字段冲突保留两值供决定；解析错显示位置，取消保持旧快照，导入的命令字段保持为文本。

## 原型对照与确认范围

HTML 原型始终使用离线夹具，连接、终端、文件、转发和监控均为模拟。

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「SSH 设置、跳板路由／代理」对照「设置／连接／配置同步」。双向配置同步用独立合成文本对照。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。
