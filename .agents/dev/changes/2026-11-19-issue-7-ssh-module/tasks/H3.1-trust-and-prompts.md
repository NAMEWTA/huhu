## 实施验收

用隔离的 Known Hosts 和已授权测试主机做首次连接与重复连接。以测试主机公布的指纹和认证记录核对客户端等待项。

1. 从首次展示指纹到用户接受再到认证，重开页面按 attempt 找回待答；多问、多轮、CA、OTP、缺本机身份分别展示，回答仅消费一次。
2. 拒绝、超时或指纹变化时停在准确 hop；旧提示不能继续，changed-key 只能在独立 Known Hosts 管理核对更新，普通回答不持久化。

## 原型对照与确认范围

HTML 原型始终使用离线夹具，连接、终端、文件、转发和监控均为模拟。

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「主机、已知主机」对照「信任与连接／陌生指纹、已知、变化、多轮问答」。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。

## Windows 指纹验收

- 对照已确认原型指纹 `0a890ec3a9f26bbedc304f7b61e9cb41975d8b48df4ca2a96a33ee05fb473d2b`。原生弹窗显示连接目标、实际跳点、指纹和密钥类型。桌面连接读取当前 Engine 快照，关闭弹窗、切出模块或刷新后仍可找到相同 attempt、hop 和 promptId。拒绝、仅本次信任、保存后重连分别回读信任记录。 [客户端场景](../../../../../tests/e2e/ssh/trust.spec.ts)
- 回环两跳先保存原指纹，在相同目标端口重启第二跳服务。准确阻断第 2 跳，服务器未收到认证，旧回答和变化提示均不可使用，跳板连接被回收。独立已知主机入口核对新旧指纹，验证取消移除保留记录，确认只删除选中旧指纹，重拨再确认新指纹。 [客户端场景](../../../../../tests/e2e/ssh/trust.spec.ts)
- Engine 回归验证等待超时清除回复权限，以及等待期间另一记录写入时复核成功阻断。已有前台连接调用和回环 Web 信任流程继续使用原能力，已知主机移除由桌面入口调用。 [Engine 管理器回归](../../../../../plugins/ssh/test/manager.test.ts)
- 参照本机 Motty `2daa9db582e16edf60a60b7ada26f47f808f973c`（Apache-2.0）的 `internal/workbench/known_hosts.go` 和 `internal/workbench/known_hosts_test.go` 中独立核对、移除和下次拨号重新询问的方式。界面、文件读写与鉴权采用 Huhu 现有组件及 Vault 接口。

跨页面待答恢复覆盖同一 Engine 的桌面会话。Engine 重启后需重新连接。OpenSSH CA、多问多轮交互、OTP 和独立的缺本机身份恢复流程待相应合同及验收。
