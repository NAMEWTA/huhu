## 实施验收

在测试 Vault 建立带引用与无引用的两台主机；从应用的删除入口检查引用清单和实际持久化结果。

1. 为测试主机建立三类引用，打开删除能辨认每个受影响对象；无引用项确认后只删除目标。
2. 有引用时按最终选择验证先解绑，或预览后原子解除；取消或提交失败保持主机和原引用，未定前不宣称级联获批。

## 原型对照与确认范围

HTML 原型始终使用离线夹具，连接、终端、文件、转发和监控均为模拟。

打开[本地原型](../prototype/index.html)，从[侧栏导航](../prototype/prototype.js)的「主机」对照「主机／删除引用预览」。演示中的删除分支仍待 Q7-1 决定。待用户确认该场景的入口、状态反馈以及上述失败后能采取的动作。落地界面前按[原型确认记录](../prototype-review.md)核对具体版本和覆盖范围；演示未覆盖的细节单列待走查。

## Windows 桌面取证

- 删除弹窗根据主机列表列出以当前主机为跳板的记录，显示引用方名称和地址，可进入引用方编辑。移除引用需独立保存，删除提交携带原主机 ID 和预期版本，由 Engine 再次检查跳板引用。 [删除弹窗](../../../../../plugins/ssh/src/ui/HostRecordActionDialog.tsx) · [版本与引用校验](../../../../../plugins/ssh/src/engine/host-configurations.ts)
- 真实工作台验证反向添加跳板会形成循环，保存失败时草稿保留。已有引用时显示引用方且无法提交删除。解除引用后，取消保留两台主机，重新确认仅删除目标，目录读取仍包含引用方的原 ID。 [定向端到端](../../../../../tests/e2e/ssh/host-records.spec.ts)
- 当前基线仅有主机跳板引用的查询和服务端约束。工作区模板、独立路由及转发引用须在相应对象落地后加入查询和删除校验，三类引用的联合验收待共享能力。
