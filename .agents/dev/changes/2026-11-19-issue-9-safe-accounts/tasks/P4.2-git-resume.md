# P4.2 修复 Git 认证后恢复同步

所属交付 P4。本项承接 [Issue S3、C03、D01](../source.md)，行为规则见[模块认证责任](../spec.md#modules)，设计见[现有消费者](../design.md#current)。

## 交付与依赖

Versioning 按所属 remote 认证状态解释暂停/重试，移除对 safe.unlocked 事件的依赖。

**前置产物**　[P4.1](P4.1-git-authentication.md)。

**代码入口**　[plugins/versioning/src/engine/sync.ts](../../../../../plugins/versioning/src/engine/sync.ts)、[plugins/versioning/src/engine/auto-sync.ts](../../../../../plugins/versioning/src/engine/auto-sync.ts)、[plugins/versioning/src/engine/index.ts](../../../../../plugins/versioning/src/engine/index.ts)。

## 原型与确认范围

[Safe 原型](../prototype/index.html)的待确认场景为「Git 状态 → 认证失败暂停 → 修复 → 恢复」。#9 原型核对凭据归属与独立配置提示。所属模块的完整表单、授权和连接体验由相关 change 的原型或实际入口补验。 [版本与用户确认范围](../prototype-review.md)

定位到[保险箱演示区域](../prototype/index.html#main)，核对settingsPage 的 Git 同步配置状态；暂停及实际恢复另在 Versioning 验。

## 验收

- [x] 令测试 remote 拒绝一次，回设置修复后以同一配置恢复同步，核对拉取/推送次数及状态。
- [x] 在暂停时反复锁定/解锁 Safe，既不恢复也不重复发请求；只读或认证仍无效时保留真实原因。

Windows Git 2.47.1.windows.2 在隔离 Vault 上通过桌面 Engine 能力 `sync.update`、`sync.auth.configure`、`sync.run` 和 `sync.status` 验证。HTTPS `a.git` 首次认证拒绝送出 2 个请求，反复锁定和解锁 Safe 增加 0 个。Safe 处于锁定状态时替换该目标凭据，沿用原 `full` 配置完成一次 fetch 和一次 push，共 7 个请求。注入的远端文件出现在 Vault 中，本地文件出现在远端，状态回到 `idle`。过期修订增加 0 个请求。

HTTP `b.git` 的保存未解除 `a.git` 的暂停。显式拉取建立 `b.git` 自己的暂停后，保留凭据增加 0 个请求，替换成仍无效的凭据增加 2 个请求并停在新修订的 `remote-rejected`。只读调用返回 `READ_ONLY_VAULT`，增加 0 个请求。夹具关闭 Engine 和回环服务，清除模块凭据并验证隔离目录已删除。相关用例见 [Windows Engine 与系统 Git 测试](../../../../../plugins/versioning/test/remote-auth.engine.test.ts)及[调度器用例](../../../../../plugins/versioning/test/auto-sync.test.ts)。前端原型仍待确认。
