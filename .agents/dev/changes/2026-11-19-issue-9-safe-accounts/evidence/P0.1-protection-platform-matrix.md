# P0.1 模块凭据本机保护平台矩阵

本轮以 `4d86c84b` 为基线，在 Ubuntu 26.04.1 LTS x86_64、Node 24.21.0、pnpm 12.10.1 验证。测试使用临时 Vault、临时应用数据目录和随机编号的合成条目。

| 平台 | 系统后端与原生绑定 | 可用时 | 不可用时 | 桌面打包 |
| --- | --- | --- | --- | --- |
| Linux x64 | Secret Service，`keyring.linux-x64-gnu.node`（本机 glibc）。锁文件另含 x64 musl。 | 实测 gnome-keyring 提供 `org.freedesktop.secrets`。真实 Engine 保存、锁定 Safe、重开并读取成功。ZIP 恢复后保留定义，凭据状态要求重新配置。重复创建被拒绝，原键仍可读。 | 实测将 D-Bus 地址指向不存在的套接字，真实测试的写入探针得到 `unavailable`。确定性用例验证取用和显式重新配置均返回 `unavailable`，原 revision 与密文字节保持，恢复后可再次取用。 | Linux x64 是 AppImage 与 deb 的当前目标。已核对本机预编译模块加载和 ASAR 解包规则。本轮没有构建安装包。 |
| macOS x64 / arm64 | Keychain，锁文件含 `keyring.darwin-x64.node` 与 `keyring.darwin-arm64.node` 对应的包。 | 本轮未实测。 | 本轮未实测。绑定加载或系统钥匙串调用异常由适配器转换为 `unavailable`。 | macOS 当前发布目标为 arm64 DMG。两种文件名均匹配解包规则。 |
| Windows x64 | Credential Manager，`keyring.win32-x64-msvc.node`。 | 本轮未实测。旧提交 `3bd2e24` 从已打包的 Electron UtilityProcess 完成 23 项合成凭据检查。 | 本轮未实测。绑定加载或系统钥匙串调用异常由适配器转换为 `unavailable`。 | Windows 当前发布目标为 x64 NSIS。旧提交实测原生模块从 `app.asar.unpacked` 加载。 |

Linux 显式启用 `secret-service`，禁用依赖默认的内核 keyutils 回退。Linux 会话需要可连接的用户 D-Bus 和可用、解锁的 Secret Service 集合。服务缺失时，在当前登录会话中启动支持 Secret Service 的钥匙串并解锁默认集合，然后重试。未在本轮锁定真实系统钥匙串。 [keyring-node 2.1.2 后端选择](https://github.com/Brooooooklyn/keyring-node/blob/v2.1.2/src/entry_builder.rs)

桌面构建继续把 `@napi-rs/keyring` 保留为运行时外部原生依赖，由 `**/keyring.*.node` 将对应平台的文件放在 ASAR 解包目录。 [Electron Vite 配置](../../../../../apps/desktop/electron.vite.config.ts) · [打包配置](../../../../../apps/desktop/electron-builder.yml) · [Windows 历史证据](../../2026-11-19-huhu-issues-3-10/windows-stage-combined-3bd2e24.md)

## 复跑与清理

- `pnpm exec vitest run apps/engine/test/module-credential-host.test.ts --reporter=verbose` 实测 2 通过、4 跳过。其中 1 项走真实 Linux 后端、1 项走确定性故障夹具。
- 使用无效的 `DBUS_SESSION_BUS_ADDRESS`，同一文件与五个 SSH 插件集成测试文件合计 14 通过、5 跳过。真实钥匙串用例按不可用跳过。两项 Engine SSH 用例在同一断开 D-Bus 的设置下另行筛选运行，均通过。
- 真实用例仅跟踪当次写入的合成探针 ID 和模块随机键 ID。正常清除后对模块键读取 `null`。即使用例提前失败，`finally` 也按已跟踪的精确 ID 删除，并逐个读取确认 `null`，随后关闭临时 Engine、删除临时目录。 [实际用例](../../../../../apps/engine/test/module-credential-host.test.ts)
