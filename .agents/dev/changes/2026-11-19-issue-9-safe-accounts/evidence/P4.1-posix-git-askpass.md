# P4.1 POSIX Git askpass 环境与取消

基线 `5021f54c`。在 Ubuntu 26.04.1 LTS x64、Node 24.21.0 与 Git 2.53.0，用临时 Vault、独立 Git 配置、隔离运行目录和回环 HTTPS 裸仓库验证。认证材料是每轮随机合成值。

- 修复前，开放 HTTPS 安全专项后，真实 fetch/push 创建了测试明确禁止的 curl trace 文件。
- 合并两种 askpass 的环境和 Git 参数后，取消阶段暴露了第二条差异。Engine 已返回取消，回环服务在八秒内仍看不到连接关闭。POSIX 只给 Git 父进程发信号，HTTPS 子进程仍持有连接。
- 修复后，Windows 命名管道与 POSIX 启动器共享对继承变量的清理、trace2 禁用、协议约束及对 hooks、fsmonitor 和子模块等的限制。POSIX 继续通过当次 Git 子进程的专用变量交给 askpass 两个值。私有 POSIX Git 命令在独立进程组内运行，取消或超时时终止组内进程。
- Linux 用例验证旧 askpass 被覆盖，curl trace 文件始终不存在，协议及仓库限制、重定向拒绝和远端错误脱敏均有效。取消已认证且尚未响应的请求后，服务端观察到断连，临时启动器删除，下一次取回成功。
