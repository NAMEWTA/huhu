# Safe 个人多账号管理与模块认证 · #9

用户在 Safe 中为一个网站或 APP 管理多个登录账号，在实际使用 SSH、Git、Agent CLI、Automations、Mail 的模块中单独配置运行凭据。即使两个地方填写同一邮箱，两份数据也拥有独立的编辑、删除、授权与恢复流程。

2026-11-17 [Issue 全文及评论快照](source.md)无评论。§1 的用户决定和 §9 的 A01–D05 为验收依据。§2.1 的表单默认值沿用原文的建议口径；实施需要改变必填/可空规则时须记录原因。当前调用链与模块自有认证边界见[设计](design.md)，采证责任见[计划](plan.md)。

## 从建条目到再次解锁

| 操作 | 验收契约 |
| --- | --- |
| 初始化和进入 | 沿用主密码设置、解锁、错误冷却、手动/自动/按设置离开锁定、改主密码。锁定页只给状态与恢复动作。切 Vault 或停用立即结束原解锁会话。损坏库明确报错，原文件保留。 |
| 一次保存多个账号 | 条目公共字段为稳定 id、名称、网址、tagIds、账号集合、时间。账号稳定 id、账号文本、密码、手机号、邮箱、备注和时间各自保存。名称与账号必填，至少一个账号，网址、手机号、邮箱、备注可空；非空网址/邮箱做基本校验。手机号按文本保留 + 和前导零，密码逐字保存，可空并显示「未设置」。无网站登录请求。保存失败仍可编辑，磁盘上无半个新条目。 |
| 编辑多账号 | 同名账号和不同网站的相同账号各有 ID。用 entryId+accountId+版本只改对应账号。编辑公共网址不得改变任何账号。密码支持保留/设置原文/显式清空，遮罩或未展开的字段不会成为覆盖值。页面与外部工具同时修改时，后提交的旧版本得到冲突且可重读。 |
| 搜索和标签 | 顶部搜索、新建、锁定；列表仅显示名称、网址摘要、账号数、文字和彩色标签。「全部」「无标签」及多个标签筛选可达，无标签互斥，多选取交集再与搜索相交。搜索名称、网址、标签、账号、手机、邮箱、备注，命中账号返回所属条目和账号位置；密码不参加索引。数据仅在解锁内存内检索。 |
| 管理标签 | 标签稳定 ID、名称、调色板颜色标识。相同标签名复用，改名换色作用于全部引用。新名称与已有标签冲突时说明冲突，保留原关联。删除标签只解除关联。颜色同时配文字，明暗主题可读。 |
| 详情、显隐和复制 | 解锁、获相应权限才可读取账号及其他个人字段。密码默认遮罩；点击特定账号的显隐/复制才显式取值。复制成功或失败给反馈；隐去、切换账号、锁定与离开清理已展示的值。成功反馈和审计仅含动作与结果。外部在用户单独开启敏感读取时可显式查看，没有主密码读取操作。 |
| 删除和取消 | 删账号前指出目标；剩最后一个时给「删除整个条目」或取消，另行执行整条删除。删条目明示账号数，保留标签目录和其他条目。普通关闭未保存编辑可继续或放弃，锁定或换 Vault 则清除明文编辑状态，提示不会生成未加密草稿。 |
| 重启、恢复 | Google 条目含三个账号和多个标签。改其中一个后重启，用原有效主密码解锁，恢复三个账号五字段及标签。改主密码以新密码打开当次备份；历史备份需使用生成该快照时的密码。缺 keyring、资料损坏、错密码均显示实际失败；不能以空库代替。 |

页面沿用 Huhu Safe 模块、设置贡献及现有组件。原型要验证大量账号、长中文名称、长 URL、多标签、窄窗返回、键盘显隐复制、保存冲突、锁定打断。界面以 Huhu 自有主题、导航、组件和文案呈现。[模拟原型](prototype/index.html)的版本及用户确认范围以[确认记录](prototype-review.md)为准。全局搜索、日志、Git 暂存和包内扫描均不得出现个人字段的明文副本；操作记录仅含时间、实体 ID、动作、结果。

## 各模块要交付的独立行为

| 所有者 | 从哪配置、如何使用、如何恢复 |
| --- | --- |
| Safe | 网站/APP 的个人记录只由用户或获开放权的 Safe 管理能力读取。用户主动复制不产生到服务配置的连接。 |
| SSH · #7 | 新增/编辑主机时输入用户名、密码或私钥/口令，按适用方式支持 agent/身份文件、代理和跳板配置。保存只返回 hostId、认证方式、已配置状态。连接按 hostId，用模块认证处理主机密钥信任、交互/OTP、取消、失败与重试。UI/MCP/CLI 共用主机及同一连接 handler。未配置时回到该主机修复。Motty 功能扩展由 #7 验收。 |
| Versioning · 本 Issue | 同步设置填写该 remote 的 HTTPS 用户名及密码/token；常规读取脱敏。更换 remote 后重新绑定，不能向新目标发旧 token。沿用系统 Git、生命周期内 ASKPASS、主机校验与清理。Git SSH URL 使用系统 SSH/agent。Safe 状态不进入 Git 暂停/恢复判定。 |
| Agent CLI · #4 | 原生登录由 CLI 本身维护；额外启动环境由 Agent CLI 拥有。区分普通变量、受保护变量及显式清空。预览、布局和恢复意图不携带值。启动、取消及重试仍走统一启动链与稳定 requestId。 |
| Automations · #5 | 脚本/规则配置自有环境，受保护值在 Engine 侧按该次运行解析，仅交目标子进程。派遣遵守 #4/#5 的执行合同，任务正文、评论、回执、通用事件不作为环境传值通道。具体测试覆盖终端退出、取消、Core 崩溃和恢复资料的清理。 |
| Mail · #8 | 认证由新增/编辑邮箱、OAuth 会话/刷新和邮件 AI 设置维护。删除或改主密码只作用于所属领域。缺本机钥匙由 Mail 修复；发件、收件和真实 provider 测试由 #8 负责。 |

业务验收横跨 Safe 未初始化、锁定、停用三种状态。实际凭据仍有效时现有模块可以正常工作。底层仅复用无业务语义的保护机制，保存不可用则给出所属模块的可处理错误。普通列表、创建/修改返回值、预览、参数、临时文件与诊断均需检查秘密泄漏。

## 数据、权限与清洁安装

- 条目私有元数据、全部账号五字段、标签名/颜色和关联整体受主密码保护。只有恢复、定位与并发校验所必需的最小元信息可在外层。Safe 解锁索引不能进入全局 FTS 或持久查询缓存。锁定后拒绝旧会话迟到读写及结果回填。
- 桌面与已登录 Web 用户、获开放权的 MCP/CLI/通用 API 都经相同 schema、handler、锁定与校验。entries、accounts、tags、生命周期/设置与显式密码读取分别登记，敏感操作独立选择开放，干净安装时 MCP/CLI 工具默认关闭，用户可逐项或明确批量开启，敏感读取独立配置。关闭外部访问不影响正常内部操作。CLI 敏感输入走受控输入方式。SSH/Git 等内部认证不得调用 Safe reveal。
- 整 Vault 备份保全密文、必要 keyring 和版本，恢复后用相应主密码访问。机器认证按模块排除或独立保护，配置恢复与认证恢复分别显示。Git 白名单和 Vault 包收集器各自验证，同机或新机均不得随包取得裸本机钥匙。
- 用户已确认产品尚未发布，交付以空白测试 Vault 设置主密码、创建新模型及在所属模块设置独立认证为起点。历史 Issue §7、B05 的适用边界是保护真实旧数据。旧格式迁入、手工转存、兼容接口、清理或改写真实旧库均不属于产品和验收流程。新格式整包恢复仍按上一项独立验收。

浏览器自动填充、自动登录、泄漏检测、团队共享、跨设备密钥托管、通用凭据代理与明文密码导出均在本期范围外。
