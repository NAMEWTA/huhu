## 所需实现边界

1. **按动作和记录签发资格。** 将 resume 和 fork 分别按已探测的真实可执行入口、provider 能力、记录状态、授权目录和目标判断。Claude/Codex 走原生 ID，Pi 继续走确切 transcript。列表状态和桌面/已开放工具的实际启动复用同一准则，启动侧再次校验。CLI 缺失、版本缺动作、记录损坏、来源有歧义或 cwd/目标权限失效时给具体原因。活跃会话保持原现场定位、只读观察及已有防重约定。
2. **证明 ID 指向所选来源。** 沿用 Engine 扫描与 `historyId`、revision，校验源记录、规范 cwd、provider profile/状态目录与真实启动环境一致，并在首次提交 Core 前重新检查。要证明原生查找范围内的完整 UUID 唯一指向该来源；仅在当前 Space 的限量列表看到一条不足以证明唯一。若重复 ID 可能在其他目录、资料库或归档被选中，只对能够核实选择结果的记录开放，歧义项仍可预览。保持参数边界，拒绝能把 ID、cwd 或资料根改到另一来源的覆盖。原生调用明确传已选 ID，禁止退回最近记录、名字猜测或 picker。现有实现把 `hit.file` 传递给只按 Pi 解析的校验，存在两处调用。补齐时需要按 provider 复核来源，不能只删除 `historySourceBlocked`，也不能只丢掉文件证据来放行。 [来源身份与 revision](../../../../../plugins/agent-cli/src/engine/history/scanner.ts#L172) · [provider 资料根](../../../../../plugins/agent-cli/src/engine/history/scanner.ts#L222) · [候选绑定](../../../../../plugins/agent-cli/src/engine/index.ts#L541) · [提交前复核位置](../../../../../plugins/agent-cli/src/engine/sessions.ts#L721)
3. **区分原会话、分支和运行回执。** 复用已有 workspace 目标冻结、Space/layout 版本、`requestId` 与 Core 原请求对账，保证提交后重试只找原进程。恢复继续原生原 ID 并进入已选 pane。分支在明确目标创建独立会话，原 transcript 保持原样，使用该 provider 支持的证据登记实际子会话原生 ID。现有 fork 统一生成的 `huhu-` ID 只有 Pi argv 真正传入；Claude/Codex 不能把该值或源 ID 当作分支身份。支持指定新 ID 的方式须由实际版本证明，或者从明确的 provider 回执或资料关联识别新 ID。只有 Core 进程创建回执时应如实呈现，不能提前确认选中历史已恢复或子会话已识别。 [目标与请求](../../../../../plugins/agent-cli/src/engine/workspace-layout.ts#L141) · [现有分支 ID](../../../../../plugins/agent-cli/src/engine/index.ts#L561) · [Session 记录](../../../../../plugins/agent-cli/src/engine/sessions.ts#L658)
