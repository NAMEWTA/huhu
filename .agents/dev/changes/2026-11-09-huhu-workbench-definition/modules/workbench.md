# 工作台外壳、Vault 生命周期、首页与命令面板

所属：`packages/workbench`（界面）、`packages/kernel` + `packages/vault`（Engine）。原型依据：`vault.jsx`（启动页）、`app.jsx`（外壳、`Home`、`ActivityFeed`、命令面板、通知）、`backup-dialog-v6.jsx`。

## 1. 用户故事

| ID | 故事 |
| --- | --- |

## 2. 界面

### 启动页（未打开 Vault）

左侧品牌区：标题“打开文件夹。进入你的工作台。”、三条要点（“笔记保留在普通文件目录中”“领域数据与设置统一位于 .huhu/”“索引随时可从文件重建”）。右侧卡片：主按钮“打开 Vault 文件夹”，次按钮“打开示例 Vault”，并排“新建空白 Vault”“导入数据包”；下方为“本次运行中打开过的 Vault”列表（D-26，仅会话内）。读取中显示进度；失败显示 Banner（原因 + “重新选择目录”/“以只读方式打开”）。

### 外壳

结构与尺寸见 [design-system](../design-system.md) §3。顶栏中部 Vault 切换器：当前 Vault 名称 + 下拉（本次运行打开过的 Vault、“打开其他 Vault…”、“在新窗口打开…”、“关闭 Vault”）。

### 首页（rail“工作台”）

模块侧栏三项：总览、今日安排、最近活动。

- **总览**：页头“从这里继续今天的工作”，右侧“自定义”（卡片显示与排序对话框）与“新建”（下拉：笔记、任务、捕获、档案）。指标条四格：待推进任务（未完成数）、知识笔记、等待整理（收件箱待处理）、已启用规则；每格点击跳到对应筛选。下方两列：左“我的任务”（分段 全部/今天，最多 5 行，行内 CompletionCircle 可直接勾选，显示执行方式徽标）与“继续上次的思考”（最近修改 4 篇笔记卡片）；右“一段专注时间”（25:00 计时、开始/暂停/重置、今日完成次数）、“保持小小的好习惯”（勾选列表）、“灵感收件箱”（最近 3 条待处理 + “+”快速捕获）。
- **今日安排**：今天到期的任务、今天到点的提醒、今天的日记入口。
- **最近活动**：事件日志中面向用户的事件时间线（文件、任务、自动化、同步），可按模块筛选。
- 卡片由插件贡献（`homeWidgets`），插件停用时卡片隐藏，数据不删。

### 命令面板（R-15）

`Mod+K` 打开居中面板。分组：最近、命令、笔记、任务、档案、收件箱。输入时并行查询 `vault.search`（全文）与命令注册表；回车执行；`Mod+Enter` 在新标签打开。命令由插件 `contributes.commands` 注册（例：新建任务、快速捕获、切换主题、重建索引、锁定保险箱）。

### 通知中心

路径栏铃铛打开 Popover：未读在前，项含标题、正文一行、时间、来源模块；点击跳转来源并标记已读；底部“全部标为已读”“打开健康中心通知”。任务提醒到点时额外弹出 sonner 持久提示（不自动消失），含“打开任务”“知道了”。

## 3. 行为

### 打开 Vault

1. 用户点“打开 Vault 文件夹” → `huhuHost.pickDirectory` → Main 在当前窗口启动 Engine（架构 §3 启动顺序）。
2. 目录内无 `.huhu/vault.json`：创建 `.huhu/` 与 `vault.json`（名称取文件夹名），不改动其他文件；首次打开时 agent-guide 插件写入三份指南文件（若同名文件已存在则进入 conflict，不覆盖）。
3. Engine ready → Renderer 进入外壳，恢复 `.huhu/ui/state.json` 中打开的标签（文件不存在或损坏则打开首页）。
4. 失败：无权限 → 提供“以只读方式打开”（Engine 只读模式：所有写能力返回 `READ_ONLY_VAULT`，界面顶部 Banner 常驻）；写者锁被另一窗口持有 → 激活该窗口；锁被其他机器进程持有（端点不可达且锁未过期）→ Banner 说明并提供“只读打开”。

### 新建空白 Vault

对话框：名称 + 位置（`pickDirectory`，要求空目录或新建子目录）。创建 `vault.json`、默认 `settings.json`、默认自动化规则“定时检查 Agent 任务”（enabled、`*/5 * * * *`、系统时区）与指南文件。

### 示例 Vault

应用资源内含示例 Vault 模板（由 `packages/testkit/fixtures/demo-vault` 构建，R-12）。“打开示例 Vault”时要求选择一个空目录作为副本位置，复制后打开；示例内容不随应用写回资源目录。

### 切换与关闭 Vault

1. 存在未保存文档：对话框列出这些文档，选项“全部保存并切换”“保留草稿并切换”“取消”。
2. Renderer 清空全部 React Query 缓存与 zustand 分片；Main 按关闭顺序停止旧 Engine，再启动新 Engine。
3. 任何旧 Engine 迟到的事件因 `vaultId` 不匹配被客户端丢弃。

### 首页数据

`home.summary` 一次返回指标与卡片数据；订阅 `entity.changed`、`task.completedChanged` 后失效刷新。专注计时在 Renderer 运行，开始/暂停/重置调用 `home.focus.update` 持久化（`remainingSec`、`running`、`startedAt`、`completedToday`）；到零时生成站内通知“专注完成”并 `completedToday+1`。关闭窗口时暂停并保存剩余时间。习惯：`home.habits.update` 保存列表与当日勾选；跨日（按设置时区）首次打开首页时清空勾选（保留习惯本身）。

## 4. 依赖与边界

- 外壳不知道具体插件；模块列表来自已启用插件的 `contributes.modules`。
- 首页不保存任何任务或笔记副本，只调用 `home.summary`（由 kernel 聚合各插件注册的查询）。

| ACC-WB-06 | 专注计时运行到 00:00 | — | 产生通知“专注完成”；今日次数 +1；计时回到 25:00 未运行 |
| ACC-WB-07 | 任意页面 | 按 `Mod+K` 输入笔记正文中的一个词 | 结果“笔记”分组列出该笔记，回车打开并定位 |
| ACC-WB-08 | 停用 tasks 插件 | 回到首页 | “我的任务”卡片与 rail 任务项消失；重新启用后恢复，任务数据未变 |
| ACC-WB-09 | 窗口 1024×768 | 浏览各模块 | 无页面级水平滚动；详情面板以抽屉打开 |
