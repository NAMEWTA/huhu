# S5.2 从新邮件通知回到目标消息

所属交付 S5。本项承接 [Issue M-03、§6.3、S5](../source.md)，行为规则见[工作台操作](../spec.md#workspace)，设计见[调用与失败处理](../design.md#operations)。

## 交付与依赖

Mail 向工作台通知贡献定位目标与实体变化，通知和搜索使用相同本地 ID、账号与选择规则。

**前置产物**　[S5.1](S5.1-sync-schedule.md)、[S2.2](S2.2-search-locate.md)。

**代码入口**　[packages/kernel/src/notifications.ts](../../../../../packages/kernel/src/notifications.ts)、[packages/workbench/src/engine-client/query.ts](../../../../../packages/workbench/src/engine-client/query.ts)。拟在 `plugins/mail` 的同步与通知流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「首次同步 → 新邮件通知 → 跨账号定位」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#main)，核对搜索选中具体消息的落点；宿主通知实际送达另验。

## 验收

- [ ] 初扫模拟历史后再投入一封新信；只出现新信通知，点击后能在正确账号居中定位。
- [ ] 重复同步相同增量、切换 Vault 后重放旧回调，既不重复通知也不错误导航；账号已移除时明确目标不可用。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
