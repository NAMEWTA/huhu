# S2.1 按公开参与者浏览单人及多人对话

所属交付 S2。本项承接 [Issue M-02、§6.1](../source.md)，行为规则见[工作台操作](../spec.md#workspace)，设计见[数据与提交顺序](../design.md#storage)。

## 交付与依赖

Mail 在同账号内先聚合全部历史再分页，按公开参与者集合分组；过滤自己、无关目录、隐藏邮件及重复副本。

**前置产物**　[S1a.2](S1a.2-first-message.md)；本机已发事实来自 [S1b.3](S1b.3-submit-draft.md)。

**代码入口**　[one-mail/src-tauri/src/commands/data/conversations.rs](../../../../../temp/sources/one-mail/src-tauri/src/commands/data/conversations.rs)、[packages/workbench/src/engine-client/query.ts](../../../../../packages/workbench/src/engine-client/query.ts)。拟在 `plugins/mail` 的联系人、阅读与写信流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「联系人 → 单人/多人往来 → 下一页」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#main)，核对账号栏、联系人列表与往来阅读区。

## 验收

- [ ] 合成跨目录副本、同 ID 跨账号和超过一页的历史，核对排序、参与者、条数和分页边界；无 ID 信保持独立。
- [ ] 加入仅 Bcc 的本机信、垃圾箱及草稿，公开会话均不出现这些地址或记录；仅密送的发送结果可在本机发件记录查到。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
