# S4.1 添加 Outlook 账号并说明可用权限

所属交付 S4。本项承接 [Issue §3.2、§6.2、S4](../source.md)，行为规则见[添加与维护账号](../spec.md#accounts)，设计见[待定产品选择](../design.md#open)。

## 交付与依赖

Mail 拥有 Microsoft 会话、账号绑定与实际受众判定。新增专属 Graph consent 的用户选择仅阻塞该分支。

**前置产物**　[S1a.1](S1a.1-account-discovery.md)；真实联验需 Microsoft 客户端/租户。

**代码入口**　[apps/desktop/src/preload/index.ts](../../../../../apps/desktop/src/preload/index.ts)、[one-mail/src-tauri/src/oauth/mod.rs](../../../../../temp/sources/one-mail/src-tauri/src/oauth/mod.rs)、[one-mail/src-tauri/src/mail/sync/graph_api.rs](../../../../../temp/sources/one-mail/src-tauri/src/mail/sync/graph_api.rs)。拟在 `plugins/mail` 的Outlook 适配流程落地。

## 原型与确认范围

[Mail 原型](../prototype/index.html)的待确认场景为「Outlook → 授权 → IMAP 可用/Graph 权限不足/修复」。此项界面实施前，在记录中核对该场景对应的用户确认、版本及范围。尚未演示的状态须另列，模拟操作仅作体验依据。 [版本与用户确认范围](../prototype-review.md)

定位到[邮件演示区域](../prototype/index.html#fault)，核对添加 Outlook 邮箱与「OAuth 授权拒绝」。

## 验收

- [ ] 给模拟 IMAP/SMTP token 与 Graph token，分别显示可用路径和具体原因；对取消、完成及重授权复查目标账号。
- [ ] 只有 Mail.ReadBasic、错误 audience、拒绝或超时，分别呈现限制；不可假定能读正文。未确认额外 consent 时仍可验默认 IMAP。

使用合成邮箱、消息、附件和模拟交付结果，记录测试 Vault、输入、操作前后结果及实际调用次数。实际结果回填本任务。
