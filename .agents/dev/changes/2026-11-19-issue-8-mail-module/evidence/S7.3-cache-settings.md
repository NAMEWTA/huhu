# S7.3 邮件缓存占用与清理

缓存文件继续使用现有可重建的 Mail 路径。占用按受管文件的实际长度统计，内存搜索投影独立报告条数与 UTF-8 文本字节。清理需要显式确认，本机只读 Vault 拒绝执行。已读覆盖独立保存在 Mail 持久数据内，旧格式缓存中的有效标记在清理前保全，重扫继续按原账号、目录、传输和消息定位匹配。

清理先中断旧缓存代，再等待旧同步及写入退出，之后清受管缓存和文本索引。后台同步丢弃旧定时／监听状态，从正常间隔重新排队。界面作废本 Vault 的邮件查询和定位，再次同步可重建远端数据。草稿附件、认证及已有投递事实继续使用原存储路径。

Windows 回环 IMAP／SMTP 回归在真实 Engine HTTP 入口中核对缓存文件大小、1 条内存文本数据、无确认和只读拒绝。等待第二封 IMAP 正文时清理，迟到正文返回未恢复查询。重启后没有旧搜索数据，已读覆盖、原账号修订及认证、草稿附件和未知投递均保留。一次后续 IMAP 刷新重建正文，已读覆盖延续，SMTP DATA 保持原有 1 次。
