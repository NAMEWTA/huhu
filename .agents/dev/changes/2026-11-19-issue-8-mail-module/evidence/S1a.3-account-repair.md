# S1a.3 邮箱切换与原账号认证修复

从已保存账号进入维修与名称变更。修复以账号 ID 和打开时的 revision 为目标，Engine 读取该账号原有配置并发起 IMAP 测试。成功后仍以该 revision 提交。名称修改使用凭据事务的 `keep` 操作。

| 路径 | Windows 观察 |
| --- | --- |
| 两个账号 | 两个独立回环 IMAP 夹具返回不同主题。Edge 通过提供商分组和键盘切换，折叠一组时另一组仍可选择。390px 下由账号、邮件列表到正文逐层返回，恢复原账号选择及触发按钮焦点。 |
| 失败与冲突 | 错误凭据被 IMAP 拒绝。测试成功后更改同账号名称，旧测试会话的提交返回版本冲突。用旧 revision 开始测试时 IMAP 请求数不增。注入凭据定义发表失败后，原 revision、定义和可读取的受保护绑定均未改变。 |
| 取消与迟到 | 暂停正在保存的凭据事务再取消，恢复执行后提交返回取消，已取消会话不能再次保存。Edge 拦住原账号已经通过的测试回应，随后取消、切到另一账号再放行，当前邮箱与内容保持正确，旧对话框未打开。 |
| 修复与名称 | 使用已测试凭据更新原账号，同一 ID 得到新 revision，配置和目录保留。第二邮箱状态保持。只更改名称时继续使用原认证，经受保护读取及真实 IMAP 同步确认。 |
