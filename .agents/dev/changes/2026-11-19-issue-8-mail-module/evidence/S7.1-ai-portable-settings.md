# S7.1 Mail AI 可移植设置的 Key 检查

基线 `5021f54c`。在 Ubuntu 26.04.1 LTS x64、Node 24.21.0，以真实 Engine HTTP、回环 HTTPS、隔离 Vault 和进程内合成凭据保护验证。

- 修复前，停用并保留 Key 的保存路径不做网络验证，原实现也因此跳过对现有 Key 的字段检查。回归中，普通设置 HTTP 响应含有合成 Key。
- 修复后，对规范化的服务地址和模型单独执行字段检查。当前 Key 可读取时，保留、替换和清除都检查它。替换还检查新 Key。无害的停用保存能保留已配置 Key，现有 Key 暂不可读取时仍可停用。
- 回归验证有问题的编辑均返回 `INVALID_INPUT`，成功和错误设置响应与 `mail.ai.getSettings` 均无合成 Key。有效停用和清除阶段没有新增网络请求。原连接验证、正常替换、保留、重开和清除均通过。
- 导出并导入整 Vault 包后，逐一检查清单中的文件。包保留停用后的设置定义，新 Vault 显示需重新配置，合成 Key 未出现在包内任何文件中。

```sh
XDG_RUNTIME_DIR="$(mktemp -d /tmp/hc-xdg.XXXXXX)" pnpm exec vitest run --project @huhu/plugin-mail --maxWorkers=2
```
