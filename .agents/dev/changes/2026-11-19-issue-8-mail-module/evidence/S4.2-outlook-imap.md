## Windows 验收

使用 `plugins/mail/test/oauth-engine.test.ts` 的隔离 Vault、真实 Engine dispatcher、本地签名 issuer 和回环 IMAP／SMTP。HTTP 运输守卫拒绝回环外目标。IMAP 夹具用合成 token 对 XOAUTH2 实际鉴权，SMTP 夹具记录收件人、发件人、线程头和 DATA。全程使用合成邮箱。

| 账户权限或操作 | 实际结果 |
| --- | --- |
| 合成 Microsoft `Mail.ReadBasic`、Graph `Mail.Read` 或缺失 Exchange scope | 分别为 `graph-metadata-only`、`wrong-resource`、`permission-missing`。未访问 IMAP 目录，也未创建 Outlook 账号 |
| 仅 Exchange `IMAP.AccessAsUser.All` | 保存为收件专用，实际 `mail.sync.refresh` 走 IMAP。UID 42 正文可打开，SMTP DATA 为零 |
| 同账号追加 Exchange `SMTP.Send` | 保留账号 ID，邮件发送由既有 outbox 事务完成。仍以 IMAP 文件夹和 UIDVALIDITY 定位正文 |
| 同 Vault Gmail API 已启用，Outlook UID 43 在正文返回前断开 | 中断后缓存仍为 UID 42。重新同步读取 UID 43 的原文，UIDVALIDITY 保持 99。`mail.sync.status` 返回 IMAP、当前目录与 200 封窗口。Gmail 最新邮件及原生定位保持原值 |
| 对 UID 43 标读并回复 | `STORE` 和 `FETCH FLAGS` 后返回 `remoteSynced: true`。回复从该 Outlook 账号向原发件人投递，带 `<exchange.43@example.invalid>` 线程头，排除原信 Bcc。该阶段实际计数为 3 次 IMAP XOAUTH2、11 次 FETCH 记录、0 次 HTTP、1 次 SMTP DATA |
