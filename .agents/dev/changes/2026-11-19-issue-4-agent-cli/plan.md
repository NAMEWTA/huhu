# #4 工作区、终端与历史的实施计划

用户从一个明确的叶子发起新建，切换工作区后仍可定位原进程；连接中断、只读观察和历史恢复分别保留自己的身份与操作边界。行为以[规格](spec.md)和[执行合同](design.md)为准。源码采用[批次默认分支检出](../2026-11-19-huhu-issues-3-10/sources.md)，原始阶段和验收号见 [Issue §15–17](source.md)。

可立即开展 W0 的来源对照和真实包能力调查。取得真实 session 后，单 viewer 的流控和工作区结构可以分别推进。#4 拥有工作区文档、会话绑定及执行回执，#5 通过公开合同接收任务结果。公共 Space façade、shared TerminalView 和 #6 Web/#7 SSH 的调用方由拥有该行为的切片统一变更。

[原型入口](prototype/index.html)覆盖 Spaces、Agents、标签、分栏、现场/历史面板及演示故障。任务链接指向相关控件及待走查行为。尚待用户确认 HTML 版本，界面实施取[确认记录](prototype-review.md)所列指纹与范围。协议、真实 provider 和进程生命周期单独取证。

## 整合与待决范围

- [设计末节](design.md#待产品选择)保留两项选择。原目标关闭后的收纳方式影响 W2.2 的展示，布局快照是否随新格式数据包导出影响 W8.1。工作区同机重开、终端对账和其余正常备份恢复可先做。
- W6.0 先交付回执与 ACK 的公共契约。执行端 W6.3 用可控接收器验重交，Tasks 用相同样例验持久消费。W8.3 完成生产调用方切换并提供同一候选包；工作区套件 W8.2 和 [Tasks 实机旅程](../2026-11-19-issue-5-task-automation/tasks/T7.2-full-task-journey.md) 可并行使用该 SHA，各自记录临时 Vault 和运行身份。#3 提供外壳，#6、#7、#9 分别提供实际授权、SSH viewer 和模块秘密边界。
- Issue §16 的 A–F 编号在上表逐项映射，§17 的真实包、上游对照、门禁与性能归 W8.2。性能样本包括冷启、热 attach、输入延迟、拖动、持续输出、大历史及资源回收；记录平台/包 SHA、Core/provider 版本、视口与主题。
