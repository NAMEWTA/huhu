# W4.2 断线后重连原进程，识别替代 shell

断开 viewer、Engine 或 Core 后，界面显示失联对象；只有仍匹配的原运行可恢复输入。

归属 W4，对应 [Issue #4 验收矩阵](../source.md) B06、C09、C11、F02、E08。[行为规格 · 启动、断线与持久化](../spec.md#启动断线与持久化) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[W4.1](W4.1-stream.md) 的连接/通道和 [W1.2](W1.2-launch-reconcile.md) 的长期身份。
- **职责与边界**　订阅按 snapshot/seq/generation 对齐，区分 lost、ended、spawn_pending 与 keep 恢复；过期回调不能跨 Vault。
- **现有代码入口**　[client.ts](../../../../../packages/herdr-client/src/client.ts) · [agent-cli/engine/terminal-bridge.ts](../../../../../plugins/agent-cli/src/engine/terminal-bridge.ts) · [components/TerminalView.tsx](../../../../../packages/ui/src/components/TerminalView.tsx) · [agent-cli/engine/sessions.ts](../../../../../plugins/agent-cli/src/engine/sessions.ts) · [apps/engine/src/boot.ts](../../../../../apps/engine/src/boot.ts)。
- **原型走查**　[现场 → 断线、重连、原实例丢失](../prototype/index.html#connection)。用「断开视图」「模拟 Agent 原进程丢失」切换场景。确认可重连和须人工找回时的动作。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 分别断开 WS、Engine、专用 Core，再连同一会话。用 seq、地址/代次、首屏次数和最后输出区分三种恢复。
2. 漏事件、旧 seq、Core keep 变成新 shell、切到另一 Vault 后迟到输入，均应可解释且旧正文发送数为零。循环后检查订阅/通道回落。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [packages/herdr-client/test/frames.test.ts](../../../../../packages/herdr-client/test/frames.test.ts) · [plugins/agent-cli/test/terminal-bridge.test.ts](../../../../../plugins/agent-cli/test/terminal-bridge.test.ts) · [packages/herdr-client/test/attach.live.test.ts](../../../../../packages/herdr-client/test/attach.live.test.ts)
