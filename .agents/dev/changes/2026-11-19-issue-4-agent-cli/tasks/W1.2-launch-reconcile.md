# W1.2 找回回包丢失的启动

用户重查同一启动能找回原进程；资源情况不明时保留原操作和查证入口。

归属 W1，对应 [Issue #4 验收矩阵](../source.md) A06、C10、C12。[行为规格 · 启动、断线与持久化](../spec.md#启动断线与持久化) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[W1.1](W1.1-launch.md) 的真实启动和 session/operation 标记。
- **职责与边界**　以规范化意图和稳定 ID 持久去重，labels、地址和代次共同对账。不同意图保留独立身份。
- **现有代码入口**　[agent-cli/engine/sessions.ts](../../../../../plugins/agent-cli/src/engine/sessions.ts) · [agent-cli/engine/herdr-core.ts](../../../../../plugins/agent-cli/src/engine/herdr-core.ts) · [agent-cli/engine/index.ts](../../../../../plugins/agent-cli/src/engine/index.ts)。
- **原型走查**　[新建目标 → 启动中、待核实、找回](../prototype/index.html#fault)。演示控制可选「确认丢失」；多候选的技术对账需故障注入。确认错误细节与重试入口。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 在 Core 创建后截断 run 响应，重启 Engine，再提交同一意图；核对一个进程、一条绑定及原 operation。
2. 分别返回多候选、空列表但仍可能启动、list 失败、spawn_pending、同键不同载荷；输出 pending/unknown 或冲突，明确未创建才准续发。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/agent-cli/test/sessions.test.ts](../../../../../plugins/agent-cli/test/sessions.test.ts) · [plugins/agent-cli/test/agent.test.ts](../../../../../plugins/agent-cli/test/agent.test.ts)
