# W6.3 持久保存并重交执行端回执

受控执行产生的问题或结果带原始身份持久留存，接收者重启后可取得同一个回执。

归属 W6，对应 [Issue #4 验收矩阵](../source.md) F01、F02、C12。[行为规格 · 启动、断线与持久化](../spec.md#启动断线与持久化) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[W6.0](W6.0-receipt-contract.md) 的回执类型、两段 ACK 与样例，以及 [W6.1](W6.1-bound-input.md) 的真实运行绑定。
- **联验证据**　保留原 receiptId、绑定、派送尝试与 ACK 顺序；下游可用同一字段在真实 Tasks 端关联结果。
- **职责与边界**　适配器及 Agent 各自持久保管待确认回执。生产端验收使用可记录或丢弃确认的契约接收器，业务端的持久确认由接收器按样例提供。
- **现有代码入口**　[agent-cli/engine/index.ts](../../../../../plugins/agent-cli/src/engine/index.ts) · [agent-cli/engine/sessions.ts](../../../../../plugins/agent-cli/src/engine/sessions.ts) · [agent-cli/engine/waiting.ts](../../../../../plugins/agent-cli/src/engine/waiting.ts)。
- **原型走查**　[等待与结果 → 回执待交](../prototype/index.html#inspect-body)。原型只呈现等待和结果投影。执行侧 ACK 由记录证明，界面结果归 #5。本片的协议或来源核验可先执行。涉及状态呈现时按同一版本的[确认记录](../prototype-review.md)核对。

## 验收与取证

1. 在执行适配器写盘后重启 Agent，确认按原 receiptId 与绑定接收；在契约接收器持久记录后丢弃首个 ACK，再重启 Agent。核对原回执仍待交、重发内容一致，最终得到匹配 ACK 后才结束待交，CLI 执行计数为一。
2. 同 ID 异载荷、缺原生回执、回传格式错误及其他 task/run 签入均被识别；保留待核实，仅修回执，执行次数不增。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/agent-cli/test/sessions.test.ts](../../../../../plugins/agent-cli/test/sessions.test.ts) · [plugins/agent-cli/test/waiting.test.ts](../../../../../plugins/agent-cli/test/waiting.test.ts)
