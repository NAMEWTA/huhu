# W8.1 Space 目录与数据包

Space 业务记录位于 `.huhu/agent-cli/spaces/`。版本 2 保留 ID、名称、创建时间、revision 以及目录类型。库根在打开时解析为当前 Vault，库内目录保存为 POSIX 相对路径。恢复时，仍存在且可以安全访问的相对目录直接绑定，缺失的目录显示待绑定。

外部 Space 在业务记录里只保留随机绑定 ID。明确选择的绝对路径及本地目录身份写入 `.huhu/runtime/<machineId>/agent-cli/space-bindings/`。已有的 ZIP 和同步规则排除该运行区。恢复到另一目录时，即使仍在原机，外部 Space 也需要重新选择。重新选择保留 Space ID 并更新 revision。Core 布局继续在原 Vault 的 `.huhu/runtime/<machineId>/herdr/` 中。

旧绝对路径只有在同机、能归属于当前 Vault 且可以安全访问时才会迁移成当前库的根或相对目录。旧外部记录无法确认原始 Vault，恢复副本与他机绝对记录也会显示待绑定。可写 Vault 的 `ensureDefault` 会将旧记录改写成版本 2，保留原 revision。迟到的旧同步记录在读取时也按这套规则判定，下一次可写初始化会落盘。只读打开不会写入配置或运行区。

## Lead 装配

1. Engine 使用 `new SpaceStore(path.join(root, ".huhu", "agent-cli", "spaces"), machineId(), undefined, { vaultRoot: root, readOnly: api.vault.files.readOnly })` 并保留 `ensureDefault(root)`。`root` 取 `api.vault.files.root`，使只读打开也能读取实际业务记录。`agent.spaces.list` 和 `agent.spaces.save` 的输出使用共享 `SpaceSchema`。
2. 在 `AgentCliModule` 的当前 Space 处挂载 `SpaceDirectoryNotice`。`onBind` 打开现有编辑表单，传 Space 的 `id`、`revision`、`name` 和空 `folder`。用 `spaceCanLaunch(space)` 控制新建标签页和分栏启动入口、`startTarget`（包含 Ctrl+T／⌘T）及启动菜单。服务端对新启动仍以 `SpaceStore.validateForLaunch` 的实时判断为准。
3. 当前 `agent.workspace.get` 会经 `current()` 调用 `core.ensure()`。恢复后的布局读取应先尝试 `core.peek()`，本地尚无 Core 布局且未连接时，返回 `emptyLayout(spaceId)` 的版本 0 视图。已有本机布局保留原重开路径。`agent.workspace.launch` 在读布局前检查新的启动申请是否绑定，已提交过的原 `requestId` 继续按现有逻辑核对。
4. 在 Engine 的 `spaceOf` 路径入口检查 `spaceCanLaunch(sp)`。历史扫描和 Git diff 都需要已绑定的绝对路径，待绑定 DTO 的空字符串不能作为工作目录传入。UI 同步停用依赖目录的历史和审查操作。

## 复验

从仓库根运行下列命令。测试只读写系统临时目录下的 Vault。

```powershell
node node_modules/vitest/vitest.mjs run --project '@huhu/plugin-agent-cli' --project '@huhu/vault' --maxWorkers=1 --minWorkers=1 spaces-package.test.ts sessions.test.ts launch-reconcile.test.ts package.test.ts
```

- `spaces-package.test.ts` 通过实际 `Vault.open`、`exportPackage` 和 `importPackage` 往返。验证配置、嵌套文件与目的地绑定，原布局文件保持原样，ZIP 未携带 runtime。外部与未随包恢复的空目录在 `SessionsService.launch` 触达 Core 前被拒绝。明确重选可启动校验，目录身份换掉后再次需要绑定。
- 恢复后将父目录换为指向仍在线的源 Vault 的 Windows 目录联接，并改写旧目录数据为穿越和绝对路径。启动校验拒绝这些目录，源 Vault 仍能使用原来的绑定。
- 另用一份实际旧格式 ZIP 验证同机旧绝对记录与他机记录。原库安全的根和相对目录可以迁移，恢复副本中的旧路径均不可启动。只读打开保持原记录。
- `package.test.ts` 覆盖损坏包、非空目的地、路径校验及 ZIP 运行区排除。UI 提示的实际挂载和恢复页面的 Core 调用在 Lead 的整合版本验收。

## Engine 接线复验

Windows 真实 Engine 使用桌面的 Vault ZIP 能力导出与恢复测试库。恢复后保留原 Space ID，默认根指向目的地，外部 Space 显示待绑定。读取两个工作区都得到初始布局，尝试启动未绑定的外部工作区得到 `SPACE_INVALID`。目标的 Herdr 运行目录仍未创建，启动回执未导入。重新打开源库，原 Core 布局版本和外部绑定仍然可读。

`apps/engine/test/agent-workspace.test.ts`、`plugins/agent-cli/test/spaces-package.test.ts` 与 `packages/vault/test/package.test.ts` 合计 21 项通过。包导入回归也核对了旧包内容中的 Core 运行目录和会话回执不会恢复到新目标。
