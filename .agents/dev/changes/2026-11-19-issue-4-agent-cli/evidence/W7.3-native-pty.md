# W7.3 · Windows 受保护宿主原生验收

本切片交付 Windows x64 的 `native/agent-pty`，使用本机 Core 外层 `terminal.run` 和 Windows 系统内层 ConPTY。Engine 需要在应用装配时保有 broker 的进程和 stdin，并按本次 Core 根终端的 PID、FILETIME 与安装映像绑定授权。 [原生模块](../../../../../native/agent-pty/README.md) · [接线协议](../../../../../native/agent-pty/PROTOCOL.md) · [W7.3](../tasks/W7.3-agent-settings.md)

## 两轮真实运行

最终 exe 用两个新 Core 实例、独立临时 HOME 和各场景随机合成值完成了两轮，每轮 17 项。场景通过现有 Huhu `HerdrCore`、`terminal.run/list/read` 和 attach 访问。Node 入口、Core 持久快照、尾帧、文件锁和后代进程均做断言。 [两轮机器结果](W7.3-native-pty-runs.json)

| 场景 | 两轮结果 |
| --- | --- |
| 批准的创建环境 | 合成 Node CLI 的第一条业务语句直接读环境，值的 SHA-256、Unicode、完整名称集合、批准 cwd、含空格和引用符的 argv、三个 TTY 句柄均匹配。父环境诱饵缺席。省略批准变量时，内层按负对照退出 17，Host 返回同一退出码。 |
| 交互和尺寸 | attach 看到无换行提示，输入 `ping` 收到 `CLI_PONG`。外层 resize 到 94 × 27 后，内层在键入之前读取到了新尺寸。 |
| 单次交付与身份否认 | 成功消费后 broker 退出 0，同名管道第二次连接找不到端点。Host 和 broker 两个方向分别使用不匹配的 FILETIME，以及同字节的另一安装路径，均拒绝且零内层启动。 |
| 文件和目录固定 | 批准后实际改写入口和解释器、替换同名 cwd、将批准目录变为 junction，broker 都返回 74。入口 argv 改变大小写、私有值混入 argv、环境名仅大小写不同均返回 73。运行期入口文件打开写入失败，Host 退出后同一路径可重新打开写入。 |
| 输出与 Core 状态 | 合成值拆到 stderr，夹有 stdout 事件，外层只观察到遮蔽标记和后续正常交互。原始 attach、Core 屏幕、Core 视图、broker 诊断和落盘扫描均无合成值，公开通道也没有随机部分的任何连续八位。Core 的 argv 和提交完全相同，`restart_env` 为空或省略。停服后补扫先前被占用的运行文件。 |
| Job 回收 | 普通根进程退出，以及 Core 主动结束外层，均观察到原本存活的独立控制台后代退出。 |
| 真实离线 Pi | 固定 Node 映像、Pi 入口、包内 manifest 和 bundle，共固定 85 个 Pi 文件。全新 HOME 离线启动后，`/session` 返回 `Session Info`，`/quit` 以 0 收尾。只使用内建命令。 |
| 清理 | 两轮的 `remainingPanes=0`、`coreStopped=true`、`tmpRemoved=true`。Core 二进制从本机已有集成资源加载。 |

## 构建与来源

- Windows x64 `10.0.26300`，Go `1.26.7`，Node `24.21.0`。独立模块的离线依赖核验、5 项 Go 测试和 Go vet 通过。最终 exe SHA-256 为 `905cc819483996cab9fd1b1c0a51a36db2632dac7cf65f878a9af8e87e6f9b85`。构建脚本、`go.sum`、Go 运行时许可与 x/sys 许可随源码交付。
- Core `0.1.19`，SHA-256 `8c5c088eda5c441502fa58714277a250e38103c66180376ef00d63d6cab03f8d`。Node 映像 SHA-256 `ba4e6d110e8c1592a1ecd390f6b05f3da124b13871a5be62b341a07a853c6c32`。Pi `1.5.2` 入口 SHA-256 `e79626f2dd6f94aa45d30f3fa63cd84319a6eefcd150b353cfaf274366926774`。
- 复用本机 t192 已证实的 x/sys 身份、ConPTY 和环境块路径。实际链接 `golang.org/x/sys v0.50.0`（`00227f1d192842e243cba7763c1f9a1fcb1c4344`，BSD-3-Clause）。用本机 Windows SDK `WinBase.h` 中 `ProcThreadAttributeJobList=13` 的定义将 Job 绑到进程创建。参考 Microsoft hcsshim `v0.15.0-rc.1` 的伪控制台句柄生命周期。 [t192 独立实验](D:/Document/code/huhu/.agents/system/herdr-core/2026-11-20-huhu-issues-3-10-implementation/t192/report03.md)

信任范围为经批准的安装、目录、声明文件和原样输出的保护值。动态加载和解释器依赖仍由应用批准策略约束。桌面包装、Safe 三种状态下的最终安装体验、授权持久化及重启对账由产品集成验收。

## 两阶段启动回执复验

在同一 Windows 和固定 Core 上用更新后的 exe 跑完 18 个场景，覆盖前述行为。批准了实际字节但 Windows 拒绝创建的测试映像先产生 broker 私有 `ISSUED_ONCE`，随后产生 `START_FAILED 70`，broker 与外层均退出 70。正常启动均先收到 `ISSUED_ONCE`，再从可信 broker 取得 `RUNNING`，其中负对照子进程随后以 17 退出。断管、确认写入失败和无效回执的单元测试保留消费事实并给出 `START_UNKNOWN`。Go 测试与 Go vet 通过，临时 Core、终端和目录均已清理。
