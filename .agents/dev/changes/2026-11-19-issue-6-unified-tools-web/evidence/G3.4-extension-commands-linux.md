# G3.4 扩展命令逐项映射与调用委托

Linux 候选基于 `499427bee8976d6e96bf19693f54641f1aa360eb`。测试采用临时 Vault、合成令牌和受控扩展，走真实 Engine 回环接口。

## 命令与权限

- 外部清单 `contributes.commandDescriptors` 声明 owner、commandId、标题、说明、输入和输出、scope、risk、retry 及下游能力。Engine 支持可往返转换的本地 JSON Schema 子集，输入是严格对象，输出支持对象、数组和标量。规范名和派生 MCP 名与注册表一起校验归属、重复及长度。任务测试确认碰撞时整份声明回滚。
- `extensions.<pluginId>.<commandId>` 是命令登记名。停用后释放活动 handler，继续保留其静态描述供预配。每条命令默认关，新增命令的策略初始未配置。
- CLI 及 HTTP MCP 直接调用同一已绑定命令。兼容入口 `plugins.commands.run` 要求自己的单项开放权限，随后以原调用者重新进入具体命令。该入口沿用 `result` 输出包络，并在持久调用时附带 `operationId`。
- Node 宿主在激活期间仅接收 `dataDir` 和命令登记接口。Engine 为每次执行保留单独的 IPC 委托、关联的 Vault、进程实例、原 actor/subject、MCP 会话、父操作、60 秒截止和取消信号。子步骤身份和授权由 Engine 计算，manifest 依赖及插件 grant 限定目标和范围。普通外部入口的目标 handler 仍收到原 caller。工作台发起时，Engine 带原始委托审计上下文，以外部插件权限执行具体目标，防止工作台专用参数被间接启用。
- 工作台管理入口 `plugins.grants.update` 可缩减或恢复该扩展清单内的授权。复合写把父操作落盘，再用父操作 ID 和稳定步骤名给子调用建回执。显式命名的读步骤可为恢复保留快照。确认未受理的步骤在当前授权下续跑，已完成的步骤从回执取原结果，未知结果保持待核实。

## 真实入口验收

| 场景 | 证据 |
| --- | --- |
| 两条命令与单项开放 | 同一扩展从真实 CLI 命令入口和 HTTP MCP initialize 后的 tools/call 各执行一套。只开写命令时，直接与代理均拒绝读命令。写命令与代理并发重交同一意图，目标只写一次，两个入口得到同一父操作。 |
| 原主体与并发上下文 | 写入 handler 观测到 CLI 的 `caller=cli`、`subject=cli`，HTTP 使用 `caller=http` 与绑定该 MCP 会话的 subject。两端都收到原始 actor 对应的 Vault 实例、经手插件、命令名和父 operationId。两个 HTTP MCP 会话共享同一父令牌并发提交，观察到不同 subject 与独立 operationId。外部剪藏传入的 `source=system` 被收件箱按真实入口改写。 |
| 逐步重验与准确写入 | 四轮分别撤具体命令、下游能力、插件 grant 和代理。每轮第一步已有一条捕获，第二步未获授权时任务计数为 0。恢复授权后重交同意图，捕获和任务各为 1 且父操作一致。停插件后在途委托失效，已消费的第一步不重跑，第二步无写入。 |
| 停用配置、换库和更新 schema | 停用时能查并预配命令，启用后该选择生效。另一个 Vault 对旧句柄拒绝并保持零写入。用现有卸载/安装流程换入新版后重新连接，旧参数在直接调用和代理处均被拒，新命令默认关。 |
| 示例每日回顾 | 合成保存明确报告未受理。再次提交原意图时仅保存原路径，笔记数保持 1。示例保留创建路径、读取快照与写入所需的 expectedVersion。 |

主要用例在 `apps/engine/test/external-plugins.test.ts`。三个随包示例已迁移到清单声明和调用上下文。扩展仍以本机用户权限运行，Engine 委托的适用边界为应用能力访问。旧的动态命令及 `activate(api).call` 用法需要迁移。
