# T4.1 设置最早派遣时间并显式提前派遣

用户分别看到业务截止与最早可派时刻；今天不能自动领取明天的任务，手动提前会记录本次覆盖。

归属 T4，对应 [Issue #5 验收矩阵](../source.md) B02、B03、A08。[行为规格 · 何时自动派遣](../spec.md#何时自动派遣) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.1](T1.1-create-task.md) 的真实任务。提前派遣接 [T1.2](T1.2-accept.md) 的受理；歧义墙钟行为见设计待决项，常规时刻可先验。
- **职责与边界**　Tasks 保存 availableAt 的 instant，due 保留原业务意义。共享控件输入墙钟与 IANA zone，端侧和 Engine 展示同一时刻。
- **现有代码入口**　[tasks/ui/TaskEditor.tsx](../../../../../plugins/tasks/src/ui/TaskEditor.tsx) · [components/DateTimePicker.tsx](../../../../../packages/ui/src/components/DateTimePicker.tsx) · [kinds/task.ts](../../../../../packages/contracts/src/kinds/task.ts) · [tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [tasks/ui/TaskDetail.tsx](../../../../../plugins/tasks/src/ui/TaskDetail.tsx)。
- **原型走查**　[任务编辑 → 最早派遣/截止、提前派遣确认](../prototype/index.html#editor)。DST 歧义只确认实际展示的备选方案。确认时区提示和歧义输入。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 让客户端与 Engine 处于不同时区，在 Asia/Taipei 创建明早任务，读回并分别走普通派遣/明确提前派遣，核对时刻、覆盖与来源。
2. 清空 availableAt、输非法时区、遇 DST 跳时/回拨，未决定的歧义分支用两种候选走查，不能静默取设备时区；取消提前时无事件。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/scan.test.ts](../../../../../plugins/automations/test/scan.test.ts) · [plugins/automations/test/scheduler.test.ts](../../../../../plugins/automations/test/scheduler.test.ts)
