# T6.4 停用模块、切 Vault 后找回未完业务

从只读 Vault 或插件不可用的任务详情能看到原因，恢复写入和插件后仍从原输入/回执继续。

归属 T6，对应 [Issue #5 验收矩阵](../source.md) D06、D08、D09、D11、E03。[行为规格 · 并发与失败的外部语义](../spec.md#并发与失败的外部语义) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 提供未领取意图，[T2.1](T2.1-dispatch-cli.md) 提供实例绑定，[T3.2](T3.2-reply.md) 提供持久回答，[T3.3](T3.3-deliver.md) 和 [W6.3](../../2026-11-19-issue-4-agent-cli/tasks/W6.3-durable-receipt.md) 分别提供真实接收与生产端。
- **职责与边界**　各插件恢复自己的持久事实，取消旧 Vault 订阅与代次。损坏记录只冻结受影响任务；先恢复未物化意图再开放领取。
- **现有代码入口**　[tasks/engine/index.ts](../../../../../plugins/tasks/src/engine/index.ts) · [tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [automations/engine/service.ts](../../../../../plugins/automations/src/engine/service.ts) · [agent-cli/engine/waiting.ts](../../../../../plugins/agent-cli/src/engine/waiting.ts) · [operations.ts](../../../../../packages/vault/src/operations.ts)。
- **原型走查**　[独立后台场景 → 插件离线、只读、恢复补送](../prototype/index.html#fault)。演示控制可选择只读 Vault 和模拟重启。确认可恢复与不可继续的区别。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 分别关闭 Automations、Agent CLI、Tasks，在可写临时 Vault 中产生待输入及待投递记录，再启用；核对人工闭环和插件间交接均恢复一次。
2. 只读/临时 stateDir、切 Vault 后迟到事件、损坏记录、目标删除/其他机器不明进程，核对拒绝、冻结或待核实原因，禁止误认领或写错任务。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts) · [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts)
