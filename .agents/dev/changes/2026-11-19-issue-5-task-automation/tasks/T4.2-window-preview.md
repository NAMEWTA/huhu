# T4.2 预览与实际扫描使用相同的时间窗口

以相同时刻和规则版本查看预览、扫描及运行一次，每个任务的候选、等待或排除原因一致。

归属 T4，对应 [Issue #5 验收矩阵](../source.md) B02、B03、B04。[行为规格 · 何时自动派遣](../spec.md#何时自动派遣) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　分类可用固定 task/now 单独实施；真实任务的 availableAt 取 [T4.1](T4.1-available-at.md)，派遣对照取 [T1.2](T1.2-accept.md)。
- **职责与边界**　Automations 以规则时区求半开区间，独立处理 includeOverdue/includeUnscheduled。首次扫描与回复/重试/跟进分别验证资格。
- **现有代码入口**　[automations/engine/scan.ts](../../../../../plugins/automations/src/engine/scan.ts) · [automations/ui/RuleEditor.tsx](../../../../../plugins/automations/src/ui/RuleEditor.tsx) · [kinds/automation.ts](../../../../../packages/contracts/src/kinds/automation.ts) · [automations/engine/scheduler.ts](../../../../../plugins/automations/src/engine/scheduler.ts)。
- **原型走查**　[规则编辑 → 时间窗口、候选/等待/排除](../prototype/index.html#editor)。确认时区、预览和运行一次的区别。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 固定台北 10:00，用今天 09:00、昨天、明天及未排期的任务比较今天/本周/本月/未来七天/自定义；在周一、跨月、DST 和终点各对照预览与处理 ID。
2. 在不同设备时区重复，未来任务、Human、配置缺失、已开始、未知占用与忙 session 理由正确；预览写入为零，运行一次不更改下次日程。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/scan.test.ts](../../../../../plugins/automations/test/scan.test.ts) · [plugins/automations/test/scheduler.test.ts](../../../../../plugins/automations/test/scheduler.test.ts)

## Windows Engine 阶段

规则按自身时区计算今天、本周、本月和未来七天的半开边界。自定义窗口以带偏移的两个 instant 保存。预览、定时扫描和运行一次沿用相同分类；实际领取重查当前任务、时钟与资源状态。旧配置沿用未排期纳入规则。明确选择窗口时，逾期与未排期各自由配置纳入。

Windows 固定时钟测试核对台北周一、跨月、纽约春季 23 小时和秋季 25 小时的日界，以及自定义结束端点。台北规则以合成执行器比较预览的入选任务 ID 与运行一次的实际 ID。预览无写入，运行一次保留下次日程和规则版本。窗口使用仓库锁定的 Croner 11.0.0 的时区转换。界面期间的跨设备显示和用户交互待原型确认后验证。 [Croner 11.0.0 的时区说明](https://github.com/Hexagon/croner/blob/master/CHANGELOG.md) · [预览与运行测试](../../../../../plugins/automations/test/service.test.ts)
