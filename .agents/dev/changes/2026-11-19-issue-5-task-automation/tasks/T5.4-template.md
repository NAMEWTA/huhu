# T5.4 按模板生成可继续问答的独立任务

一次模板发生创建一条真实任务并派给所选目标，后续问题及结果回到这条任务。

归属 T5，对应 [Issue #5 验收矩阵](../source.md) A01、A03、B06、B09、D10。[行为规格 · 何时自动派遣](../spec.md#何时自动派遣) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T5.3](T5.3-scan-occurrence.md) 的 occurrence 记录及 [T1.1](T1.1-create-task.md)/[T1.2](T1.2-accept.md) 的创建与受理。
- **职责与边界**　冻结模板、来源和预留 taskId。另一次新发生取得独立身份；已有任务扫描使用任务本身配置。
- **现有代码入口**　[automations/ui/RuleEditor.tsx](../../../../../plugins/automations/src/ui/RuleEditor.tsx) · [automations/engine/service.ts](../../../../../plugins/automations/src/engine/service.ts) · [automations/engine/scheduler.ts](../../../../../plugins/automations/src/engine/scheduler.ts) · [tasks/ui/TaskEditor.tsx](../../../../../plugins/tasks/src/ui/TaskEditor.tsx) · [tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts)。
- **原型走查**　[规则编辑 → 新任务模板 → 新建任务来源](../prototype/index.html#editor)。确认模板与补充指令的区分和原任务链接。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 创建及编辑固定提示模板，触发后沿 occurrence→taskId→dispatch 查到独立任务，核对 run 输入仍绑定该任务；另触发一期得到新身份。整段问答在真实 CLI 旅程用模板来源重走。
2. 在建任务后、受理前崩溃并修改模板；恢复用原 taskId/快照，离线多期只补最近一次。配置失效可见，空目标不启动。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts) · [plugins/automations/test/scheduler.test.ts](../../../../../plugins/automations/test/scheduler.test.ts)

## 持久模板验收

- 发生保存规则版本、正文、执行配置和预留任务 ID。Tasks 使用规则名作为初始任务标题，并保存规则与发生的来源。任务文件落盘后、受理前中断，重开后读取原 ID，再按原正文受理。修改过执行输入的原任务或已经移到回收站的原任务有可读诊断。 [模板发生实现](../../../../../plugins/automations/src/engine/task-scan-occurrences.ts)
- Windows 经实际 Engine、固定时钟、pnpm 和合成执行器验证两种路径。规则中途编辑后，原计划点和输入仍查到一次受理，第二个计划点生成独立任务并使用新正文。目标 Space 缺失时记录跳过，任务和运行数量均为零。三文件联跑 68 项通过。 [模板场景回归](../../../../../plugins/automations/test/task-scan-occurrences.test.ts)
- 生产触发和模板编辑界面继续按 [T7.1](T7.1-cutover.md) 接入。真实提供方的模板问答仍按 [T7.2](T7.2-full-task-journey.md) 取证。
