# T3.3 回执重交后原任务只显示一次结果

任务可在 CLI 结束后补收到结果，时间线恰有一条可见评论，任务由用户手动关闭。

归属 T3，对应 [Issue #5 验收矩阵](../source.md) A02、A03、D04、D05、D06、D10、D11、E02。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 提供任务 run 与持久记录，[W6.0](../../2026-11-19-issue-4-agent-cli/tasks/W6.0-receipt-contract.md) 提供回执及 ACK 契约样例。

- **现有代码入口**　[tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [tasks/engine/index.ts](../../../../../plugins/tasks/src/engine/index.ts) · [kinds/task-run.ts](../../../../../packages/contracts/src/kinds/task-run.ts) · [markdown/regions.ts](../../../../../packages/vault/src/markdown/regions.ts) · [automations/engine/service.ts](../../../../../plugins/automations/src/engine/service.ts)。

## 验收与取证

1. 向 Tasks 提交固定 result 回执，在保存 payload 前、保存后至 ACK 前、评论写入至送达标记前分别中断 Tasks。重开后以同样例再次提交，核对持久消费后才有 ACK、同一 messageId 仅出现一条原任务评论、执行调用计数为零。
2. 插件停用、权限暂失、坏回执、同 ID 异内容或删除目标时保留失败/待核实及补送记录；只有退出码或静默时不显示业务成功。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts) · [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts)

## Windows Tasks 接收端取证

通过真实 Engine Dispatcher，使用受信插件身份交付同一个合成结果。开始前持久保存已经确认的 Vault、运行、轮次和原会话绑定。当前接收端只在原回执与可重建的 delivery 同时写入并回读后返回 `tasks_consumed`。

在首次保存前注入失败，收到错误且评论为空。释放保存后取得 ACK，随后在评论出现到投递标记之间注入写失败。重开同一 Vault 并用原键重传，得到同一 ACK、同一 messageId 和同一原任务的唯一结果评论。同 ID 异载荷和其他运行绑定被拒绝。原任务保持进行中，执行器自受理以来总调用次数为一。外部 CLI 不可发现或直接提交该回执。 [实际 Engine 测试](../../../../../plugins/tasks/test/persistence-http.test.ts)

定向测试三文件共 59 项通过，原工作区日志 `temp/issue-baseline/core-finished/t14s.log`。本轮由合成原接收方驱动已注册的 Tasks 接收端。Agent 真实回执的发送与重交、问题和回答、实际进程中断及同包验收分别记录。
