# T6.2 等待回答时让独立任务继续工作

同一 Space 中，一个任务等回答时，另一个独立会话能占用空出的执行槽；共享写资源保留串行。

归属 T6，对应 [Issue #5 验收矩阵](../source.md) B05、C02、C03、D08。[行为规格 · 并发与失败的外部语义](../spec.md#并发与失败的外部语义) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.2](T1.2-accept.md) 的 task 领取、[T3.1](T3.1-questions.md) 的等待状态和 #4 [W6.1](../../2026-11-19-issue-4-agent-cli/tasks/W6.1-bound-input.md) 的 session 仲裁。
- **职责与边界**　Tasks 管 task/global/rule/资源键，#4 最终裁决 session owner。按资格时刻、受理时刻、稳定 ID 有界领取；不同任务上下文隔离。
- **现有代码入口**　[tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [automations/engine/claims.ts](../../../../../plugins/automations/src/engine/claims.ts) · [automations/engine/holds.ts](../../../../../plugins/automations/src/engine/holds.ts) · [automations/engine/scan.ts](../../../../../plugins/automations/src/engine/scan.ts) · [agent-cli/engine/sessions.ts](../../../../../plugins/agent-cli/src/engine/sessions.ts)。
- **原型走查**　[后台场景 → 等待回答、资源忙、空闲唤醒](../prototype/index.html#simulation)。并发资源计数和多机事实需在 Engine 检查。确认等待原因与现场绑定。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 一个并发槽下令 A 等待回答，B 使用另一 session，C 与活跃工作抢同一资源；记录 B 能领取、C 等待、A 保留原请求。
2. 两规则争用共享容量、人工占用目标或其他机器的 unknown 记录重启，按确证事实唤醒；超时和正文变化均不能绕过原锁。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts) · [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts)

## 规则执行槽

- 扫描发生在冻结时保存限额，Tasks 从已受理的运行投影同一规则的占用。领取后、派遣中和待核实均占用。原生轮明确停在问题时释放一个执行槽。已持久受理的回答在新派遣前尝试重新取得槽。旧接受记录读取时保留原请求身份。 [Tasks 领取](../../../../../plugins/tasks/src/engine/dispatch.ts)
- Windows Engine 使用合成执行器和实际 Tasks 回执入口验证一个槽的三条任务。A 等待原生问题后 B 进入运行，C 保持等待。B 确认结束后先向 A 原会话发送唯一回答，C 继续等待。Tasks 与 Automations 三文件联跑 37 项通过。不同规则、全局资源键和真实提供方仍按本任务的其余判据验收。 [Engine 夹具](../../../../../plugins/tasks/test/persistence-http.test.ts)
