# T3.2 从原问题提交一次回答

任务详情和运行抽屉共享回答入口；回答已保存、待发送、待核实、已处理可区分。

归属 T3，对应 [Issue #5 验收矩阵](../source.md) A05、A06、A07、C02、D01、D03、D09、D11、E02。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T3.1](T3.1-questions.md) 的问题身份、[T1.2](T1.2-accept.md) 的持久接受与 #4 [W6.1](../../2026-11-19-issue-4-agent-cli/tasks/W6.1-bound-input.md) 的绑定输入合同。
- **职责与边界**　服务端核 request/version、原轮、选中消息和 replyId。普通回答开有 parentRunId 的新轮，原生请求在能力允许时继续原轮；仅补充用户明确选入的内容。
- **现有代码入口**　[ui/TaskDetail.tsx](../../../../../plugins/tasks/src/ui/TaskDetail.tsx) · [ui/RunsPanel.tsx](../../../../../plugins/automations/src/ui/RunsPanel.tsx) · [engine/index.ts](../../../../../plugins/tasks/src/engine/index.ts) · [engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [dto/task.ts](../../../../../packages/contracts/src/dto/task.ts)。
- **原型走查**　[详情与抽屉 → 回复并发送](../prototype/index.html#detail)。确认问题定位、竞争和待发送提示。对应体验待用户按[原型确认记录](../prototype-review.md)的指纹和范围确认。

## 验收与取证

1. 在两个入口同时回答最后一个有效问题，插入新问题改变顺序，再重传；以具体 ID 核一个有效接受和一次输入。停用 Automations 后仍可从详情作答。
2. 接受后评论/event 尚未物化即断电，重启补齐；相同键异文、不同键抢答、发送确认丢失或原生请求失效时拒绝或待核实，不重发或自动批准。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts) · [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts)

## Windows 原生回答阶段

Tasks 经内部工作台 HTTP 接口 `tasks.reply` 保存当前 task、run、session、request、version、replyId 和选项，再按稳定 ID 投影回答评论。回复查询返回 `pending`（已保存）、`sending`、`unknown`（待核实）、`accepted`（原生已确认）、`expired`、`not_sent` 或 `unsupported`。保存与回执接收使用同一 task 写锁。原生路由从已签收的当前问题解析，回复接口不接收该路由。

真实 Windows Engine 与合成回答执行器的测试停用 Automations，并提交两个明确绑定同一问题的回答。一个保存，另一个返回版本冲突。同 replyId 同载荷重交读回原记录，同 ID 异载荷返回幂等冲突。评论投影受阻时关闭 Vault，重开只补写一条评论。合成发送确认丢失后保留 `unknown`，再次启动仅向执行器查询原回复并读到 `accepted`，累计发送一次。答案绑定原问题，即使另一个问题随后出现。

验证入口见 [persistence-http.test.ts](../../../../../plugins/tasks/test/persistence-http.test.ts)。实际 Agent/helper 回答、普通问题的下一轮、任务详情与运行抽屉的共同入口仍由对应切片验收。
