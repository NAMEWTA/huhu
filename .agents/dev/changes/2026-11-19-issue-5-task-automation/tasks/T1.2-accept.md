# T1.2 持久接受人工派遣并恢复未领取意图

用户点立即派遣获得可重查的受理身份；待资源时任务仍在未开始列。

归属 T1，对应 [Issue #5 验收矩阵](../source.md) A02、B05、C06、D01、D02、E01。[行为规格 · 用户可以做什么](../spec.md#用户可以做什么) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T1.1](T1.1-create-task.md) 的持久任务和执行配置。可用协议替身独立验收受理边界。
- **职责与边界**　Tasks 在 taskId 临界区冻结版本、正文/消息、授权和配置引用，接受记录原子提交后再物化并领取；权威状态在 Tasks。
- **现有代码入口**　[tasks/engine/index.ts](../../../../../plugins/tasks/src/engine/index.ts) · [tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [kinds/task-run.ts](../../../../../packages/contracts/src/kinds/task-run.ts) · [operations.ts](../../../../../packages/vault/src/operations.ts) · [write.ts](../../../../../packages/vault/src/write.ts) · [automations/engine/claims.ts](../../../../../plugins/automations/src/engine/claims.ts)。
- **原型走查**　[任务详情 → 立即派遣、已受理、等待/冲突](../prototype/index.html#detail)。用「下一次执行」选择会话忙或确认丢失。确认反馈与看板状态。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 停用 Automations，从详情点击两次，再以两个规则来源竞争。断在受理/物化/领取之间后重启，核对一个有效 event/run/attempt、原输入 hash 与任务锁。
2. 超过 24 小时同键同载荷读原凭据，同键异内容冲突；只改评论可条件重写，正文变化报告 stale_input，活跃/未知旧轮仍占用任务。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts) · [plugins/tasks/test/shared.test.ts](../../../../../plugins/tasks/test/shared.test.ts)
