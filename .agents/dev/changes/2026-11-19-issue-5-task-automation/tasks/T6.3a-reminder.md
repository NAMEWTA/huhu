# T6.3a 投递一次提醒或生成提醒任务

规则选通知、建 Human 任务或两者时，每个效果可分别查证；恢复后可找回已经创建的提醒任务。

归属 T6，对应 [Issue #5 验收矩阵](../source.md) B06、D10。[行为规格 · 并发与失败的外部语义](../spec.md#并发与失败的外部语义) · [设计与状态所有权](../design.md) · [计划索引](../plan.md)

## 实施范围

- **前置条件**　[T5.3](T5.3-scan-occurrence.md) 的发生记录；建提醒任务使用 [T1.1](T1.1-create-task.md) 的稳定创建身份。
- **职责与边界**　runReminderAction 为每个子动作保存效果身份，任务有预留 ID；通知由现有通知入口受理。
- **现有代码入口**　[automations/engine/service.ts](../../../../../plugins/automations/src/engine/service.ts) · [automations/engine/scheduler.ts](../../../../../plugins/automations/src/engine/scheduler.ts) · [tasks/engine/service.ts](../../../../../plugins/tasks/src/engine/service.ts) · [kinds/automation.ts](../../../../../packages/contracts/src/kinds/automation.ts)。
- **原型走查**　[规则详情 → 提醒、建任务与结果](../prototype/index.html#editor)。提醒多子动作如未展示，留作后续专项确认。确认各子动作和未知状态。该界面范围待用户按版本确认，实施前核对[原型确认记录](../prototype-review.md)中的资源指纹、场景与实际确认范围；未演示的分支单列。

## 验收与取证

1. 在三个提醒模式触发同一发生两次，再重启，核对任务、通知及发生的关联。已确认送达的子动作只产生一次效果。
2. 令建任务成功后确认写入失败，按原 taskId 补齐；通知发出但无可查确认时保留未知，不自动再次发送。

在仓库根用 `pnpm exec vitest run` 加下方对应的 `.test.ts` 路径执行领域回归，再按上面的实际入口补齐行为证据。 [plugins/automations/test/service.test.ts](../../../../../plugins/automations/test/service.test.ts) · [plugins/tasks/test/service.test.ts](../../../../../plugins/tasks/test/service.test.ts)

## Windows Engine 验证

用固定 pnpm 运行 Automations 发生记录、旧规则兼容路径及 Kernel 通知的 54 条用例，全部通过。测试经 Engine 创建三种提醒规则，推进可控时钟，对同一发生并发触发两次，重启后读回两条通知与两个人工任务。人工「立即运行」有独立发生身份。模拟建任务成功而确认文件落盘失败后，重启用原 taskId 完成确认。模拟通知没有可读回证据时保留未知，人工任务仍成功，重启未重复通知。 [发生记录测试](../../../../../plugins/automations/test/task-scan-occurrences.test.ts)
