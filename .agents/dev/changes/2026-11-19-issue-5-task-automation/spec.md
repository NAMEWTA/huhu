# #5 在原任务中派遣、答复和收取结果

用户今天创建“明天处理”的 Agent 任务，明天到点由指定 CLI 接手。Agent 的问题、用户的回答和最终结果依次出现在这一个任务中。应用重启或暂时无法写评论时，用户仍能查到上次输入和结果的去向。

依据 [Issue 全文及验收矩阵](source.md) §0–16，快照无评论。下列是目标行为，现有实现与目标之间的断点见 [设计](design.md)。真实 CLI、故障窗口与各验收号的分工见 [计划](plan.md)。

## 用户可以做什么

| 条件与动作 | 可观察结果 | 来源 |
| --- | --- | --- |
| 人工创建或保存未配齐目标的任务 | 默认 Human，Agent 可选择具体 Space、provider、模型、参数和目标策略；默认新会话，复用须明确指定。任务保持可编辑，保存不起进程。模板创建的 Agent 任务有独立 taskId 和来源，使用模板的配置快照。已有任务采用自己的执行配置。 | §3–5，A01–04 |
| 在详情点“立即派遣”；未到时间时显式点“提前派遣” | 返回稳定事件/派遣身份，显示已受理、待资源、已启动或失败原因。提前操作记录这一次覆盖。进入待派时看板仍未开始，实例接受本轮输入后才进入进行中并追加一次系统评论。人工无须创建规则，Automations 停用也可操作。 | §5.2、7，A01–03、B05 |
| 在 Task 发讨论、回复提问或单独发送补充信息 | 普通评论只保存讨论。默认选最后一个仍有效的问题，服务端校验具体 request/version、task/run/session 及 replyId。回复和补充都先持久保存，随即尝试派遣；忙时待发送，明确拒绝显示失败，确认丢失显示待核实。重试同键同内容返回原结果，换键不能抢答同版本。只在新版意图里选择新的正文/消息。 | §5.3–5.4、9，A05–07 |
| 普通业务提问，或 provider 报告了原生 deferred 请求 | 前者可结束本轮，回答驱动同任务、同会话的新轮并留 parentRunId；后者仅在支持时恢复原 run/request。等待时释放工作槽，保留任务/实例绑定。只有 blocked 信号的提供“前往现场处理”，敏感原生操作由有权的人在原现场处理。 | §3.1、5.4、8，C01–04 |
| 打开问题、进度和最终结果，或关闭任务/视图/运行 | 绑定任务只追加有意义的摘要/问题/结果，详细日志留现场。独立终端可保留原 Human 等待任务兜底。用户手动关闭完成；运行结束、pane 关闭、原生进程丢失均只更新运行事实。已关闭任务允许补历史结果，后续输入须明确重开。取消未发送、停止运行、关闭任务、离开视图、停用规则各有后果。 | §5、7、12，A02–03、C07–08 |

任务仅有 Human/Agent 两类和未开始/进行中/已完成三状态。运行、注意力和送达状态在详情展示。保留 Markdown 的 task/comments 区段、区段外字节、条件写、路径引用、完成删除线、列表及三列看板。上下文只包含本轮选中的未消费消息、原问题/回答、任务正文、必要摘要和资料引用；上轮 Agent 的输出不会因出现在评论里而自动变成新指令。

## 何时自动派遣

| 字段或操作 | 明确规则 |
| --- | --- |
| trigger、zone、availableAt、window、due | Croner 按规则 IANA 时区决定检查时刻。availableAt 是任务最早可派时刻（UTC instant，空为尽快）。window 针对 availableAt；due 保留业务截止日期与列表原分类。 |
| 选择窗口 | 以规则当地日历构造半开区间：今天零点至次日零点；本周周一至下周一；本月月初至下月初；未来七天为今天零点至第七天零点。自定义显示两端和时区。includeOverdue 和 includeUnscheduled 独立配置。可执行判断始终要求 availableAt 为空或不晚于 now。 |
| 筛选与预览 | 预览、扫描和“运行一次”共用谓词，取相同 now 和规则版本时得到相同分类。首次只收 Agent + 未开始、范围和标签/项目匹配、目标/授权有效且无重复、活跃、未决请求或未知执行的任务。目标忙列“等待空闲”，预览无写入，手动运行一次不改下次日程。回复、同快照重试和跟进走各自预检。 |
| 默认规则 | 首次启用闭环幂等安装普通规则“处理可执行的 Agent 任务”。启用，每 15 分钟（`*/15 * * * *`），取工作台 IANA 时区，包含漏处理与未排期的可执行任务，逐条使用任务自身目标，默认一个活跃工作轮次。等待用户不占槽。持久化初始化/删除事实，用户改、关、删后重启维持选择；只有显式恢复才重建。 |
| 停用或删除规则 | 只停止未来触发。已入队未发送的任务继续保留，可在原任务中单独取消。已发送的轮次、待回答问题和待投递结果仍可追查。恢复启用时跳过停用期间的发生。[用户决定](../../../system/herdr-core/2026-11-19-huhu-prototypes-and-slices/topic.md) |
| occurrence / invocation / follow-up | 定时身份由 ruleId 和 scheduledForUTC 确定，记录当时规则版本/快照；手动使用独立 invocationId。重复命中同一发生只接受一次。恢复最多补一次当前扫描，固定模板只补最近一次，记录跳过/合并原因；停用期间不追补。一次性跟进可查看、改期、取消，按授权只向尚未关闭的原任务投递。Engine 离线期间按恢复处理。 |

**可复核例子。** 固定 Asia/Taipei 11 月 15 日 10:00，今天 09:00 的有效任务可派，次日 09:00 在“今天”和“未来七天”均不可派。昨天 18:00 在“今天”窗口仅在开启逾期选项时纳入；未排期任务按独立选项。再用跨月、周一零点、夏令时跨越日和设备时区不同的浏览器重走，检查边界 instant、预览原因、实际接受 ID 以及进程数。

## 并发与失败的外部语义

- 一个 taskId 同时只有一个活跃工作轮次。已接受、可合并的补充消息按原 ID/顺序进入同任务下一轮；不同任务各持一份上下文。按可执行时刻、接受时刻、稳定 ID 有界领取。手动派遣与两条同时命中的规则竞争同一 task，只产生一份有效执行；后到来源能查到已有接受或排除原因。
- 一个 session 同时只有一个输入所有者。人工接管、review.send、派遣、问题回复共享 #4 仲裁。指定实例忙时保留 pending 和原因；默认新任务新会话，同 Space 中独立会话可并行，共享写资源按显式资源键串行。unknown 继续占用相关任务/实例/资源直至对账。其他机器遗留执行不以超时自动接管。
- 看板和运行页分别显示 Task 和 Run。普通问题、原生暂停、已接受回答、已处理、发送未知有独立事实。时间线显示的 messageId 唯一。结果存好但评论失败时只补送原结果；超时/退出 0、最后一行屏幕和静默均不能当作业务成功。
- 只读 Vault 或临时状态目录拒绝持久派遣和回复。Tasks 暂停时 Agent 保留回执，Agent CLI 暂停时 Tasks 保留输入，切 Vault 隔绝旧回调。任务删除后保留送达失败/目标已消失的诊断，原执行不可再启。损坏的 durable 记录显式报错并冻结相关领取。

## 界面、权限与数据范围

任务详情按目标、最早派遣/截止、执行目标、当前运行及待处理问题、评论和运行记录组织。列表概要看 questionCount，详情用共享的 Question[]。只有有效问题显示回答入口。前往现场携带 Space/session/run，实例已失效则解释原因。自动化列表用现有 Switch、右侧详情抽屉和 DataTable；编辑器区分既有任务补充指令与新任务模板，均可创建及编辑，预览显示候选、等待与排除原因。Agent List 标识手动/后台来源，后台新建不抢焦点。第三方源码用于对照功能和信息结构，导航、文案、主题和组件采用 Huhu 自有设计，沿用 Huhu DateTimePicker、Markdown 及分层样式；此次交互按[原型确认记录](prototype-review.md)逐场景确认；后台时间推进、竞争、故障和恢复经独立的演示控制触发。

规则保留 Agent、终端命令和提醒三类。Agent 动作只走已有任务或创建真实模板任务，终端命令仍走 Agent CLI，提醒仍走通知/提醒任务。只对授权目的开放执行；外部创建不自动获得派遣权，内部回执绑定本 task/run，无须打开全局外露。规则专用秘密由 Automations 本机加密保存，可复用启动环境归 Agent CLI，经同一执行合同注入。普通查询、导出、评论、快照和日志不含秘密；使用 [#6 外露权限](../2026-11-19-issue-6-unified-tools-web/spec.md)与 [#9 模块认证](../2026-11-19-issue-9-safe-accounts/spec.md)统一切换旧消费者。干净安装 MCP/CLI 工具默认全关，逐项或明确批量授权后才能对外调用。

本期投递到原任务时间线。后续邮件/IM 通过所属插件，把带 channel/account/thread/externalMessageId/replyTo 的明确输入映射到 taskId 和具体请求；输出消费持久 delivery 并返回渠道确认。无新增渠道服务、消息中间件、全局记忆、独立 Agent harness 或跨机调度。本期沿用单 Vault 单 Engine 的 Markdown/JSON 文件事实，SQLite 只作可重建索引。在空白测试 Vault 验证新格式的正常备份、恢复和损坏报告，按模块的导出范围和执行绑定恢复。未发布产品直接采用新契约，保全真实旧数据和外部历史、进程。
