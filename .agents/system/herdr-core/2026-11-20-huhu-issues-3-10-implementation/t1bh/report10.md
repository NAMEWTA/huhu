### 已提交的 Pi 意图可能因二次能力探测失败而无法回放

已登记原生 ID 的普通 Pi 以同一 request ID 重交时，先读取原记录并验证输入，但仍重新探测 `--help`。即使配置和请求没变，一次探测超时或暂时拿不到帮助也会返回未跟踪启动参数，`executionHash` 因缺少原 `--session-id` 而变化。之后先比较新 hash，再进入原 attempt 对账，结果可为 `IDEMPOTENCY_MISMATCH`。这阻断原会话确认，不会再启动第二个进程。最短验收为受控探测首次报告支持，Core 已收到第一次启动；同 request ID 重交时让帮助探测返回失败，核对回读同一 Pane 或继续原 ACK 对账。冻结提交中的稳定帮助回放用例没有覆盖该交错。 [新 Pi 解析与降级](../../../../../temp/issue-worktrees/integration/plugins/agent-cli/src/engine/index.ts#L74) [准备启动](../../../../../temp/issue-worktrees/integration/plugins/agent-cli/src/engine/sessions.ts#L313) [executionHash](../../../../../temp/issue-worktrees/integration/plugins/agent-cli/src/engine/sessions.ts#L433) [对账顺序](../../../../../temp/issue-worktrees/integration/plugins/agent-cli/src/engine/sessions.ts#L450) [现有稳定回放](../../../../../temp/issue-worktrees/integration/tests/e2e/shell.spec.ts#L1399)

### Mail 整包仍可能在独立写者新增引用时漏收附件
