**现状。** 先鉴权再查缓存，仅 write/execute 去重。执行后才写 NDJSON，写失败仍返回结果，重启忽略坏行，24 小时后失忆。handler 输出未经 schema 校验。业务落盘后崩溃可重复创建。见 dispatcher.ts:89、idempotency.ts:29。

**身份与传参。** HTTP 按 bearer 确定 Caller；CLI 用 cliToken，stdio 用 mcpToken 经 HTTP 解析别名；HTTP MCP 接受 mcp 或 http，保留真实角色。同一服务令牌经 API/MCP HTTP 应归同一主体。现有服务令牌全映成 http，Web 为 web:sessionId。HTTP 可传 key，其余三条路径随机生成。见 http-app.ts:102、CLI call.ts:54。

保留 Caller 作授权角色，认证层另传主体 ID。服务令牌签发及重载绑定已有 token.id；本地 CLI/MCP 各用稳定凭据槽，同槽进程共享身份，区分用户须分别发凭据。Web 按有效会话，插件按插件 ID。以 Vault 本地实例、主体、规范能力名、意图键组成唯一元组。CLI 增 --intent-key；两种 MCP 公布同一元数据字段，由适配器剥离并传 Dispatcher。调用方发送前保存 key，每次尝试另生成 requestId。

**最小落地。** 先贯通一次任务创建，复用 IdempotencyStore 和 Vault 单写锁，无需新库。按真实副作用覆盖管理变更。对校验后普通参数（含目标、预期版本）取 canonicalJson 全长 SHA-256。同键异参冲突。串行预留随机 opId 和实体 ID，追加含摘要的 prepared 并刷盘，失败不执行；并发同键共享操作。恢复时修复尾部半行再追加，损坏记录冻结，旧角色缓存不可跨主体重放。未决记录不超期，压缩终态保留防重标记。

若领域使用数据库，唯一意图记录与业务变更同事务提交。任务复用 create(reservedId)，随实体保存操作归属（service.ts:236）。重启按 ID 和归属核对；对象缺失可能已删除。NDJSON 与业务文件或远端效果无法原子提交，只有领域证实未发才续办；否则返回 unknown 与原句柄，禁止再次派发。OperationLog 仅证明登记的文件步骤。

分别记录受理、业务效果、结果校验、送达确认。用 def.output 校验；失配保留已证实的效果，标记结果无效。序列化成功只证明可返回，客户端未确认则送达未知。超时、断线或失应答不等于业务失败，迟到回执仅更新原操作。

**查询与敏感域。** 允许按「能力＋已知 key」或随机 opId 查询；HTTP、CLI JSON、MCP 的成功和错误均携带操作标识。查询、重放均重验入口、原能力现行授权、插件及对象归属；撤权即拒，原主体恢复授权才可查。换令牌、跨 Vault 或持他人句柄均不泄露是否存在。只返获准结果投影。handler 自管的 dispatchId、replyId、审批版本、邮件草稿版本继续由领域对账，共享层只存安全引用。令牌创建丢应答仅查签发状态，明文只能首次返回。Safe、邮件凭据和一次性令牌不进共享缓存、摘要、日志或重放结果；敏感比对由所有者负责。
