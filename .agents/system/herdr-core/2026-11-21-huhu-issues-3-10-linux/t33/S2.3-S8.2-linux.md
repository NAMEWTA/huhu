# Mail 阅读与 Web 附件 · Linux

基线 `1c2f8089`。使用临时 XDG 运行目录、临时 Vault、合成邮件与附件。OAuth 测试的 fetch 守卫只允许 `127.0.0.1`，凭据保护用 `TestProtection`。

| 场景 | 实际观察 |
| --- | --- |
| 单封外部图片 | `remote-images.test.ts` 2 项通过。HTTPS 传输替身记录 4 次成功过 DNS 校验的连接尝试，只返回合规图片；检查拒绝混合解析、内部地址、超限、跳转、SVG、源中的凭据与候选 `srcset`。出站仅有 `Accept` 请求头。 |
| 原文和消息代 | `messages-engine.test.ts` 1 项通过。两账号同 UID 分离，回读原文、只读和已读状态得到预期结果。四种批准入口观察覆盖当前摘要、伪造 URL 输入、错误摘要和错账号；换代后旧批准返回 `NOT_FOUND`。 |
| Web 上传 | `web-draft-attachments.engine.test.ts` 1 项通过。由真实 Web listener 的两 Vault、多浏览器会话登记及流式提交 9 MiB，重开草稿核对长度、SHA-256 与受管对象。错 Origin、转发头、无会话、错媒体类型、跨会话、跨 Vault、重复使用、过期、超限、大小不符和伪造路径均被拒绝。取消覆盖未上传、分块进行中与对象发布至草稿提交之间。最后一种取消回收对象，草稿版本保留原值。 |
| 桌面附件回归 | `draft-attachments-engine.test.ts` 8 项通过，含受管附件去重、只读、备份排队、取消与编辑 CAS。通过现有草稿移除行为验证 Web 的已登录会话，CLI 默认仍需开放策略。 |
| Web OAuth | `oauth-engine.test.ts` 2 项通过。通过真实浏览器会话 Cookie 发起 Google 回环 OAuth，Engine 宿主收到授权 URL，PKCE S256 及 state 经夹具核验。第二会话不能取消，合法回调只交换一次，原 Web 会话看到 configured。Safe 锁定期间 Mail 用自己保存的 OAuth 材料同步回环 IMAP。文件另覆盖 Microsoft 资源识别、回环 IMAP/SMTP、取消、失效与重授权。 |

桌面和 Web 使用同一阅读器与现有 CSP。用户点击后 Engine 从当前消息缓存版解析图片 URL，检查公网解析并固定连接地址，最多处理八个 HTTPS 图片，每个上限 512 KiB，整批限时 8 秒。界面用 `data:` 显示返回的静态图像媒体，消息切换移除原授权结果。Web 上传登记元数据并返回一次性句柄，实际文件通过二进制请求流传送。

尚未验证跨物理设备 LAN、真实外部图片服务器和桌面或 Web 实际浏览器渲染。`tests/e2e/workflows/mail.spec.ts` 已编写「窄屏 Web 工作台流式上传 9 MiB 邮件附件，重开草稿验证哈希并可取消」及「邮件阅读按单封放行图片，原文和切换邮件保持默认屏蔽」，本轮按实施者职责留给集成验收。
