## 待运行风险

- **Web 同文档导航的事件顺序。** Chromium 会排队发送 `hashchange`，并先在同文档导航提交中触发 `popstate`。Web 的 `main.tsx:251–265` 每次都根据现有 pathname 重开 URL 对应目标并切功能模块。可用 `/tasks/<id>` 进入后，通过功能栏切到收件箱，再点击收件双链作区分。此时 pathname 仍是任务路径，`popstate` 会尝试切回任务，收件组件及其 `OkRoot` 可能在消费片段前卸载。`/notes/<path>` 上也会先重发 pathname 中的笔记请求。最终激活结果需看渲染与事件顺序。若出现该问题，最小修正是让 Web 的 pathname 路由只处理初次加载与 pathname 真正变化的事件。G07 是桌面用例。 [Web 路由](../../apps/desktop/src/renderer/main.tsx#L251) [路径解码](../../apps/desktop/src/renderer/web-host.ts#L33) [模块挂载](../../packages/workbench/src/shell/AppShell.tsx#L321) [Chromium 同文档事件](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/loader/document_loader.cc)
- **H05 的慢桥起点与点击时点。** 夹具复用真实 Y.Doc，首笔正常写入并轮询 source，随后让生产桥自己进入慢分支。两种发表逐字断言 DOM 为完整文本且 source 恰为首段，删除分支逐字断言 source 仍为旧文。超时或提前结算会使对应前置断言失败。两个读数与点击分属 Playwright 任务，窗内若发生额外 flush，仍可能在没有分歧的情况下到达真实提交。定向复跑若有波动，可把两份快照移到按钮同一次 evaluate 中、在两次连续点击之前采集。撤销分支现在验 DOM 后直接 Ctrl/Meta+Z，覆盖真实撤销至空。若要继续覆盖“已结算正文再撤销”这一旧前置条件，先等普通 source 含初始正文即可。删除支路独立负责“DOM 已空、source 仍旧”。 [夹具](../../tests/e2e/knowledge/session-slow-bridge.ts#L9) [发表断言](../../tests/e2e/knowledge/compact-submit.spec.ts#L41) [撤销与删除](../../tests/e2e/knowledge/compact-submit.spec.ts#L83) [桥调度](../../packages/editor/src/vendor/open-knowledge/server-bridge/server-observers.ts#L1580)
- **OP-D18 的探针粒度。** Range 两端在同一个普通 Text 节点，矩形取首字中心，并先用 `elementFromPoint` 检查是否命中段落。没有把选区或焦点写回编辑器。现有 `click` / `keyup` 记录是捕获阶段快照，PM 的 DOMObserver 同步可能稍后才发生，不能把单次 PM 值直接当成最终状态。探针也只附加数据，测试本身只规定最终 DOM 选区和最终焦点。定向复跑先看附件是否包含可信 click、Home 和两次 Shift+ArrowRight，再对照每一步的 DOM 偏移、焦点和 PM 区间。需要区分暂时滞后与真正失配时，可加只读的按键后稳定采样，或逐步断言 DOM 为词首折叠、「参」、「参考」，并用 `doc.textBetween(from, to)` 报告对应模型文本。继续保留真实批注快捷键、无浮层、焦点和保存后引用检查。 [测点和探针](../../tests/e2e/knowledge/editor-compact-commands.spec.ts#L10) [原断言](../../tests/e2e/knowledge/editor-compact-commands.spec.ts#L88) [生产同步](../../packages/editor/src/rich/RichMarkdownEditor.tsx#L364)
